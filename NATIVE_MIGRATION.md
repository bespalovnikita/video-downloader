# Единая UI-версия и совместимость прежних данных

Video Downloader работает как одно Windows-приложение на **C# / .NET 8 / WPF**. Пользователь запускает `VideoDownloader.exe` из полностью распакованного ZIP. Устанавливать PowerShell, Python или .NET Runtime не требуется. Загрузки выполняют `yt-dlp.exe` и FFmpeg/ffprobe; интерфейс не открывает консольный загрузчик.

CMD-launcher, резервный PowerShell GUI и пользовательский CLI удалены. URL, `.txt`, `.url` и `videodownloader://` остаются входами графического приложения. Повторный запуск передаёт аргументы существующему окну через named pipe и возвращает его из трея.

Удаление прежней реализации не меняет форматы пользовательских данных. [Поэтапный план](docs/UI_ONLY_PLAN.md) и [матрица покрытия](docs/UI_ONLY_COVERAGE.md) описывают переход и проверки, которые сохраняются при упрощении исходников.

## Код, сборка и пакет

| Часть | Расположение |
| --- | --- |
| Проект приложения | `native/VideoDownloader.Native.csproj` |
| UI и управление очередью | `native/NativeWindow*`, разметка `ui/` |
| Загрузки и дочерние процессы | `DownloadCoordinator`, `ManagedChildProcess`, `OwnedFiles`, `DownloadCleanup` |
| Превью | `PreviewService`, `PreviewImage` |
| Подписки | `SubscriptionStore`, `SubscriptionScanner`, `PornHubChannel`, `SubscriptionNames` |
| Данные | `AppPersistence`, совместимые форматы версии 1 |
| Нативные тесты | `native-tests/`, статичные прежние данные `tests/fixtures/legacy/` |
| Разработка и CI | `scripts/`, `.github/workflows/native-windows.yml` |
| Встроенный коллектор | `collection-plugins/videodownloader/yt_dlp_plugins/extractor/vd_pornhub.py` |

Разработчику нужны Windows, .NET 8 SDK и PowerShell 7. Из корня репозитория:

~~~powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Build
pwsh -NoProfile -File scripts/build.ps1 -Task Test
pwsh -NoProfile -File scripts/build.ps1 -Task Publish
~~~

`Test` собирает приложение и запускает проверки движка, совместимости и настоящих WPF-контролов с изолированными данными. `Publish` создаёт папку `dist/native`, архив `dist/VideoDownloader-native.zip` и SHA-256; поддерживает явные `-Version`, `-OutputDirectory`, `-ArchivePath`, `-ChecksumPath`. Скрипты разработки в пользовательский пакет не входят.

ZIP содержит настоящий WPF EXE, `yt-dlp.exe`, XAML, ресурсы и исходники встроенного коллектора. CMD, пользовательские `.ps1/.psm1` и `pwsh.exe` в пакете запрещены. Для проверки коллектора разработчику дополнительно нужны Python и версия `yt-dlp`, закреплённая в CI. Приложение загружает плагин внутри `yt-dlp.exe` и не требует внешнего Python.

## Обновление с прежней версии

1. Заверши приложение и работающие загрузки прежней версии.
2. Распакуй новый ZIP целиком в отдельную папку и запусти `VideoDownloader.exe`.
3. Подтверди восстановление очереди, если оно предложено. Проверь каталог загрузок и зависимости перед **Start**.

Данные остаются в `%LOCALAPPDATA%\VideoDownloader`, доступном кнопкой **«📁 Открыть папку настроек»**. Удалять настройки или вручную переписывать JSON при обновлении не нужно. Перед ручным редактированием закрой приложение и сделай резервную копию.

| Данные | Путь | Правила чтения |
| --- | --- | --- |
| Очередь и параметры | `session.json` | Версия 1, исходные поля очистки и папок сохраняются |
| История успешных URL | `successful-downloads.jsonl` | Append-only JSONL версии 1, прежние записи без даты поддерживаются |
| Кеш превью | `preview-cache\` | SHA-256 точного URL, версия 1, TTL 72 часа |
| Подписки и входящие | `subscriptions.json` | Версия 1; прежние записи без `ShortName` продолжают читаться |
| Старые конечные результаты | Путь `Engine.EventsPath` из checkpoint | Корректные `Result` читаются после завершения прежнего движка |

Профили сохраняют идентификаторы `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3`, `Subtitles archive`, хотя в интерфейсе видны русские названия. Сравнение URL точное, с учётом регистра пути и параметров. Перенос кода не нормализует ссылки и не объединяет их по media ID.

Активные ранее строки становятся прерванными, завершённые не запускаются повторно обычной кнопкой Start. Настройки применяются при пустой/завершённой очереди и при отказе от восстановления строк. До закрытия диалога восстановления автосохранение защищает предыдущий checkpoint; повреждённый файл остаётся без изменений.

Если прежний процесс `pwsh` ещё работает, восстановление и новые сессии блокируются. Проверка использует PID и время создания процесса для защиты от повторного использования PID. После завершения старого движка финальные `Result` восстанавливают результаты, которые не успели попасть в checkpoint. Повреждённые события и неполный JSONL-хвост не доказывают успех. Старый Result не применяется к `DeferredToNextStart`.

Сохраняются `PendingRemoval`, `CleanupError`, `CleanupPaths`, `StageDir`, `RunDir`, `OutputRoot`, `AttemptFinished`, `DeferredToNextStart` и поля подписки. Незавершённая очистка исключается из Start/Retry, переживает Clear Queue и доступна для повторного Remove. Старые staging-пути поддерживаются с проверкой принадлежности; одного `Path` без манифеста владения недостаточно для удаления файла.

История хранит последнюю известную дату успеха, поддерживает корректную последнюю запись без LF и не исправляет молча повреждённый хвост. При ошибке чтения новый запуск блокируется. Отсутствующая обложка или ошибка записи кеша не лишают интерфейс полученных названий и остальных метаданных.

## Подписки

Ручная проверка выполняет полный просмотр HTTP/HTTPS-коллекции через текущий `yt-dlp`; RSS/Atom лишь обогащает подтверждённые точные URL. Неизменившаяся или недоступная лента не отменяет полный обход. Первая успешная проверка по выбору пользователя запоминает исходный набор либо добавляет существующие материалы в очередь. Последующие новинки появляются во входящих. Загрузку запускает **Start**; подписки не присоединяют задания к уже работающей сессии.

`ShortName` задаёт безопасный компонент папки и заполняется из названия канала/автора, затем коллекции, только если ещё пуст. Задание сохраняет снимок `SubscriptionName` при добавлении; базовый каталог закрепляется при Start. Пример: `D:\Video\123` или `D:\Video\ГГГГ-ММ-ДД\123`. Переименование влияет на будущие добавления и не перенаправляет старые строки. Отсутствующие поля прежнего checkpoint означают обычное задание без подпапки подписки.

Материал идентифицируется парой `SubscriptionId` + точный URL. Обработку подтверждает успешный результат или постоянная история. Обнаружение, baseline, постановка в очередь и пропуск успехом не считаются. Известный успех в другой подписке вызывает однократное уведомление; успех из общей истории без установленного источника означает Processed без такого уведомления.

Предел обычного обхода — 10 000 материалов, 180 секунд и 32 МиБ метаданных. RSS/Atom ограничена 2 МиБ и 12 секундами. Встроенный сборщик публикаций Pornhub имеет отдельные пределы: 10 000 роликов, 500 страниц, 15 минут и 32 МиБ. Он обходит публикации, исключает историю и рекомендации, проверяет страницы и повторяет первую. Неполный ответ не заменяет прежние материалы, baseline и время последней успешной проверки.

Прогресс показывает текущий источник, этап, время и реальные завершённые источники. Неизвестное число видео не выдаётся за процент готовности; успех появляется после сохранения полного результата. Отмена, закрытие и повторное открытие окна защищены от запоздалых обновлений.

Подробнее об источниках, cookies, вариантах разметки Pornhub и ограничениях — в [GUI.md](GUI.md#подписки-на-каналы-и-плейлисты). Автоматические проверки, Планировщик Windows и автоскачивание остаются в [BACKLOG.md](BACKLOG.md).

## Процессы и файлы

Загрузки, превью и проверка подписок используют `ManagedChildProcess`: индивидуальный Windows Job Object назначается атомарно, наследуются только нужные pipe handles. Аварийный выход владельца завершает его дерево работников, сохраняя независимые приложения. GUI и программы, открываемые через оболочку, не входят в job работника. `yt-dlp -U` запускается отдельно, чтобы штатная отложенная очистка `.old` могла завершиться после выхода обновления.

Каждый URL пишет в собственную staging-папку. Успех требует существующего медиафайла из `after_move:__VD_FILE__`; код завершения 0 без файла не публикует sidecars и не пополняет историю. Публикация и отмена согласованы; `OwnedPaths` содержит только действительно созданные файлы. Новые копии получают общий свободный суффикс для media/sidecars без перезаписи существующих результатов.

Проверяются границы каталога, корни дисков/UNC, относительные шаблоны и reparse points во всём пути. Исходный `OutputRoot` закреплён за заданием и не меняется вместе с полем вывода или датой. Проверки перед файловыми операциями не дают абсолютной защиты от намеренной одновременной подмены каталогов (TOCTOU); для неё нужен отдельный слой операций по открытым дескрипторам Win32.

До начала скачивания UI проверяет FFmpeg и ffprobe. Контейнер применяется через merge и remux; несовпадающее расширение результата блокирует публикацию. Предел загрузки установщика FFmpeg — шесть минут на заголовки и всё тело ответа. Превью ограничено 30 секундами на весь запрос, 12 секундами и 2 МБ на изображение; зависший процесс завершается, работник переходит к следующему URL.

## Проверки и выпуск

Единственный Windows workflow `native-windows.yml` проверяет приложение, реальные WPF-сценарии, локальные загрузки настоящим `yt-dlp`, паузу, отмену, файловые границы и встроенный коллектор, затем формирует автономный ZIP. Статичные legacy fixtures проверяют чтение старых данных без запуска второй реализации. Холодные тесты подтверждают получение названий после URL/TXT/InternetShortcut/подписки до Start; отдельные тесты сохраняют singleton, протокол, трей и варианты диалога повторной загрузки.

Каждый успешно протестированный коммит в `main` публикуется как стабильный GitHub Release с версией `v2.0.N`, совпадающей с версией EXE, ZIP и SHA-256. PR и ручной запуск CI не публикуют релиз. Подробности — [RELEASING.md](RELEASING.md).
