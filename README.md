**Video Downloader** — загрузчик видео и аудио с графическим интерфейсом для Windows. Основная версия написана на **C# / .NET 8 и WPF**, использует `yt-dlp` для скачивания и FFmpeg для обработки медиа. Приложение умеет работать с несколькими ссылками одновременно, запоминать историю, восстанавливать очередь после перезапуска и показывать превью.

**[Скачать последнюю версию](https://github.com/bespalovnikita/video-downloader/releases/latest)** · [Руководство по интерфейсу](GUI.md) · [Релизы](RELEASING.md) · [Переход с PowerShell](NATIVE_MIGRATION.md)

## Установка

1. Открой раздел [GitHub Releases](https://github.com/bespalovnikita/video-downloader/releases/latest).
2. Скачай `VideoDownloader-Windows-x64.zip` и распакуй его целиком в отдельную папку.
3. Запусти `VideoDownloader.exe`. Запуск напрямую из ZIP не поддерживается: нужны соседние `yt-dlp.exe`, папки `ui/` и `assets/`.

Сборка автономная (`self-contained`). Устанавливать PowerShell 7 или .NET Runtime для обычной C#-версии не требуется. `ffmpeg.exe` и `ffprobe.exe` можно установить через встроенный раздел зависимостей. Вместе с ZIP публикуется `SHA256SUMS.txt` для проверки целостности.

## Основные возможности

| Функция | Описание |
| --- | --- |
| Очередь | Несколько URL, импорт `.txt` / `.url`, вставка и отслеживание буфера обмена, перетаскивание |
| Работа во время загрузки | Новые ссылки добавляются в текущую сессию без перезапуска |
| Скачивание | Параллельные задания, ограничение скорости, качество 720–2160 и максимальное, выбор кодека и контейнера |
| Управление | Пауза, продолжение, остановка сессии, отмена конкретного URL |
| Превью | Заголовок, автор, продолжительность, обложка, разрешение, FPS, кодеки и HDR; фоновая загрузка и кеш на **72 часа** |
| Дополнительные данные | Субтитры, метаданные, обложки, главы, аудио MP3, SponsorBlock |
| История и восстановление | Журнал успешных URL и времени загрузки, защита от случайных повторов, сохранённый checkpoint |
| Трей | Состояние `OK → Left → Err` и скорость скачивания; продолжение работы без видимого окна |
| Интеграция | Протокол `videodownloader://`, меню зависимостей |

### Кнопки быстрого доступа

**Возле `↻ Failed`** находится **«📂 Открыть папку загрузок»**. Она открывает папку, заданную в поле `Output folder`. Если включено архивирование по дате, учитывается соответствующая папка `ГГГГ-ММ-ДД`; во время активной сессии C#-версия использует зафиксированный путь сессии.

**Возле `Register protocol`** находится **«📁 Открыть папку настроек»**, которая открывает:

~~~text
%LOCALAPPDATA%\VideoDownloader
~~~

Это папка с `session.json`, `successful-downloads.jsonl` и кешем превью. Поле `%APPDATA%` относится к другой папке (`Roaming`), поэтому для приложения нужен именно `%LOCALAPPDATA%`.

Обе кнопки есть в основной C#-версии **и** в интерфейсе, запускаемом через `start-gui.cmd` с PowerShell GUI. Кнопки не удаляют файлы.

## Профили загрузки

Пять встроенных профилей теперь имеют русские названия:

| Название в программе | Назначение |
| --- | --- |
| **Универсальный** | Автоматический выбор наилучших параметров |
| **Архив 4K** | Качество до 2160p, MKV, метаданные и главы |
| **Совместимый MP4** | До 1080p, предпочтение H.264, контейнер MP4 |
| **Музыка MP3** | Извлечение звука MP3 и метаданных |
| **Архив с субтитрами** | MKV, обычные и автоматические субтитры, встраивание |

Идентификаторы профилей **в `session.json` не меняются**: ранее выбранные `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3` и `Subtitles archive` продолжат восстанавливаться корректно. Пользовательские профили пока не поддерживаются. В обеих версиях каждый встроенный профиль полностью задаёт связанные параметры: формат, режим только аудио, архивирование по дате, субтитры и встраивание данных не наследуются от предыдущего профиля. Только «Архив 4K» включает подкаталог даты; остальные профили отключают эту настройку. Пути, cookies, скорость и число работников сохраняются.

## Превью, кеш и параметры

Метаданные и обложки загружаются отдельным фоновым заданием: ждать выбора строки необязательно. При выборе ещё не обработанной ссылки запрос получает приоритет, а дополнительный дублирующий запрос не запускается. Кеш живёт 72 часа в папке `%LOCALAPPDATA%\VideoDownloader\preview-cache`.

При выборе качества `2160` или `1080` допускается снижение разрешения, если соответствующего формата нет. Выбор кодека (`H264`, `VP9`, `AV1`) — предпочтение, не жёсткое требование. Для объединения видео и аудио в один файл обычно нужен FFmpeg.

В таблицах очереди и загрузок отображаются проценты, скорость и ориентировочное оставшееся время. Успех выделяется зелёным, ожидание серым, активная загрузка голубым, прерывание жёлтым, ошибка красным.

## Безопасность файлов и история

Файлы для каждого URL сначала помещаются в отдельную временную директорию и переносятся в конечную папку после успешной загрузки. Существующие файлы не перезаписываются без проверки. При удалении из очереди действуют проверки разрешённого каталога и списка действительно созданных приложением файлов. Операции через junction/symlink/reparse point блокируются. Защита от намеренной параллельной подмены папок (TOCTOU) не заявляется абсолютной.

В обеих версиях строка удаляемого задания остаётся до завершения его процесса и подтверждения очистки. PowerShell получает подтверждение через `Result` либо завершение движка; C# — через конечный результат работника. Ошибка удаления показывается явно; `Remove` можно повторить, в том числе после восстановления приложения. Для удаления готовых результатов сохраняется исходный `OutputRoot`, поэтому смена папки вывода не мешает очистке. Повторно добавленный после `Remove` URL в ещё работающем сеансе остаётся `Queued` до следующего запуска.

Оба движка считают загрузку успешной только при наличии итогового медиафайла из `after_move:__VD_FILE__`: одного кода завершения `yt-dlp` `0` недостаточно. Внешние конфигурации `yt-dlp` игнорируются. Шаблон имени должен быть относительным путём внутри папки загрузки; абсолютные пути и компоненты `..` отклоняются до запуска `yt-dlp`.

История успешных URL находится в `%LOCALAPPDATA%\VideoDownloader\successful-downloads.jsonl`. Если ссылка уже скачивалась, приложение предлагает повторить или пропустить её. Удаление скачанного файла не очищает историю автоматически. Оба движка поддерживают добавление после корректной последней JSON-записи без перевода строки, но не исправляет молча повреждённый хвост.

Предпросмотр ограничен общим сроком 30 секунд, включая процесс метаданных и чтение изображения. Для миниатюры действует дополнительный предел 12 секунд и 2 МБ. Зависший запрос освобождает работника для следующих URL; при ошибке миниатюры метаданные остаются доступны.

## Запуск через CMD и старая PowerShell-версия

`start-gui.cmd` из корня исходного проекта **сначала** пытается запустить соседний `VideoDownloader.exe` (или `dist\VideoDownloader.exe`). Если EXE отсутствует, он запускает прежний `ytdl-manager-gui.ps1` через установленный **PowerShell 7**.

Обе версии используют общий файл интерфейса `ui/MainWindow.xaml` и получают четыре изменения: обе кнопки, русские профили и обновлённую русскую документацию. PowerShell-версия сохранена для совместимости и отката; не запускай обе версии одновременно, так как они используют общие файлы данных.

## Командная строка

Основной C#-вариант поддерживает базовый командный режим:

~~~powershell
.\VideoDownloader.exe --cli --input .\list.txt --out D:\Videos --threads 4 --quality 1080
~~~

Для специфических старых параметров `-Watch`, `-LiveQueueFile` и других доступен прежний PowerShell-движок `ytdl-manager-v8.ps1`. Подробности приведены в [его русскоязычном руководстве](ytdl-manager-v8-manual.md).

## Сборка и проверка

Для самостоятельной сборки C#-версии на Windows требуется .NET 8 SDK:

~~~powershell
dotnet publish native/VideoDownloader.Native.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o dist/native
~~~

Для тестирования старой версии требуется PowerShell 7:

~~~powershell
pwsh -NoProfile -File .\tests\russian-ui-tests.ps1
pwsh -NoProfile -File .\tests\smoke.ps1
pwsh -NoProfile -File .\tests\download-history-tests.ps1
pwsh -NoProfile -File .\tests\cross-runtime-contract-tests.ps1
pwsh -NoProfile -File .\tests\preview-deadline-tests.ps1
pwsh -NoProfile -File .\tests\engine-review-regression-tests.ps1
pwsh -NoProfile -File .\tests\gui-review-regression-tests.ps1
pwsh -NoProfile -File .\tests\file-boundary-safety-tests.ps1
~~~

Полный Windows CI автоматически запускается при PR и после merge. Каждый успешный коммит в `main` публикуется как GitHub Release с ZIP, контрольной суммой SHA-256 и описанием изменений.
