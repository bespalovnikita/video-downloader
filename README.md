# Video Downloader

[![Сборка Windows (C#)](https://github.com/bespalovnikita/video-downloader/actions/workflows/native-windows.yml/badge.svg)](https://github.com/bespalovnikita/video-downloader/actions/workflows/native-windows.yml)
![Платформа](https://img.shields.io/badge/Windows-10%2F11-0078D4)
![Технологии](https://img.shields.io/badge/C%23-.NET%208%20%7C%20WPF-512BD4)

**Video Downloader** — загрузчик видео и аудио с графическим интерфейсом для Windows на **C# / .NET 8 и WPF**. Использует `yt-dlp` для скачивания и FFmpeg для обработки медиа. Приложение умеет работать с несколькими ссылками одновременно, запоминать историю, восстанавливать очередь после перезапуска и показывать превью.

**[Скачать последнюю версию](https://github.com/bespalovnikita/video-downloader/releases/latest)** · [Пошаговое руководство](docs/USER_GUIDE.md) · [Справочник интерфейса](GUI.md) · [Архитектура и диаграммы](docs/ARCHITECTURE.md)

## Установка

1. Открой раздел [GitHub Releases](https://github.com/bespalovnikita/video-downloader/releases/latest).
2. Скачай `VideoDownloader-Windows-x64.zip` и распакуй его целиком в отдельную папку.
3. Запусти `VideoDownloader.exe`. Запуск напрямую из ZIP не поддерживается: нужны соседние `yt-dlp.exe`, папки `ui/`, `assets/` и `collection-plugins/`.
4. Перед первым скачиванием установи FFmpeg и ffprobe кнопкой **Install FFmpeg** в разделе **Dependencies**, если они ещё не доступны рядом с приложением или в PATH. Программа проверяет их до начала загрузки. Скачивание установочного ZIP ограничено шестью минутами, включая чтение всего файла; после таймаута установку можно повторить.

Сборка автономная (`self-contained`). Пользователю не нужны PowerShell, Python или установленный .NET Runtime. `ffmpeg.exe` и `ffprobe.exe` можно установить через встроенный раздел зависимостей. Вместе с ZIP публикуется `SHA256SUMS.txt` для проверки целостности. Единственная пользовательская точка запуска — `VideoDownloader.exe`; добавление URL и файлов, в том числе через `videodownloader://`, открывает интерфейс.

## Руководство по сценариям

| Задача | Инструкция |
| --- | --- |
| Скачать отдельное видео YouTube | [URL видео → очередь → Start](docs/USER_GUIDE.md#youtube-video) |
| Скачать видео из плейлиста YouTube | [Выбор ролика или импорт плейлиста с отдельным заданием на каждый ролик](docs/USER_GUIDE.md#youtube-playlist) |
| Следить за каналом или плейлистом | [Подписка → ручная проверка → входящие → очередь → Start](docs/USER_GUIDE.md#subscriptions) |
| Подключить RSS/Atom к подписке | [Адрес коллекции + необязательная лента → ручная проверка](docs/USER_GUIDE.md#rss) |

RSS/Atom дополняет названия материалов, подтверждённых полным обходом коллекции через yt-dlp. Лента не заменяет этот обход и сама по себе не добавляет материалы во входящие. Проверок по расписанию и автоматического скачивания сейчас нет.

Для отдельного задания на каждый ролик плейлист импортируется через **«Подписки»** с добавлением существующих материалов. Прямой URL плейлиста в основной очереди остаётся одной задачей; её состав определяет yt-dlp. Это различие подробно описано в руководстве.

## Основные возможности

| Функция | Описание |
| --- | --- |
| Очередь | Несколько URL, импорт `.txt` / `.url`, вставка и отслеживание буфера обмена, перетаскивание; отображение URL или названий видео |
| Работа во время загрузки | Новые ссылки добавляются в текущую сессию без перезапуска |
| Скачивание | Параллельные задания, ограничение скорости, качество 720–2160 и максимальное, выбор кодека и контейнера |
| Управление | Пауза, продолжение, остановка сессии, отмена конкретного URL |
| Превью | Заголовок, автор, продолжительность, обложка, разрешение, FPS, кодеки и HDR; фоновая загрузка и кеш на **72 часа** |
| Дополнительные данные | Субтитры, метаданные, обложки, главы, аудио MP3, SponsorBlock |
| История и восстановление | Журнал успешных URL и времени загрузки, защита от случайных повторов, сохранённый checkpoint |
| Подписки | Ручная проверка каналов и плейлистов с визуальными этапами и временем, входящие и отдельные папки по кратким именам подписок |
| Трей | Состояние `OK → Left → Err` и скорость скачивания; продолжение работы без видимого окна |
| Интеграция | Протокол `videodownloader://`, меню зависимостей |

Названия найденных материалов подписок появляются в очереди и выбранном превью сразу после добавления. Недоступная обложка не скрывает название и остальные метаданные; повреждённые изображения пропускаются в пользу запасных. Для WebP/AVIF-обложек используется установленный FFmpeg. Ошибка сохранения кеша не мешает просмотреть уже полученные данные.

### Кнопки быстрого доступа

**Возле `↻ Failed`** находится **«📂 Открыть папку загрузок»**. Она открывает папку, заданную в поле `Output folder`. Если включено архивирование по дате, учитывается соответствующая папка `ГГГГ-ММ-ДД`; во время активной сессии используется зафиксированный путь сессии.

**Возле `Register protocol`** находится **«📁 Открыть папку настроек»**, которая открывает:

~~~text
%LOCALAPPDATA%\VideoDownloader
~~~

Это папка с `session.json`, `subscriptions.json`, `successful-downloads.jsonl` и кешем превью. Поле `%APPDATA%` относится к другой папке (`Roaming`), поэтому для приложения нужен именно `%LOCALAPPDATA%`.

Кнопки не удаляют файлы.

## Подписки на каналы и плейлисты

Кнопка **«Подписки»** открывает отдельное окно для сохранённых источников. Можно добавить HTTP/HTTPS-ссылку на канал или плейлист любого сайта, для которого установленный `yt-dlp` умеет полностью перечислить коллекцию. Для YouTube RSS может определяться автоматически; для других источников можно указать RSS/Atom вручную. Лента дополняет полный просмотр через `yt-dlp`: во входящие попадают только URL, подтверждённые полным списком выбранной коллекции. Отсутствие или ошибка ленты не ограничивает список поддерживаемых сайтов.

При добавлении выбери поведение первой проверки: запомнить все существующие материалы как исходный набор либо добавить их в обычную очередь. Последующие новые ссылки появляются во входящих. Доступны ручная проверка, отмена проверки, пауза подписки, добавление выбранного в очередь, пропуск и открытие ссылки. Загрузки начинаются только кнопкой **Start**; ссылки из подписок не присоединяются к уже выполняющейся сессии.

Подписка получает краткое имя из названия канала, а если оно недоступно — из названия коллекции. Его можно задать при добавлении или изменить позже. При папке вывода `D:\Video` материалы подписки «123» сохраняются в `D:\Video\123`; при архивировании по дате — в `D:\Video\ГГГГ-ММ-ДД\123`. Краткое имя закрепляется за материалом при добавлении в очередь, поэтому переименование подписки влияет на новые задания и не перемещает уже скачанные файлы.

Для каналов Pornhub предусмотрен отдельный сборщик публикаций. Открой **«Подписки»**, добавь URL вида `/channels/имя`, `/model/имя`, `/pornstar/имя` или `/users/имя` и выбери добавление существующих материалов, если нужен весь архив. После проверки нажми **Start** в основном окне. Сборщик обходит страницы опубликованных видео; история просмотров, избранное и рекомендации не импортируются. Каждый ролик получает отдельную задачу, результат и запись истории; недоступный ролик можно повторить отдельно. Предел проверки — 10 000 роликов, 500 страниц и 15 минут. Неполный список не сохраняется как успешный. Обработчик поставляется в ZIP и не требует установки Python. Подробнее — [в руководстве](GUI.md#публикации-pornhub).

Редиректы Pornhub между `/videos/upload` и `/videos` того же профиля поддерживаются. При отклонении перехода сообщение показывает конечный адрес, чтобы можно было отличить смену страницы от входа или ограничения доступа.

Сборщик учитывает несколько вариантов разметки профилей и каналов. При нераспознанной странице он сообщает найденные секции вместо успешного пустого результата. Подтверждение возраста в браузере не переносится в загрузчик автоматически; для передачи браузерной сессии используется файл в поле **Cookies** основного окна.

Если страница содержит несколько сеток видео, сборщик использует секции внутри основной вкладки `videosTab`, когда она присутствует. Вложенные обёртки, точные копии одного списка и пустые блоки без содержимого не вызывают ложную неоднозначность. Разные самостоятельные списки не объединяются; ошибка показывает их названия и число видео.

Один материал учитывается по паре «подписка + точный URL». Если этот URL уже успешно обработан в другой подписке, приложение один раз сообщает об этом. Само обнаружение, добавление в очередь или пропуск не считаются успешной загрузкой. Разные URL одного видео не объединяются по ID.

Состояние сохраняется отдельно в `%LOCALAPPDATA%\VideoDownloader\subscriptions.json`. Повреждённый файл не перезаписывается автоматически. Сейчас проверки запускаются вручную: таймер, Планировщик Windows и автоматическая загрузка остаются в [BACKLOG.md](BACKLOG.md). Подробности и ограничения — в [GUI.md](GUI.md#подписки-на-каналы-и-плейлисты).

## Профили загрузки

Пять встроенных профилей имеют русские названия:

| Название в программе | Назначение |
| --- | --- |
| **Универсальный** | Автоматический выбор наилучших параметров |
| **Архив 4K** | Качество до 2160p, MKV, метаданные и главы |
| **Совместимый MP4** | До 1080p, предпочтение H.264, контейнер MP4 |
| **Музыка MP3** | Извлечение звука MP3 и метаданных |
| **Архив с субтитрами** | MKV, обычные и автоматические субтитры, встраивание |

Идентификаторы профилей **в `session.json` не меняются**: ранее выбранные `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3` и `Subtitles archive` продолжат восстанавливаться корректно. Пользовательские профили пока не поддерживаются. Каждый встроенный профиль полностью задаёт связанные параметры: формат, режим только аудио, архивирование по дате, субтитры и встраивание данных не наследуются от предыдущего профиля. Только «Архив 4K» включает подкаталог даты; остальные профили отключают эту настройку. Пути, cookies, скорость и число работников сохраняются.

## Превью, кеш и параметры

Метаданные и обложки загружаются отдельным фоновым заданием: ждать выбора строки необязательно. При выборе ещё не обработанной ссылки запрос получает приоритет, а дополнительный дублирующий запрос не запускается. Кеш живёт 72 часа в папке `%LOCALAPPDATA%\VideoDownloader\preview-cache`.

При выборе качества `2160` или `1080` допускается снижение разрешения, если соответствующего формата нет. Выбор кодека (`H264`, `VP9`, `AV1`) — предпочтение, не жёсткое требование. Для объединения видео и аудио в один файл обычно нужен FFmpeg.

В таблицах очереди и загрузок отображаются проценты, скорость и ориентировочное оставшееся время. Успех выделяется зелёным, ожидание серым, активная загрузка голубым, прерывание жёлтым, ошибка красным.

Выбранный контейнер применяется и к одиночному готовому потоку через remux. Если кодеки несовместимы с контейнером, загрузка сообщает об ошибке. При повторном скачивании существующие файлы сохраняются, а новая копия и её субтитры получают согласованный суффикс `(2)`, `(3)` и далее. Параллельные задания согласуют публикацию файлов. Папкой вывода может быть и корень диска, если доступна запись.

Настройки восстанавливаются при пустой или полностью завершённой очереди, а также при отказе от восстановления её строк. Пока открыт диалог восстановления, предыдущий checkpoint защищён от автосохранения; повреждённый файл сохраняется без изменений.

## Безопасность файлов и история

Файлы для каждого URL сначала помещаются в отдельную временную директорию и переносятся в конечную папку после успешной загрузки. Существующие файлы не перезаписываются без проверки. При удалении из очереди действуют проверки разрешённого каталога и списка действительно созданных приложением файлов. Операции через junction/symlink/reparse point блокируются. Защита от намеренной параллельной подмены папок (TOCTOU) не заявляется абсолютной.

Строка удаляемого задания остаётся до завершения его процесса и подтверждения очистки работником. Ошибка удаления показывается явно; `Remove` можно повторить, в том числе после восстановления приложения. Для удаления готовых результатов сохраняется исходный `OutputRoot`, поэтому смена папки вывода не мешает очистке. Повторно добавленный после `Remove` URL в ещё работающем сеансе остаётся `Queued` до следующего запуска.

Загрузка считается успешной только при наличии итогового медиафайла из `after_move:__VD_FILE__`: одного кода завершения `yt-dlp` `0` недостаточно. Внешние конфигурации `yt-dlp` игнорируются. Шаблон имени должен быть относительным путём внутри папки загрузки; абсолютные пути и компоненты `..` отклоняются до запуска `yt-dlp`.

История успешных URL находится в `%LOCALAPPDATA%\VideoDownloader\successful-downloads.jsonl`. Если ссылка уже скачивалась, приложение предлагает повторить или пропустить её. Удаление скачанного файла не очищает историю автоматически. Добавление после корректной последней JSON-записи без перевода строки поддерживается; повреждённый хвост не исправляется молча.

Предпросмотр ограничен общим сроком 30 секунд, включая процесс метаданных и чтение изображения. Для миниатюры действует дополнительный предел 12 секунд и 2 МБ. Зависший запрос освобождает работника для следующих URL; при ошибке миниатюры метаданные остаются доступны.

## Сборка и проверка

Разработчику на Windows нужны .NET 8 SDK и PowerShell 7. Все команды выполняются из корня репозитория:

~~~powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Build
pwsh -NoProfile -File scripts/build.ps1 -Task Test
pwsh -NoProfile -File scripts/build.ps1 -Task Publish
~~~

Приложение находится в `src/VideoDownloader/`. `Test` собирает его и запускает `tests/VideoDownloader.Tests/` и `tests/VideoDownloader.UiTests/`: unit/integration-тесты и настоящие WPF-проверки с изолированными данными. `Publish` создаёт автономную папку `dist/native`, архив `dist/VideoDownloader-native.zip` и SHA-256. Скрипты из `scripts/` нужны разработке и CI и не входят в пользовательский ZIP. Для изменения встроенного коллектора дополнительно нужен Python и закреплённая в CI версия `yt-dlp`: `python tests/pornhub-collector-tests.py`.

Полный Windows CI автоматически запускается для PR, затрагивающих код, тесты, скрипты или сборку, и для каждого push в `main`. PR только с Markdown может не запускать этот workflow: для него проверяются ссылки, якоря и диаграммы. После успешных проверок в `main` публикуется GitHub Release с ZIP, контрольной суммой SHA-256 и описанием изменений.
