# Video Downloader — руководство по интерфейсу

Пошаговые кейсы для YouTube, плейлистов, подписок и RSS находятся в
[руководстве пользователя](docs/USER_GUIDE.md). Взаимодействие компонентов и
жизненные циклы показаны в [архитектурных диаграммах](docs/ARCHITECTURE.md).

Запусти `VideoDownloader.exe` из полностью распакованного Windows ZIP. Интерфейс работает на C# / .NET 8 / WPF; PowerShell, Python и установленный .NET Runtime пользователю не нужны. Папки `ui/`, `assets/`, `collection-plugins/` и `yt-dlp.exe` должны оставаться рядом с приложением.

Запуск EXE с URL, `.txt`, `.url`, `.vdqueue` или адресом `videodownloader://` добавляет материалы в интерфейс. Если окно уже открыто или спрятано в трей, аргументы получает существующий экземпляр. Загрузки запускаются из окна.

## Ширина панелей

При первом запуске Queue шире прежнего на треть: около 507 px вместо 380 px. Перетаскивай вертикальные разделители между **Queue / Downloads** и **Downloads / Preview**, чтобы изменить ширину панелей. Размеры сохраняются вместе с настройками. Downloads занимает оставшееся место; при уменьшении окна сохранённые размеры подстраиваются так, чтобы панели оставались доступны.

## Очередь ссылок

Под очередью находится переключатель **«Показывать названия видео вместо URL»**. Он меняет подписи в очереди и списке загрузок: выключен — видны URL, включён — названия видео. Пока метаданные загружаются или название недоступно, остаётся URL. Названия подхватываются из фонового превью и кеша без дополнительного запроса при переключении. Исходная ссылка всегда доступна в подсказке и действиях строки. Выбранный режим и полученные названия сохраняются между запусками.

Можно добавлять:

- одну ссылку или несколько HTTP/HTTPS-ссылок в поле ввода;
- содержимое буфера через **Paste**; при включении **Watch clipboard** ссылки добавляются автоматически;
- `.txt` со списком URL и Windows `.url`;
- ссылки и файлы перетаскиванием в окно.

Повторяющиеся URL в очередь не добавляются. До запуска доступны изменение порядка мышью и стрелками, `Remove` и `Clear`. Во время активной загрузки очередь остаётся доступной для выбора, просмотра превью, открытия и копирования URL.

**Новые обычные ссылки во время скачивания** поступают в асинхронную очередь текущей сессии. Если сессия уже закончилась, новая ссылка останется в очереди до следующего запуска. Материалы из подписок и импортированной переносимой очереди всегда ждут следующего **Start**.

### Перенос очереди на другое устройство

Кнопка **«Перенос очереди»** открывает команды **«Копировать очередь»**, **«Вставить очередь»**, **«Сохранить очередь в файл…»** и **«Открыть файл очереди…»**. Текст и файл `.vdqueue` совместимы с Android-клиентом. Обычная **Paste** также распознаёт переносимую очередь; **Watch clipboard** не импортирует её автоматически.

Переносятся все строки с URL и названиями в их порядке. Новые ссылки дополняют очередь и ждут **Start**; существующие сохраняют состояние. Прогресс, скачанные файлы, cookies, настройки, история и связь с подписками не переносятся. Для текста длиннее 262 144 символов используй файл. Пошаговые действия — в [инструкции переноса](docs/QUEUE_TRANSFER.md).

### Кнопка открытия папки загрузок

В верхней части очереди **сразу рядом с `↻ Failed`** находится кнопка **«📂 Открыть папку загрузок»**. Она не зависит от выделения файла в таблице и не удаляет файлы.

Папка берётся из поля `Output folder`. При включённом `Archive by date` открывается датированная подпапка вида `D:\Videos\2026-10-20`. При активном скачивании используется **зафиксированный каталог текущей сессии**, чтобы переход через полночь не переключал папку.

Если каталог ещё не создан, приложение показывает предупреждение вместо открытия чужой родительской папки. Чтобы изменить каталог, используй поле `Output folder` или кнопку с многоточием рядом с ним.

Отдельная кнопка `Show in folder` в таблице результатов продолжает открывать **папку конкретного скачанного файла**; эти действия не следует путать.

### Удаление и отмена конкретного задания

`Remove` доступна во время скачивания. Она отменяет только выбранный URL, не останавливая остальные задания. Для начатых и завершённых загрузок запрашивается подтверждение удаления связанных файлов. У каждого задания отдельная временная staging-папка и список `OwnedPaths`, чтобы не удалить чужие файлы.

Файлы не удаляются по шаблонам. Проверяется принадлежность папке назначения, отклоняются выходы за каталог через `..` и NTFS junction/symlink/reparse point. Наличие одного лишь старого пути из checkpoint **не является достаточным подтверждением владения**. От намеренной конкурентной подмены файловой системы (TOCTOU) полной гарантии пока нет.

Строка активного задания остаётся до завершения процесса и подтверждения очистки работником. Если файл заблокирован или не хватает прав, приложение показывает ошибку и сохраняет строку для повторного `Remove`. Исходный `OutputRoot` хранится у задания: смена поля `Output folder` после скачивания не меняет границы удаления старого результата.

После подтверждённого удаления повторное добавление того же URL в ещё работающий сеанс оставляет его `Queued` до следующего запуска. Пока отмена не подтверждена, строка остаётся в очереди и повторно не добавляется.

Незавершённая очистка сохраняется в `session.json`: `PendingRemoval`, `CleanupError`, `CleanupPaths`, `StageDir`, `RunDir` и исходный `OutputRoot`. Такие строки исключаются из Start/Retry и сохраняются при Clear Queue. После восстановления приложения можно повторить Remove. Если у старой записи есть только `Path` без списка владения, удали файл вручную и затем повтори Remove.

Удаление файла не удаляет соответствующий URL из постоянной истории успешных загрузок.

## Профили загрузки

В поле **Profile** названия показываются на русском:

| Название | Основные настройки |
| --- | --- |
| **Универсальный** | Максимально доступное качество и автоматические параметры |
| **Архив 4K** | До 2160p, контейнер MKV, метаданные и главы |
| **Совместимый MP4** | До 1080p, предпочтение H.264, контейнер MP4 |
| **Музыка MP3** | Извлечение звука, метаданные и обложка |
| **Архив с субтитрами** | MKV, субтитры, автосубтитры и встраивание |

Профили применяют готовые наборы полей. Ты можешь вручную изменить любое поле после выбора профиля. Создание собственных именованных профилей пока не предусмотрено. Выбор профиля полностью задаёт качество, кодек, контейнер, обычные и автоматические субтитры, встраивание данных и режим только аудио. «Архив 4K» включает архивирование в подкаталог даты; остальные профили его отключают. Пути, cookies, скорость, число работников и прочие параметры соединения не меняются. Настройки восстанавливаются независимо от наличия очереди, а восстановление самих строк требует подтверждения; это не глобальные пользовательские профили.

До скачивания программа проверяет FFmpeg и ffprobe. При отсутствии зависимостей установи их кнопкой **Install FFmpeg** в **Dependencies** и повтори Start. Передача медиа до этой проверки не начинается.

Контейнер MP4/MKV/WebM применяется и к одиночному файлу. Для несовместимых кодеков возможна ошибка remux: автоматическое перекодирование не выполняется. При разрешённой повторной загрузке новая копия получает свободное имя с `(2)`, `(3)` и далее; субтитры сохраняют тот же суффикс. Удаление копии сохраняет прежние результаты.

**Совместимость с предыдущими версиями:** в файле `session.json` имена по-прежнему сохраняются как `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3` и `Subtitles archive`. При открытии старой сессии они преобразуются в русские названия.

## Папка настроек приложения

В разделе **Dependencies** рядом с **Register protocol** находится кнопка **«📁 Открыть папку настроек»**.

Она открывает в Проводнике:

~~~text
%LOCALAPPDATA%\VideoDownloader
~~~

Обычно это `C:\Users\<имя>\AppData\Local\VideoDownloader`. Используется именно **Local**, а не `%APPDATA%` (`Roaming`).

Содержимое:

| Путь | Назначение |
| --- | --- |
| `session.json` | Сохранённая очередь и параметры |
| `subscriptions.json` | Подписки, исходные наборы и входящие |
| `successful-downloads.jsonl` | Постоянная история успешных URL |
| `preview-cache\` | JSON-кеш метаданных и изображений |

Если директория настроек ещё не существует, кнопка создаёт её и открывает. Сама кнопка ничего не удаляет и не сбрасывает. Прежде чем вручную менять эти файлы, закрой программу и сделай резервную копию.

## Предпросмотр

В панели **Preview** отображаются заголовок, автор, продолжительность, обложка, платформа, доступное разрешение, FPS, кодеки и HDR (если эти сведения предоставлены сайтом).

Для каждого точного URL программа получает и кеширует **до 15 изображений сайта**. Если сайт отдал меньше пригодных изображений, галерея будет меньше; одинаковые по содержимому картинки не дублируются. Если ни одна не подошла, остаются текстовые метаданные. Обложка может быть выбранной автором картинкой, а не кадром видео: программа не извлекает кадры из скачанного файла и не выбирает таймкод.

yt-dlp может вернуть варианты в `thumbnails` и отдельный адрес `thumbnail`. Программа убирает повторы адресов, сначала рассматривает ссылки с расширениями JPG/JPEG/PNG, затем внутри каждой группы — картинки с большей площадью `width × height`. Проверяются до 60 кандидатов, пока не набраны 15 разных пригодных изображений или не исчерпан бюджет запроса. Адреса без расширения тоже допустимы. Несколько вариантов могут быть разными разрешениями одной обложки; различие содержимого видео между картинками не гарантируется.

Наведи мышь на изображение в Preview: доступные картинки начнут листаться по кругу каждые 0,9 секунды. Колесо мыши и кнопки **‹ / ›** переключают их вручную, счётчик показывает текущий номер. После ухода мыши автоматическое листание останавливается. Листание использует уже полученные изображения и не запускает сеть. Название и первая картинка появляются сразу по готовности; оставшаяся галерея дополняется в фоне.

**Embed thumbnail** — отдельная настройка скачивания: она поручает yt-dlp сохранить и встроить обложку в поддерживаемый медиафайл. Изображение при этом выбирает сам yt-dlp; картинка из кеша Preview ему не передаётся, поэтому совпадение не гарантируется. Приложение не запрашивает сохранение всех обложек и не управляет несколькими вложенными изображениями файла. Миниатюру в Проводнике Windows создаёт отдельный обработчик Windows, она также может отличаться от Preview.

Метаданные готовит отдельный фоновый работник сразу после добавления URL. Он не мешает текущим загрузкам. При выборе URL без готового превью эта ссылка получает приоритет. При ручном Paste приложение выбирает добавленную ссылку и начинает показывать её превью, когда данные готовы; Watch clipboard сохраняет текущее выделение.

На один предпросмотр отводится не более 30 секунд, включая процесс yt-dlp и чтение изображений. Вся галерея дополнительно ограничена общими 12 секундами, размером 2 МБ на изображение и 12 МБ на набор. При таймауте сохраняются уже полученные картинки и текстовые метаданные; очередь предпросмотра продолжает работу. Внешние конфигурации yt-dlp игнорируются и при предпросмотре.

При добавлении из подписки уже найденное название сразу переносится в очередь и в панель предпросмотра выбранного видео, даже если ссылка уже была в очереди. Оно остаётся видимым, если полный запрос метаданных или обложки не удался. При восстановлении сохранённой очереди пропущенные названия берутся из списка соответствующей подписки. Для отображения названий в таблицах включи **«Показывать названия видео вместо URL»**. Ошибка полного запроса завершает состояние загрузки и показывает причину в панели; повторный выбор ссылки без готового кеша позволяет повторить запрос.

Адрес обложки может не иметь расширения файла: приложение проверяет декодирование изображения, перебирая подходящие варианты в пределах общего лимита миниатюры. Повреждённая картинка не блокирует запасной вариант. Допустимый исходный размер — до 16 777 216 пикселей; отображаемая обложка ограничена 720 пикселями по большей стороне без увеличения маленьких изображений. Для WebP/AVIF используется установленный FFmpeg, который преобразует локально полученные байты в PNG. Если нужного декодера нет, название и остальные метаданные всё равно сохраняются. Старые записи кеша с ошибкой `no JPEG/PNG thumbnail was provided by yt-dlp` обновляются при следующем запросе.

Кеш действует до 72 часов в папке `preview-cache` внутри каталога настроек. Служебные записи автоматически вытесняются, когда дисковый кеш превышает примерно 512 МиБ; они могут быть получены заново. Ссылки сопоставляются точно, с учётом регистра пути и параметров. Повреждённые изображения и устаревшие записи обновляются при следующем запросе. Прежний кеш с одной обложкой остаётся пригодным и дополняется галереей при обращении к URL. Ошибка записи на диск не мешает показать уже полученные данные.

После успешного сохранения проверки подписки превью её новых и ожидающих очереди материалов подгружаются сразу, без добавления в обычную очередь и без Start. Исходный набор, уже обработанные материалы и дубли повторно не подгружаются. Выбор материала во «Входящих» показывает его в основном Preview; фоновая подгрузка не меняет текущее выделение. Она использует того же единственного работника и не запускает скачивание видео.

Некоторые сайты могут требовать cookies. Путь к файлу задаётся в `Cookies`, а не содержимое cookies непосредственно в программе. См. отдельную [инструкцию по экспорту из браузера и подключению cookies](docs/COOKIES.md). Ошибки получения метаданных выводятся в лог.

Если во время диалога повтора та же ссылка приходит из буфера или через протокол, она остаётся в очереди в одном экземпляре. Если текущая сессия успела завершиться, подтверждённая ссылка ждёт следующего Start.

Сохранённые настройки применяются и при пустой или полностью завершённой очереди, даже если восстановление строк отклонено. Скачивание ZIP установщика FFmpeg ограничено шестью минутами, включая тело ответа; при таймауте кнопки зависимостей снова доступны.

## Подписки на каналы и плейлисты

Кнопка **«Подписки»** в основном окне открывает отдельное окно. Обычной очередью можно продолжать пользоваться, пока идёт проверка источника.

### Добавление источника и первая проверка

1. Укажи HTTP/HTTPS-ссылку на канал или плейлист. Поддерживается любой сайт, для которого установленная версия `yt-dlp` может полностью перечислить такую коллекцию; отдельного ограничения только на YouTube нет.
2. При необходимости укажи RSS/Atom. Для YouTube приложение может получить адрес ленты из метаданных канала. Этот шаг необязателен.
3. При необходимости задай краткое имя подписки. Если оставить поле пустым, первая успешная проверка возьмёт название канала или автора, а при его отсутствии — название коллекции.
4. Выбери, что сделать с существующими материалами при первой успешной проверке. Флаг называется **«Добавить все существующие материалы в очередь (без скачивания)»**. По умолчанию они становятся исходным набором и не добавляются в очередь. Включённый флаг добавления существующих материалов отправляет их в обычную очередь, ожидающую Start.
5. Нажми **«Добавить и проверить»**. Первая проверка выполняется в фоне. Если она не завершилась успешно, источник остаётся для повторной проверки, а исходный набор не считается установленным.

При последующих проверках новые материалы появляются во входящих. Дата публикации и позиция в плейлисте не используются как единственное доказательство новизны: список сравнивается по точным URL внутри конкретной подписки.

### Краткое имя и папка подписки

Полное название коллекции остаётся в списке подписок, а краткое имя определяет подпапку для её материалов. Например, при `Output folder = D:\Video` подписка «123» скачивается в `D:\Video\123`. Если включено `Archive by date`, путь будет `D:\Video\ГГГГ-ММ-ДД\123`. Обычные ссылки сохраняются в выбранную папку вывода с учётом настройки даты.

Чтобы переименовать подписку, выбери её, измени краткое имя и сохрани. Недопустимые для Windows символы заменяются, лишние пробелы убираются, слишком длинное имя сокращается до 80 символов. После сохранения поле показывает имя, которое будет использовано для папки. Повторная проверка не меняет его вслед за названием канала.

Краткое имя закрепляется за новым заданием при добавлении в очередь, а общая папка вывода выбирается при **Start**. Переименование подписки действует на последующие добавления: уже поставленные задания сохраняют прежнее имя, а скачанные файлы остаются на месте. Если точный URL уже есть в обычной очереди, добавление из подписки сохраняет прежнее назначение этого задания. Краткое имя сохраняется при перезапуске и читается из прежних пользовательских данных.

### Проверка и действия со входящими

Можно проверить выбранную подписку или все активные, отменить текущую проверку, поставить подписку на паузу и удалить её. Пауза исключает источник из общей проверки; возобновление само по себе не запускает загрузку. Удаление подписки удаляет её записи и входящие, сохраняя скачанные файлы, постоянную историю и обычную очередь.

Во время проверки над списком подписок появляется карточка прогресса: текущий источник, этап, прошедшее время и число завершённых проверок из выбранных. Общая шкала учитывает источники, а анимированная полоса показывает работу с текущим источником. Этапы различают полный обход, разбор списка, необязательную RSS/Atom, сравнение и сохранение результата, а при первом импорте — добавление в очередь. Число материалов появляется после проверки полного списка; до этого процент внутри коллекции не вычисляется. При получении данных карточка также показывает фактически полученный объём. Итог остаётся видимым после завершения, ошибки или отмены; анимация и отсчёт времени останавливаются. Отмена и закрытие окна сохраняют прежние результаты незавершённого обхода.

Для выбранных материалов доступны действия:

- **В очередь** — добавить ссылки в обычную очередь; запуск производится кнопкой **Start**. Даже при работающей сессии это задания следующего запуска, без добавления в live ingress. Если материал удалён из обычной очереди до успешной загрузки, его можно добавить повторно из подписки той же кнопкой.
- **Пропустить** — сохранить решение не добавлять материал в очередь. Это не успех скачивания.
- **Открыть** — открыть исходный URL в браузере.

Входящие показывают материалы выбранной подписки. Исходный набор не засоряет входящие. Записи различают исходный набор, новые материалы, добавленные в очередь, успешно обработанные, уже обработанные в другом источнике и пропущенные пользователем. Повторная проверка не создаёт ещё одну запись с тем же точным URL в той же подписке. Различающиеся URL одного видео считаются разными записями.

Однократное уведомление о материале из другой подписки появляется только при наличии подтверждённого успеха этого точного URL в другой подписке. Постоянная история также подтверждает успех; если связь с другой подпиской неизвестна, материал помечается обработанным без такого уведомления. Постановка в очередь, исходный набор и пропуск не вызывают такое уведомление. Оно не повторяется при каждой проверке или открытии окна.

### Полнота проверки и сохранение данных

Полный список от `yt-dlp` определяет состав подписки. RSS/Atom дополняет метаданные только для точных URL, подтверждённых этим списком. Ссылки, найденные лишь в ленте, не добавляются во входящие: они могли исчезнуть, стать приватными либо не относиться к выбранной коллекции. Даже неизменившаяся лента не позволяет пропустить полный просмотр коллекции: лента может содержать только последние публикации. При недоступности или ошибке RSS используется результат полного просмотра через `yt-dlp`, а предупреждение о ленте показывается отдельно.

Обычная проверка раскрывает вложенные коллекции до отдельных материалов через `yt-dlp --no-flat-playlist`, без скачивания файлов. Это требует запросов метаданных каждого материала и может занимать больше времени, чем быстрый список плейлиста. Она ограничена 10 000 материалов, 180 секундами и 32 МиБ вывода метаданных `yt-dlp`. Для публикаций Pornhub действует отдельный сборщик, описанный ниже. RSS/Atom ограничена 2 МиБ и 12 секундами. Если коллекция превышает предел, ответ обрезан, содержит нераскрытые вложенные источники или непригодные элементы либо полное перечисление не удалось, проверка завершается ошибкой. Она не заменяет исходный набор, список материалов и время последней успешной проверки частичным результатом.

Подписки сохраняются в `%LOCALAPPDATA%\VideoDownloader\subscriptions.json`, отдельно от `session.json` и `successful-downloads.jsonl`. Ранее сохранённые подписки без краткого имени продолжают читаться; имя определяется при успешной проверке или задаётся вручную. Если JSON повреждён, приложение сообщает об ошибке и оставляет файл без изменений. Перед ручным редактированием закрой приложение и сделай копию файла.

В текущей версии проверки запускаются вручную. Открытие программы, возобновление подписки или обнаружение материалов не запускает скачивание автоматически. Таймеры, Планировщик Windows, фильтры и собственные профили подписок перечислены в [BACKLOG.md](BACKLOG.md).

### Публикации Pornhub

В **«Подписках»** поддерживаются адреса `/channels/имя`, `/model/имя`, `/pornstar/имя` и `/users/имя`, включая локализованные домены и ссылки на вкладку видео. Каналы проверяются по `/videos`, остальные профили — по `/videos/upload`. Начальная страница из параметра `page` игнорируется: обход начинается с первой страницы публикаций. История просмотров, избранное и рекомендации исключаются.

Чтобы скачать архив, при добавлении выбери добавление существующих материалов в очередь, дождись успешной проверки и нажми **Start** в основном окне. Без этого выбора первая проверка только запомнит текущие публикации. Для доступа с авторизацией укажи файл cookies в основном окне до проверки; тот же файл используется при скачивании роликов.

Обработчик последовательно обходит страницы и повторно проверяет первую страницу. Пределы — 10 000 уникальных роликов, 500 страниц, 15 минут и 32 МиБ итоговых метаданных. Пропуск страницы, повтор списка, изменение первой страницы, неподтверждённая пустая выдача или ошибка доступа завершают проверку без изменения прежнего набора. Если сайт меняет разметку, проверка может потребовать обновления приложения.

Если сайт перенаправляет `/videos/upload` на `/videos` того же профиля, сборщик продолжает обход по конечному адресу. Смена языка домена в пределах того же сайта также допустима. Переход на главную страницу профиля, другой профиль, избранное или страницу входа отклоняется; сообщение показывает конечный адрес без данных авторизации и произвольных параметров запроса.

Поддерживаются также списки публикаций `claimedUploadedVideoSection`, `moreData` с классом `videos`, списки каналов `channelVideosList` / `showAllChanelVideos` и обёртки `videoUList`. Обычная лента активности `moreData.feedItems`, история просмотров, рекомендации, боковые панели и меню исключаются. Независимые списки внутри одной обёртки не объединяются в один полный архив.

При наличии основной вкладки `section#videosTab` список и его пагинация выбираются внутри неё: сетки и кнопки навигации из других частей страницы не подменяют публикации. Вложенная обёртка и её список считаются одной секцией; точные копии списка сверяются и не дублируют ролики. Пустой блок без карточек, ссылок, счётчика, признака пустого архива и пагинации считается элементом разметки. Различающиеся самостоятельные списки вызывают ошибку с названиями секций и числом видео. Выбранная секция проверяется на всех страницах и при повторной проверке первой.

Если список не распознан, ошибка показывает адрес страницы, названия найденных секций и число карточек вне списка. Для распознанной страницы подтверждения возраста выводится отдельное сообщение. Подтверждение в браузере и запрос загрузчика — разные сессии. Поле **Cookies** в основном окне принимает путь к файлу cookies, экспортированному из браузера после подтверждения возраста или входа; открытие страницы в браузере само по себе не передаёт эту сессию приложению. Без подтверждённого списка прежние результаты сохраняются.

Сборщик создаёт обычные ссылки `https://www.pornhub.com/view_video.php?viewkey=…` (либо соответствующий основной домен сайта) и проверяет манифест полноты. При обнаружении не запрашиваются полные метаданные каждого ролика, поэтому недоступный ролик с известной ссылкой остаётся отдельной задачей и получает собственную ошибку при загрузке. Остальные задачи продолжаются; **Retry failed** повторяет неудачные загрузки. История успехов, отмена и восстановление работают для каждого видео отдельно. Сам канал не записывается как успешно скачанный материал.

Папка `collection-plugins/` должна оставаться рядом с приложением. Встроенный `yt-dlp.exe` загружает обработчик только при проверке подписки; установка Python пользователю не требуется. Добавление URL канала обычной кнопкой **Add** не включает этот сборщик — для импорта по роликам используй **«Подписки»**.

## Таблица загрузок

В таблице **Downloads** находятся результаты и активные задачи. Для выбранного файла доступны `Open file`, `Show in folder`, `Copy path`, `Open URL`, `Retry URL`, `Show raw error`.

Состояния выделены цветом: ожидание — серым, активная загрузка — голубым, успешная — зелёным, прерванная — жёлтым, ошибка — красным.

Процент относится к текущему видео- или аудиопотоку и может начинаться заново при переключении потока либо повторной попытке.

## Журнал и профили трассировки

Над журналом в панели **Downloads** находится выбор подробности: **«Только ошибки»**, **«Обычный»**, **«Прогресс загрузок»** и **«Подробный yt-dlp»**. Профиль применяется к новым событиям сразу, сохраняется между запусками и независим от **Profile** скачивания.

Для скачков процентов включи **«Прогресс загрузок»**: записи связываются с сессией, точным URL через короткий `job` и работником `T1`–`T4`. Видны смена компонента, сброс счётчика, повтор и расчёт общей шкалы. **«Подробный yt-dlp»** добавляет вывод stdout/stderr. Видео и аудио одного URL могут иметь отдельные проценты; при прямом URL плейлиста текущий ролик тоже меняется.

Кнопки **«Копировать журнал»** и **«Сохранить журнал…»** выгружают сохранённый в памяти хвост — до 5 000 записей и 2 МиБ. Экран показывает до 2 000 строк и 512 КиБ. **«Очистить»** очищает экран и память; автоматические файлы в `%LOCALAPPDATA%\VideoDownloader\logs` сохраняются, а самые старые заменяются по мере заполнения. Подробности и сценарий для четырёх параллельных загрузок — в [docs/LOGGING.md](docs/LOGGING.md).

## Параллельность, пауза и остановка

**Threads** задаёт максимальное число одновременно скачиваемых URL; **Fragments** — число параллельных фрагментов внутри `yt-dlp`. `Rate limit` ограничивает скорость.

**Pause / Resume** приостанавливают и возобновляют процессы Windows, включая связанные задачи FFmpeg. **Stop** отменяет сессию и выполняет очистку временных файлов, прежде чем окончательно закрыть программу. После остановки оставшиеся URL можно запустить вновь.

При нажатии X приложение предлагает спрятать окно в трей, выйти или остаться. При работе в трее загрузки и получение превью продолжаются.

## Настройки видео и аудио

| Поле | Доступные варианты и особенности |
| --- | --- |
| `Quality` | `Best`, 2160, 1440, 1080, 720; возможно снижение разрешения при отсутствии формата |
| `Codec` | `Auto`, `H264`, `VP9`, `AV1`; предпочтение, а не жёсткий запрет альтернатив |
| `Container` | `Auto`, `MP4`, `MKV`, `WebM`; для объединения потоков может понадобиться FFmpeg |
| `Rate limit` | Максимальная скорость, передаётся в `yt-dlp --limit-rate` |
| `Subtitles` | Обычные и автоматически распознанные субтитры, языки (например, `ru.*,en.*`), встраивание |
| `Metadata` | Обложка, главы, описательная информация |
| `Archive by date` | Подкаталог с датой загрузки |
| `MP3 only` | Сохранение только аудио |
| `Filename template` | Шаблон названия для `yt-dlp`, например `%(title)s [%(id)s].%(ext)s` |

Шаблон имени допускает относительные подпапки; абсолютные пути и компоненты `..` отклоняются до запуска `yt-dlp`. Внешние конфигурации `yt-dlp` игнорируются. Успешный результат требует существующего итогового медиафайла из `after_move:__VD_FILE__`; код завершения `0` без файла считается ошибкой и не попадает в историю.

Сетевые сбои повторяются с паузой, обычно по последовательности 5, 10, 20 секунд; ошибки доступа или недоступного материала не должны повторяться бесконечно.

## Системный трей

При наведении курсора значок показывает компактную статистику:

~~~text
VD | OK 12 Left 5 Err 2 | 2.5 MB/s
~~~

Поля расположены в порядке **OK → Left → Err**. Во время паузы показывается `Paused`. Сообщение ограничено длиной, поддерживаемой Windows `NotifyIcon`. Двойной щелчок или `Open` возвращает окно; `Exit` закрывает приложение. В трее также есть `Open downloads`.

## Зависимости и интеграция с браузером

В разделе **Dependencies** доступны проверка компонентов, обновление `yt-dlp`, установка FFmpeg и регистрация протокола `videodownloader://` в `HKCU\Software\Classes\videodownloader`. После регистрации внешний вызов может добавить ссылку в работающий экземпляр приложения.

Установка FFmpeg скачивает внешний архив; для этого нужны сеть и права записи в папку программы. Проверка цифровой подписи скачиваемого архива отдельно пока не реализована.

## История и восстановление после перезапуска

История успешных URL хранится в `successful-downloads.jsonl`. Перед повторной загрузкой известного URL появляется диалог: загрузить снова, пропустить, применить выбор ко всем совпадениям либо отменить начало сессии. Данные не удаляются при очистке очереди.

Очередь и настройки атомарно сохраняются в `session.json`. После запуска можно восстановить незавершённую очередь; скачивание не начинается автоматически. Активные задания прошлого запуска переходят в состояние прерванных. Настройки применяются даже при отказе от восстановления строк. Пока открыт диалог восстановления, автосохранение защищает исходный файл; повреждённый checkpoint остаётся без изменений.

Приложение читает финальные `Result` из прежнего PowerShell-журнала по `Engine.EventsPath`, если старый интерфейс завершился до сохранения checkpoint. Старые события не применяются к повторно добавленной строке `DeferredToNextStart`. Незавершённая очистка и исходная папка вывода сохраняются. Если старый процесс `pwsh` ещё работает с этими данными, восстановление и начало новой сессии блокируются: заверши прежнюю загрузку и перезапусти программу.

История поддерживает корректную последнюю JSON-запись без завершающего перевода строки. Повреждённый незавершённый хвост не исправляется молча; при ошибке чтения истории новый запуск блокируется. Форматы данных прежних версий сохраняются; повторная установка не требует их удаления.

## Где проверять изменения

На Windows с .NET 8 SDK и PowerShell 7:

~~~powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Test
~~~

Команда собирает `src/VideoDownloader/VideoDownloader.csproj` и запускает `tests/VideoDownloader.Tests/` и отдельный WPF-host `tests/VideoDownloader.UiTests/`. Проверяются движок, файловая безопасность, совместимость со старыми данными и настоящие контролы приложения в изолированном профиле. Единственный Windows workflow `native-windows.yml` выполняет эти проверки и тесты встроенного коллектора перед публикацией portable ZIP. Компоненты и границы их ответственности описаны в [архитектуре](docs/ARCHITECTURE.md).
