# Video Downloader — руководство по интерфейсу

Программа имеет два способа запуска с общей WPF-разметкой `ui/MainWindow.xaml`:

- **Нативная C#-версия** — `VideoDownloader.exe` из GitHub Releases, не требует PowerShell. Очередью и `yt-dlp` управляет код в папке `native/`.
- **Резервная PowerShell-версия** — `start-gui.cmd` из исходников без EXE (для неё нужен PowerShell 7). Очередью управляют `ytdl-manager-gui.ps1` и `ytdl-manager-v8.ps1`.

Если `start-gui.cmd` находит EXE рядом с собой или в `dist/`, он **запускает EXE**, а не PowerShell. В обоих интерфейсах присутствуют новые кнопки и русские профили. Пользовательская история и checkpoint общие: не запускайте обе версии одновременно.

## Очередь ссылок

Можно добавлять:

- одну ссылку или несколько HTTP/HTTPS-ссылок в поле ввода;
- содержимое буфера через **Paste**; при включении **Watch clipboard** ссылки добавляются автоматически;
- `.txt` со списком URL и Windows `.url`;
- ссылки и файлы перетаскиванием в окно.

Повторяющиеся URL в очередь не добавляются. До запуска доступны изменение порядка мышью и стрелками, `Remove` и `Clear`. Во время активной загрузки очередь остаётся доступной для выбора, просмотра превью, открытия и копирования URL.

**Новые ссылки во время скачивания:** в C# используются асинхронная очередь и прямое добавление в текущий координатор заданий. В старой PowerShell-версии — отдельный входящий файл `incoming.txt`, который читает движок. Если активная сессия уже закончилась, новая ссылка останется в очереди до следующего запуска.

### Кнопка открытия папки загрузок

В верхней части очереди **сразу рядом с `↻ Failed`** находится кнопка **«📂 Открыть папку загрузок»**. Она не зависит от выделения файла в таблице и не удаляет файлы.

Папка берётся из поля `Output folder`. При включённом `Archive by date` открывается датированная подпапка вида `D:\Videos\2026-10-20`. В C# при активном скачивании используется **зафиксированный каталог текущей сессии**, чтобы переход через полночь не переключал папку.

Если каталог ещё не создан, приложение показывает предупреждение вместо открытия чужой родительской папки. Чтобы изменить каталог, используй поле `Output folder` или кнопку с многоточием рядом с ним.

Отдельная кнопка `Show in folder` в таблице результатов продолжает открывать **папку конкретного скачанного файла**; эти действия не следует путать.

### Удаление и отмена конкретного задания

`Remove` доступна во время скачивания. Она отменяет только выбранный URL, не останавливая остальные задания. Для начатых и завершённых загрузок запрашивается подтверждение удаления связанных файлов. В C# и PowerShell используются отдельные временные staging-папки и список `OwnedPaths`, чтобы не удалить чужие файлы.

Файлы не удаляются по шаблонам. Проверяется принадлежность папке назначения, отклоняются выходы за каталог через `..` и NTFS junction/symlink/reparse point. Наличие одного лишь старого пути из checkpoint **не является достаточным подтверждением владения**. От намеренной конкурентной подмены файловой системы (TOCTOU) полной гарантии пока нет.

В резервном PowerShell-интерфейсе строка активного задания остаётся до подтверждения очистки событием `Result` либо до подтверждённого завершения движка и успешной локальной очистки GUI. Если файл заблокирован или не хватает прав, приложение показывает ошибку и сохраняет строку для повторного `Remove`. Исходный `OutputRoot` хранится у задания: смена поля `Output folder` после скачивания не меняет границы удаления старого результата. Перед `Remove` GUI дочитывает финальные события, даже если процесс уже завершился.

После подтверждённого удаления повторное добавление того же URL в ещё работающий PowerShell-сеанс оставляет его `Queued` до следующего запуска. Пока отмена не подтверждена, строка остаётся в очереди и повторно не добавляется.

Удаление файла не удаляет соответствующий URL из постоянной истории успешных загрузок.

## Профили загрузки

В поле **Profile** названия показываются на русском:

| Название | Основные настройки |
| --- | --- |
| **Универсальный** | Максимально доступное качество и автоматические параметры |
| **Архив 4K** | До 2160p, контейнер MKV, метаданные и главы |
| **Совместимый MP4** | До 1080p, предпочтение H.264, контейнер MP4 |
| **Музыка MP3** | Извлечение звука, метаданные и обложка |
| **Архив с субтитрами** | MKV, субтитры, автосубтитры и встраивание |

Профили применяют готовые наборы полей. Ты можешь вручную изменить любое поле после выбора профиля. Создание собственных именованных профилей пока не предусмотрено. В резервном PowerShell-интерфейсе выбор профиля полностью задаёт связанные параметры: обычные и автоматические субтитры, встраивание данных и режим только аудио не наследуются от предыдущего профиля. Настройки очереди сохраняются в checkpoint и восстанавливаются после подтверждения; это не глобальные пользовательские профили.

**Совместимость с предыдущими версиями:** в файле `session.json` имена по-прежнему сохраняются как `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3` и `Subtitles archive`. При открытии старой сессии они преобразуются в русские названия. Это работает и в C#, и в PowerShell-версии.

## Папка настроек приложения

В разделе **Dependencies** рядом с **Register protocol** находится кнопка **«📁 Открыть папку настроек»**.

Она открывает в Проводнике:

~~~text
%LOCALAPPDATA%\VideoDownloader
~~~

Обычно это `C:\Users\<имя>\AppData\Local\VideoDownloader`. Используется именно **Local**, а не `%APPDATA%` (`Roaming`).

Содержимое:

| Путь | Назначение |
| --- | --- |
| `session.json` | Сохранённая очередь и параметры |
| `successful-downloads.jsonl` | Постоянная история успешных URL |
| `preview-cache\` | JSON-кеш метаданных и изображений |

Если директория настроек ещё не существует, кнопка создаёт её и открывает. Сама кнопка ничего не удаляет и не сбрасывает. Прежде чем вручную менять эти файлы, закрой программу и сделай резервную копию.

## Предпросмотр

В панели **Preview** отображаются заголовок, автор, продолжительность, обложка, платформа, доступное разрешение, FPS, кодеки и HDR (если эти сведения предоставлены сайтом).

В C#-версии и резервной PowerShell-версии метаданные готовит отдельный фоновый работник. Он не мешает текущим загрузкам. При выборе URL без готового превью эта ссылка получает приоритет. При ручном Paste приложение выбирает добавленную ссылку и начинает показывать её превью, когда данные готовы; Watch clipboard не должен сбрасывать текущее выделение.

Кеш хранится 72 часа в папке `preview-cache`, расположенной внутри каталога настроек. Повреждённые или устаревшие записи игнорируются/обновляются. Изображения декодируются из байтов, а не с пользовательского доступа к UI-элементам из фонового потока.

Некоторые сайты могут требовать cookies. Путь к файлу задаётся в `Cookies`, а не содержимое cookies непосредственно в программе. Ошибки получения метаданных выводятся в лог.

## Таблица загрузок

В таблице **Downloads** находятся результаты и активные задачи. Для выбранного файла доступны `Open file`, `Show in folder`, `Copy path`, `Open URL`, `Retry URL`, `Show raw error`.

Состояния выделены цветом: ожидание — серым, активная загрузка — голубым, успешная — зелёным, прерванная — жёлтым, ошибка — красным.

Процент относится к текущему видео- или аудиопотоку и может начинаться заново при переключении потока либо повторной попытке.

## Параллельность, пауза и остановка

**Threads** задаёт максимальное число одновременно скачиваемых URL; **Fragments** — число параллельных фрагментов внутри `yt-dlp`. `Rate limit` ограничивает скорость.

**Pause / Resume** приостанавливают и возобновляют процессы Windows, включая связанные задачи FFmpeg. **Stop** отменяет сессию и выполняет очистку временных файлов, прежде чем окончательно закрыть программу. После остановки оставшиеся URL можно запустить вновь.

При нажатии X приложение предлагает спрятать окно в трей, выйти или остаться. При работе в трее загрузки и получение превью продолжаются.

## Настройки видео и аудио

| Поле | Доступные варианты и особенности |
| --- | --- |
| `Quality` | `Best`, 2160, 1440, 1080, 720; возможно снижение разрешения при отсутствии формата |
| `Codec` | `Auto`, `H264`, `VP9`, `AV1`; предпочтение, а не жёсткий запрет альтернатив |
| `Container` | `Auto`, `MP4`, `MKV`, `WebM`; для объединения потоков может понадобиться FFmpeg |
| `Rate limit` | Максимальная скорость, передаётся в `yt-dlp --limit-rate` |
| `Subtitles` | Обычные и автоматически распознанные субтитры, языки (например, `ru.*,en.*`), встраивание |
| `Metadata` | Обложка, главы, описательная информация |
| `Archive by date` | Подкаталог с датой загрузки |
| `MP3 only` | Сохранение только аудио |
| `Filename template` | Шаблон названия для `yt-dlp`, например `%(title)s [%(id)s].%(ext)s` |

В резервном PowerShell-движке шаблон имени допускает относительные подпапки; абсолютные пути и компоненты `..` отклоняются до запуска `yt-dlp`. Внешние конфигурации `yt-dlp` игнорируются. Успешный результат требует существующего итогового медиафайла из `after_move:__VD_FILE__`; код завершения `0` без файла считается ошибкой и не попадает в историю.

Сетевые сбои повторяются с паузой, обычно по последовательности 5, 10, 20 секунд; ошибки доступа или недоступного материала не должны повторяться бесконечно.

## Системный трей

При наведении курсора значок показывает компактную статистику:

~~~text
VD | OK 12 Left 5 Err 2 | 2.5 MB/s
~~~

Поля расположены в порядке **OK → Left → Err**. Во время паузы показывается `Paused`. Сообщение ограничено длиной, поддерживаемой Windows `NotifyIcon`. Двойной щелчок или `Open` возвращает окно; `Exit` закрывает приложение. В трее также есть `Open downloads`.

## Зависимости и интеграция с браузером

В разделе **Dependencies** доступны проверка компонентов, обновление `yt-dlp`, установка FFmpeg и регистрация протокола `videodownloader://` в `HKCU\Software\Classes\videodownloader`. После регистрации внешний вызов может добавить ссылку в работающий экземпляр приложения.

Установка FFmpeg скачивает внешний архив; для этого нужны сеть и права записи в папку программы. Проверка цифровой подписи скачиваемого архива отдельно пока не реализована.

## История и восстановление после перезапуска

История успешных URL хранится в `successful-downloads.jsonl`. Перед повторной загрузкой известного URL появляется диалог: загрузить снова, пропустить, применить выбор ко всем совпадениям либо отменить начало сессии. Данные не удаляются при очистке очереди.

При закрытии создаётся `session.json`. После запуска можно восстановить незавершённую очередь и настройки; скачивание не начинается без решения пользователя. Активные задания прошлого запуска переходят в состояние прерванных. Новая C#-версия также может восстанавливать финальные результаты из старого PowerShell журнала событий, если старое окно успело закрыться до сохранения checkpoint.

При восстановлении резервного PowerShell-интерфейса новые загрузки блокируются, пока прежний движок ещё работает. Восстановленный контекст хранит путь отмены и исходную папку вывода: `Remove` продолжает работать с прежним движком, а финальные события сверяются во время его работы и перед новым запуском. Если контекст отмены из старого checkpoint восстановить невозможно, GUI сообщает об ограничении вместо удаления активной строки.

PowerShell-движок поддерживает корректную последнюю JSON-запись истории без завершающего перевода строки при последующем добавлении. Повреждённый незавершённый хвост не исправляется молча; при ошибке чтения истории новый запуск блокируется.

Запрещено одновременно запускать обе версии: они имеют общие историю и настройки, но разные движки.

## Где проверять изменения

Нативный C#-интерфейс проверяется отдельным Windows-тестом с настоящим WPF-окном:

~~~powershell
dotnet build native/VideoDownloader.Native.csproj -c Release
dotnet run --project native-tests/VideoDownloader.NativeTests.csproj -c Release
~~~

PowerShell-интерфейс проверяется так:

~~~powershell
pwsh -NoProfile -File .\tests\russian-ui-tests.ps1
pwsh -NoProfile -File .\tests\smoke.ps1
pwsh -NoProfile -File .\tests\session-checkpoint-tests.ps1
pwsh -NoProfile -File .\tests\download-history-tests.ps1
pwsh -NoProfile -File .\tests\engine-review-regression-tests.ps1
pwsh -NoProfile -File .\tests\gui-review-regression-tests.ps1
pwsh -NoProfile -File .\tests\file-boundary-safety-tests.ps1
~~~

В GitHub Actions эти проверки запускаются вместе с остальными Windows CI-тестами перед публикацией portable ZIP.
