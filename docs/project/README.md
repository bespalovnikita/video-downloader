## Текущая основа

В проекте два приложения: Windows на C# / .NET 8 / WPF и Android на Kotlin / Jetpack Compose. Оба используют yt-dlp и FFmpeg. Предложения развивают этот стек; перенос на другой UI-фреймворк или отдельный постоянно работающий сервер не требуется.

Уже доступны очередь и история, ручные подписки, необязательное обогащение названий через RSS/Atom, подпапки подписок, галерея до 15 готовых изображений сайта и перенос очереди между платформами через `VDQUEUE1:` / `.vdqueue`. APK собирается в GitHub Actions; Windows имеет автоматические стабильные релизы. Эти возможности не являются новыми задачами дорожной карты.

Функциональность клиентов различается: Windows уже имеет расширенные профили журнала, проверенное окно новых публикаций, общее предложение принять новинки и отдельную панель сведений о материале подписки. В Android соответствующие доработки запланированы в [плане выравнивания](ANDROID_PARITY.md).

Проверки подписок сейчас запускаются вручную. Добавление материалов в очередь не запускает скачивание: нужен `Start`. Проверок по расписанию, задания Планировщика Windows и автоматического скачивания по подписке сейчас нет.

## Рекомендуемый порядок

1. Выровнять основные сценарии Android с Windows, начиная со списка подписки, прогресса и диагностики.
2. Упростить большие очереди и входящие: поиск, фильтры, группы и пакетные действия.
3. Добавить индивидуальные правила подписок с предварительным просмотром результата.
4. Развить диагностику и управление местом на диске, сохраняя историю и пользовательские файлы.
5. После этого развивать проверки по расписанию и отдельные политики автоматического скачивания по явному выбору пользователя.

Приоритеты обозначают порядок обсуждения и разработки, а не обещанную дату выпуска. Реализация каждого пункта требует отдельной задачи, проверки и обновления руководств под фактическое поведение.
