# Контракты Windows для агента

Прочитай после [CORE.md](CORE.md) и [SHARED.md](SHARED.md), если задача затрагивает C#, WPF, Windows-данные, зависимости, сборку или тесты. Пути в кодовых фрагментах указаны от корня репозитория. Это действующие ограничения реализации, а не список будущих функций.

## Проект и точки входа

- Точка запуска — `VideoDownloader.exe`; пользовательского CLI, CMD-launcher и резервного GUI нет.
- Единственный Windows-проект приложения: `src/VideoDownloader/VideoDownloader.csproj`. Окна и XAML находятся в `src/VideoDownloader/UI/Views/`, владельцы состояния — в `src/VideoDownloader/UI/Controllers/`.
- Модели и entry point находятся в корне проекта; загрузки, превью, подписки, хранение и совместимость разделены по `Downloads/`, `Preview/`, `Subscriptions/`, `Persistence/`, `Compatibility/`; Windows-процессы — в `Infrastructure/Windows/`.
- C# unit/integration-тесты: `tests/VideoDownloader.Tests/`; настоящие WPF-сценарии: `tests/VideoDownloader.UiTests/`. Оба проекта ссылаются на приложение через ProjectReference. Не включай тестовые partial-классы, сценарии или переключатели запуска тестов в релизный EXE.
- Единые команды build/test/publish: `scripts/build.ps1`. PowerShell нужен разработке и CI, не приложению.
- Релизный ZIP автономен: пользователь не устанавливает PowerShell, Python или .NET Runtime.
- Сохраняй чтение прежних пользовательских данных в `%LOCALAPPDATA%\VideoDownloader`, включая финальные Result-события и защиту от живого старого работника `pwsh`.

## Архитектура и владение процессами

WPF-интерфейс и движок расположены в `src/VideoDownloader/`, два тестовых проекта — в `tests/`. Релизный ZIP создаётся workflow `native-windows.yml`.
Пользовательская сборка не должна включать CMD/PowerShell-скрипты или запускать `pwsh.exe`. URL, TXT, InternetShortcut и `videodownloader://` передаются в интерфейс; второй экземпляр использует singleton и named pipe и возвращает существующее окно из трея.

При изменениях в `src/VideoDownloader/`:
- Запускай native Windows CI: сборка, открытие окна WPF, реальные Add/Remove,
  clipboard-preview, .url import и checkpoint через изолированный UI-тест.
- Запускай офлайн тесты реального `yt-dlp.exe`: параллельная загрузка,
  queued/running cancellation, late live Add, pause/resume.
- При отмене URL используй tombstone и синхронизацию конечного результата:
  публикация и удаление файлов должны быть согласованы, без оставшихся media.
- `DownloadItem` сохраняет прежние `PendingRemoval`, `CleanupError`,
  `CleanupPaths`, `StageDir`, `RunDir`, `AttemptFinished`, `DeferredToNextStart`.
  Не удаляй активную строку до подтверждения работника. Ошибка очистки и
  частичный манифест переживают checkpoint, Clear Queue и обновление приложения;
  Start/Retry исключают такие строки. Полный список опубликованных файлов
  сохраняется даже при неудачном rollback; меняй списки атомарной заменой,
  чтобы сериализация GUI не гонялась с изменением коллекции работником.
- Старый Result не применяется к `DeferredToNextStart`. Сохраняй контекст
  очистки и исходный `OutputRoot` также при чтении legacy Result-событий.
- Успех требует валидного `after_move:__VD_FILE__` media path из staging;
  код 0 без медиа не должен публиковать sidecars или пополнять историю.
- Счётчики transfer учитывают сброс при retry; постоянная HTTP/auth ошибка
  имеет приоритет над transient-подсказками в том же diagnostic.
- Операции удаления разрешены только с известным `OwnedPaths`; неизвестный
  путь из старого checkpoint сам по себе **не является доказательством владения**.
- Относись к C# `session.json`, `successful-downloads.jsonl`, preview cache
  как к совместимым с ранее использованными форматами.
- Из старого `Engine.EventsPath` читай финальные Result-события: старый GUI
  мог умереть до сохранения checkpoint. Активный legacy `pwsh` блокирует
  восстановление и новые native sessions.
- При `Archive` фиксируй каталог назначения на всю сессию; ночной переход
  даты не должен менять место публикации и удаления.
- Создавай native процессы загрузки, превью и сканирования yt-dlp через `ManagedChildProcess`: индивидуальный job назначается атомарно через `PROC_THREAD_ATTRIBUTE_JOB_LIST`; наследуются только явные pipe handles. Не помещай GUI или открываемые пользователем приложения в job работника. `yt-dlp -U` запускается отдельно: его штатная отложенная очистка `.old` должна пережить выход обновляющего процесса. Проверяй аварийный выход владельца, потомков, независимый процесс, аргументы, окружение и оба pipe в Windows CI.
- До запуска загрузок UI проверяет FFmpeg/ffprobe. Выбранный контейнер требует и merge, и remux; native-публикация проверяет расширение результата.
- После модального подтверждения live Add повторно проверяй наличие URL и идентичность активной сессии. Повторный вход не создаёт дубликат; завершённая или заменённая сессия оставляет ссылку для следующего Start. Проверяй это реальными вложенными WPF-диалогами.
- Границы вывода поддерживают корень диска/UNC с одним завершающим separator; сам root не считается дочерним файлом.
- Разрешённая повторная загрузка выбирает свободный суффикс для всего batch media/sidecars. `OwnedPaths` содержит только новые файлы. Helper без явного `renameCollisions` продолжает отклонять существующий destination; никакой overwrite. Планирование и публикация параллельных заданий согласованы; гонка с внешним процессом не разрешает перезапись чужого файла.
- Не запускай таймеры до восстановления. `SaveCheckpoint` блокируется на всём протяжении диалогов восстановления; ошибка чтения переводит checkpoint в read-only до показа предупреждения. Настройки восстанавливаются при пустой/завершённой очереди и при отказе от восстановления строк. Установка FFmpeg имеет общий шестиминутный deadline скачивания, включая тело при `ResponseHeadersRead`; timeout/cancel удаляет scratch и освобождает кнопки зависимостей.
- Для полной защиты от намеренной TOCTOU-подмены каталогов понадобится
  handle-based Win32 реализация; текущая проверка reparse/junction не даёт
  такой абсолютной гарантии.

Схемы взаимодействия компонентов и совместимость данных описаны в
[архитектуре](../developer/architecture.md), правила выпуска — в
[правилах выпуска](../developer/releases.md).

## Русификация интерфейса и документации

- Пользовательские ошибки локализует `Infrastructure/ErrorMessages.cs` по `CultureInfo.CurrentUICulture` (все локали `ru`); `CurrentCulture` отвечает за числа/даты, не язык сообщений. Перевод применяется только при отображении. Не меняй `RawError`, `CleanupError`, `LastError`, `LastWarning`, текст диагностических файлов/кеша или машинные `State`/`Status`; display-only поля помечай `JsonIgnore`. Сохраняй доступ к исходной диагностике. Для новых правил проверяй русскую и нерусскую UI-локаль, приоритет HTTP/auth над временными ошибками и отсутствие ложных совпадений по ID/URL. Не используй переведённый текст для retry, успеха или восстановления кеша.
- Названия встроенных профилей **локализуются только для отображения**. Идентификаторы `Universal`, `4K archive`, `MP4 compatibility`, `Music MP3`, `Subtitles archive` в `session.json` неизменны.
- Маппинг находится в `src/VideoDownloader/Downloads/ProfileCatalog.cs`.
- WPF-разметка должна содержать две кнопки: `OpenOutputDirectoryButton` возле `RetryFailedButton` и `OpenAppSettingsButton` возле `RegisterProtocolButton`. Обработчики обязательны в UI.
- Для настроек используется **`%LOCALAPPDATA%\VideoDownloader`**, не `%APPDATA%` (Roaming). В C# путь нужно получать из фактического экземпляра `AppPersistence`, чтобы поддерживался тестовый профиль.
- Папка загрузок берётся из UI, а во время активной C#-сессии — из зафиксированного `DownloadOptions.OutputDirectory`; архивирование добавляет подкаталог даты.
- Перед merge обязательно проверь `scripts/russian-ui-tests.ps1` и настоящие WPF-тесты в Windows CI. Единая команда — `pwsh -NoProfile -File scripts/build.ps1 -Task Test`.

## Архитектурные инварианты

### Структурированный прогресс

Не возвращай парсинг обычных строк <code>[download] ...</code> как основной механизм прогресса.

Engine использует:

- <code>--progress-template</code> с <code>__VD_PROGRESS__</code>;
- <code>--print before_dl:__VD_TITLE__:</code>;
- <code>--print before_dl:__VD_PLAN__:</code> с ограниченными полями идентичности материала, форматов и позиции/размера плейлиста;
- <code>--print after_move:__VD_FILE__:</code>.

Структурированный вывод разбирается в `src/VideoDownloader/Downloads/YtDlpOutputParser.cs`, аргументы строит `YtDlpArguments` в том же каталоге. Согласованное завершение, отмена, публикация и очистка остаются в `DownloadCoordinator`.

Human-readable stdout допустимо анализировать только для вспомогательных событий вроде merge/error diagnostics.

`--progress` обязателен вместе с `--print`. Stdout/stderr читаются параллельно. UI показывает progress/скорость/объём/ETA в обеих таблицах. Result не должен повторно прибавлять размер файла к уже учтённому session transfer volume. При чтении старых JSONL-событий не принимай неполный или некорректный Result за терминальный результат; процент прогресса сам по себе не доказывает успех.

### Журнал и трассировка

- Профиль `DownloadOptions.LogProfile` хранится отдельным стабильным ID: `Errors`, `Standard`, `Progress`, `Detailed`. Старые настройки без поля и неизвестный ID используют `Standard`. Выбор профиля скачивания не сбрасывает профиль журнала; изменение подробности действует во время сессии без её перезапуска.
- Передавай снимки диагностических событий со стабильными session/job/worker и попыткой, качеством, компонентом, источником stdout/stderr, порядком и временем. Короткий job вычисляется из точной строки URL; не нормализуй адрес ради логирования. Общую статистику связывай с сессией и составом учитываемых строк.
- Все per-job события, включая `Verbose/yt-dlp` и `Progress/download`, содержат `video_seq` из текущего `DownloadItem.Order` и `video` с названием либо точным URL при неизвестном названии. При Order=0 показывай `video_seq=?`. Метку маскируй до JSON-цитирования и ограничивай 160 символами; в `overall.members` используй те же поля с меткой до 64 символов. Сохраняй job/session/worker и engine `seq`: номер строки не является устойчивой идентичностью. Общий список ограничен 32 строками и 2800 символами, содержит `members_shown` / `members_truncated`; суммарные счётчики учитывают всю сессию.
- Читаемый префикс журнала — `[yyyy-MM-dd HH:mm:ss.fff]` по локальному времени, без зоны и отображаемого `#`-счётчика. Внутренний `Entry.Sequence` и курсор выдачи сохраняются для порядка/вытеснения; это не номер видео и не код цвета. Не обещай цвет по текстовому префиксу: текущий журнал — обычный TextBox. Отдельные `seq`, `ui_seq` и elapsed-поля трассы остаются.
- Прогресс берётся из `__VD_PROGRESS__`, план компонентов — из `__VD_PLAN__`. Общая шкала задачи усредняет выбранные компоненты с равным весом и потолком 99%; этап и сырой процент текущего компонента отображаются отдельно. Только успешная публикация устанавливает 100%. При неизвестном плане/размере коллекции сохраняй честный fallback текущего материала и объясняй ограничение. Смена компонента, сброс байтов и уменьшение процента должны быть объяснимы по трассе. Не маскируй реальные повторы искусственным монотонным `Math.Max`; `N/A`, NaN и Infinity не должны заменять последнее известное значение нулём или попадать в WPF как нечисловой процент. Повтор/quality fallback отмечай отдельной попыткой и состоянием; после начала postprocessing не перезапускай весь download автоматически.
- Ограничивай частоту обычных образцов, размер строк, память, очередь записи и файлы. Записывай файлы в фоне; WPF получает пакеты событий вместо отдельного Dispatcher-вызова на каждую строку. Ошибки sink, записи и ротации не меняют скачивание, историю и публикацию. Переполнение и отказ записи сообщаются в ограниченном виде.
- До сохранения и копирования маскируй URL userinfo/fragment, значения query за пределами разрешённого списка публичных идентификаторов и навигации, известные заголовки и параметры авторизации. Сохраняй диагностически полезные `v`, `list`, `viewkey` и другие ключи из `JournalSanitizer` с точным написанием URL; неизвестные параметры и токены не раскрывай. Не записывай содержимое cookies, полный argv или окружение. Подробный профиль сохраняет stdout/stderr, не требует `--verbose`.
- Сообщения журнала показывай с настоящими переносами строк, включая разделение перевода и исходной диагностики. Продолжения одной записи отделяй от нового заголовка отступом; correlation fields оставляй однострочными. Экран, Copy, Save и текстовые `journal*.log` должны согласованно сохранять многострочный текст. Не делай blanket-unescape произвольных `\\r`/`\\n`: это может повредить Windows-пути. Машинное JSONL-экранирование не меняй.
- Окно диагностики закрепляй за точным URL выбранной строки. Принадлежность событий определяй по типизированному полному SHA-256 `Identity`, не grep по сообщению или 12-символьному `job`. Для порядка/дедупликации используй `Journal` + `Sequence`, для попытки — журнал/сессию/invocation и отдельный номер retry. Параметры бери из разрешённого immutable снимка при admission/попытке/ошибке, а не из текущих настроек UI; не сериализуй целиком options/selection. Старые текстовые журналы не восстанавливают отсутствующие попытки.
- Текст и `job-events*.jsonl` делят одно кольцо 5 000 записей / 2 МиБ, одну очередь 2 048 записей / 4 МиБ и три парные ротации до 5 МиБ каждая. Чтение задания выполняй в фоне: до 15 МиБ входа, 64 КиБ на JSONL-строку, 2 000 событий / 2 МиБ результата, два общих слота и явные счётчики усечения/недоступности. Закрытие окна отменяет чтение/экспорт; поздний ответ не обновляет закрытый UI. Эти операции не меняют checkpoint/history и не мешают активному скачиванию.
- Переносимый ZIP строится из снимка разрешённых событий, не из всего профиля и не из сырых текстовых файлов. После `JournalSanitizer` скрывай абсолютные Windows/UNC/Unix-пути, включая пробелы/Unicode, и диагностические argv. Пять фиксированных entries, лимит 8 МиБ несжатого содержимого, свой CreateNew temp и очистка только его; overwrite требует явного подтверждения замены. Версии узнавай локальными ограниченными owned child без сети, не сохраняй stderr/полный stdout. Отмена/таймаут завершает и дожидается child и обоих потоков. Проверяй реальные JSONL/ZIP/процессы/Windows-окно в `JobDiagnosticsTests` и `JobDiagnosticsUiTests`.
- Проверяй профили, фильтрацию, маскирование, конкуренцию и ограничения нативными тестами; реальный WPF-сценарий должен проверять переключение, восстановление и копирование. Интеграция с упакованным yt-dlp должна подтвердить независимые трассы четырёх параллельных заданий. Пользовательское описание — [руководстве по журналу](../user/windows-logging.md).

### Предварительная загрузка превью

URL должен попадать в preview-prefetch queue сразу после добавления в Queue. Это немедленная постановка запроса: единственный работник может ждать предыдущий запрос и ответ сайта. Не обещай мгновенную готовность изображения; публикуй название и первую картинку по готовности, не ожидая всей галереи.

Контракт:

- один независимый background preview worker;
- Clipboard URLs во время загрузки получают приоритет в очереди prefetch, а ручной Paste сразу показывает выбранную ссылку в preview панели; Watch clipboard не крадёт текущее выделение;
- metadata + thumbnail запрашиваются заранее;
- клик по строке читает cache;
- если preview ещё не готов, клик только повышает приоритет URL;
- клик не создаёт второй тяжёлый metadata request;
- persistent cache: <code>%LOCALAPPDATA%\VideoDownloader\preview-cache</code>;
- TTL пригодных данных и ответа без кандидатов изображений: **72 часа**;
- cache key: SHA-256 URL.

Получение и кеширование реализованы в `src/VideoDownloader/Preview/PreviewService.cs`.

`Show` и `RequestUrl` явно выбранного URL запрашивают локальный fallback для текущей пригодной Completed-строки также за пределами startup256, включая панель подписок. Потеря ранее успешного изображения из памяти/по TTL допускает повтор при следующем выборе; неудачный decoder не должен повторяться на каждый клик. Для сохранения remote image в `CanKeepPoster` требуется свежесть её метаданных, согласованная с `Peek`; отдельный TTL локального кадра остаётся прежним.

После успешной публикации видео допустим локальный запасной кадр, если пригодной обложки сайта нет или она повреждена. Работает тот же единственный `PreviewService` с чередованием сетевых/локальных заданий, без yt-dlp и сети для локального задания. Требуются Completed + AttemptFinished, подтверждённый опубликованный `OwnedPaths`, `OutputRoot`, отсутствие staging/cleanup/pending removal; путь из импортированной истории не даёт гранта. Проверяй regular/no-reparse/границу корня и неизменность файла; на Windows read lease живёт до dispatcher-допуска. FFprobe исключает audio-only/attached_pic; фиксированный безопасный demuxer + protocol whitelist только `file`, для MOV внешние ссылки выключены. Сырой probe/stderr ограничен 128 КиБ, PNG — 1 МиБ / 640 × 360, общий probe/decode deadline — 20 секунд; отмена/ошибка ждёт child и оба pipe. Локальная очередь ≤64, UI admission ≤16, startup backfill ≤256 строк; новые Completed обрабатываются независимо от выбора и Start, при переполнении остаются слабые маркеры с дозаполнением до 16 текущих строк без горячего повтора отказов. Кеш общий: только image-only merge, прежние SavedAtUtc/Success/PreviewFetchVersion/ThumbnailError/форматы сохраняются, пригодная remote image выигрывает повторную проверку при допуске. Локальный кадр не отменяет минутный cooldown повторного remote-запроса или повтор после появления конвертера; до ответа сайта он остаётся видимым. Additive LocalThumbnailFingerprint — только хеш, LocalThumbnailSavedAtUtc задаёт срок локального изображения отдельно от метаданных. Не меняй media/sidecar/history/Processed/status/ownership и не записывай название/checkpoint из image-only callback. Перед remove/retry/dependency replacement/profile maintenance/close отменяй и join-ь работу, проверяй stale row/attempt/owner/барьеры; updater ждёт простоя. Проверки — реальные цветные кадры, audio-only/cover/corrupt/manifest, merge/remote race/TTL, bounded queue/output, PID join и настоящий WPF без выбора строки.

У правой панели подписок свой выбранный URL: `SubscriptionPreviewController` получает данные и ошибки того же `PreviewController` / `PreviewService`, а не создаёт второго работника. Один выбранный материал показывает известные название, URL, состояние, подписку и время обнаружения сразу, метаданные и до двух пригодных изображений — по готовности. Выбор нескольких строк или отсутствие выбора очищает панель; выбор во входящих не меняет Preview основного окна. Дисковый кеш не читай из UI: используй memory-only `GetCached` и обычный запрос общего работника. Ошибка или поздний callback другой ссылки не стирает сведения текущего материала; пригодные картинки сохраняются при сбое обновления. Закрытие и Dispose отписывают панель от событий и освобождают изображения. Проверяй холодные HTTP-картинки, две разные картинки, быстрый A → B, готовый кеш без сети, множественный выбор, закрытие и повторное открытие.

Пустой результат версии получения 3 с непустым `ThumbnailError` от сети, таймаута или повреждённой картинки повторно проверяется при следующем Request после минуты от `SavedAtUtc`. Автоматического таймера нет; свежую ошибку не повторяй при каждом обращении. Существующее правило отсутствующего FFmpeg отдельно разрешает обновление после его установки. Проверяй обе границы кеша: холодное чтение с диска и прогретый Request.

Явный приём материалов подписки должен вызывать RequestRowPreview для всех принятых пригодных незавершённых строк, включая уже существующие после неудачного полного metadata request. Не меняй принадлежность или состояние существующей строки и не создавай второй worker. Cold ingress-тесты URL/подписки должны подтвердить не только Title, но и реальную HTTP-картинку в кеше до Start и выбора строки основного окна; готовое превью показывается без нового процесса или HTTP-запроса.

После успешного ручного scan ставь в общий preview worker фоновую догрузку обложек материалов всех состояний, включая Baseline/Processed/AlreadyProcessed/Skipped. Для Full используй только подтверждённые `scan.Items`, для RecentWindow — накопленный snapshot источника после ApplyScan. Прежнее исключение исходного набора и обработанных материалов из такой предзагрузки больше не действует. Не начинай backfill после неполного/отменённого/пропущенного из-за паузы scan. Постановка выполняется в фоне и не задерживает scan/общий диалог приёма, не меняет состояний и не запускает скачивание. Актуальные готовые данные не требуют HTTP; сохраняй TTL 72 часа для пригодного/без кандидатов ответа и минутный cooldown пустой ошибки. Проверяй оба scope, все состояния, отсутствие повторной сети и отказ изображений без влияния на scan/очередь.

Ошибки превью должны давать полезную ограниченную диагностику: video URL, image URL и номер кандидата при наличии, этап, HTTP-статус и размеры при наличии ответа, тип/причину исключения и вложенной причины. Метаданные и запись кеша тоже сообщают точный URL и этап. Маскируй секреты до записи; не сохраняй cookies, HTML и произвольные ответы сайта. Ошибка диагностического обработчика не должна останавливать preview worker.

Метаданные preview читаются через `BoundedProcessOutput` по сырым байтам до накопления JSON: stdout не более 32 МиБ, stderr не более 2 МиБ, включая вывод без переноса строки. Превышение лимита, ошибка чтения или отмена останавливает собственный job; перед возвратом должны завершиться процесс и оба читателя pipe. Не заменяй это ограничением уже готовой строки или `ReadToEndAsync`.

Общий deadline запроса — 30 секунд, включая дочерний процесс,
заголовки и изображения. Для всей галереи дополнительно действуют общие 12 секунд,
2 МБ на изображение и 12 МБ на набор. Максимум 15 изображений из 60 кандидатов;
ранние кандидаты делят этот бюджет и получают отдельный срок min(4 секунды, срок галереи / 3). Таймаут раннего адреса разрешает следующий; последний или единственный адрес использует остаток общего срока. Отмена владельца и общего deadline прекращает перебор и join-ит работу.
совпадающие байты не дублируй. Таймаут метаданных завершает дочерний процесс и освобождает
единственного работника; ошибка изображения сохраняет текстовые метаданные.
Используй отдельный token для всего чтения тела при ResponseHeadersRead.

PreviewData сохраняет прежний positional ctor и `ThumbnailBase64` первой картинки; новый `ThumbnailsBase64` добавлен совместимо. Кеш версии 1 с PreviewFetchVersion<3 можно показывать сразу и дополнять без дублирования процесса. Полный `Get` с дисковой проверкой галереи не вызывай из UI; для него нужен быстрый memory-only `Peek`, а чтение/проверка диска выполняется работником. Прогрессивные callbacks не должны перезаписывать неизменившиеся названия и сериализовать checkpoint при каждой картинке. При неудачном обновлении пригодная прежняя обложка остаётся видимой. Автолистание работает только при наведении на видимую галерею; уход мыши, смена URL, скрытие и Dispose останавливают таймер. Проверяй реальные mouse enter/leave/wheel, сохранение выбранного кадра при прогрессивных обновлениях и отсутствие сети от листания.

Кеш строк в памяти ограничен 64 МиБ и 128 записями; дисковый кеш имеет мягкий предел 512 МиБ. Автоочистка касается только собственных SHA-256.json в preview-cache, не следует reparse points и выполняется вне UI. Ошибка кеша не блокирует метаданные.

Название из SubscriptionItem переносится в main queue до preview; при восстановлении очереди пустые/URL-placeholder названия дополняются одним bulk-чтением подписок по точным SubscriptionId+Url. Ошибка необязательного файла подписок не блокирует восстановление обычной очереди. Preview с пустым заголовком не стирает известное название. Не определяй пригодность миниатюры только по суффиксу URL; проверяй байты, ограничивай весь набор кандидатов одним бюджетом и используй существующий FFmpeg для WebP/AVIF. Конвертер читает только собственный локальный scratch, ограничивает память/выход и отменяется вместе с запросом. Старая точная ошибка фильтра JPEG/PNG не должна удерживать пустую обложку в кеше 72 часа.

До принятия обложки проверяй реальное декодирование кадра, а не только сигнатуру; некорректный кандидат не блокирует запасной. Исходный кадр ограничен 16 777 216 пикселями, декодируемый растр — 720 по большей стороне без увеличения. Проверяй изображения при чтении дискового кеша; проверенную память не декодируй повторно при каждой постановке URL. Кеш использует точное ordinal-сравнение URL, включая проверку identity памяти. Ошибка записи кеша не должна отбрасывать полученные данные из памяти и панели. Полный сбой метаданных сообщает URL и причину интерфейсу, завершает состояние загрузки, сохраняет известное название и не меняет превью другой ссылки. Сам перенос известного названия из подписки сразу обновляет заголовок текущего совпадающего превью без сети; отдельный RequestRowPreview при явном приёме строки использует обычные правила кеша и повтора.

Профили задают полный набор параметров: качество,
кодек, контейнер, AudioOnly, Archive, субтитры и встраивание данных. Только
«Архив 4K» включает Archive; остальные профили сбрасывают его. Пути, cookies,
скорость и число работников не меняются при выборе профиля.

### Очередь во время активной загрузки

Во время активной загрузки пользователь должен иметь возможность:

- выбирать строки;
- смотреть preview;
- open/copy URL.

Во время активной сессии **Remove разрешён**: пользователь может убрать URL из очереди, а для уже начатого/законченного задания — после подтверждения отменить конкретный native yt-dlp и удалить его собственные файлы. Другая очередь и процессы остаются активными.

Reorder / drag/drop / download selected остаются заблокированными, добавление через Paste, + Add или Watch clipboard по-прежнему разрешено.

- Для удаляемого URL координатор выставляет tombstone и отменяет его token; отмена проверяется до запуска, во время чтения stdout/stderr yt-dlp и перед публикацией результата.
- Каждый cancellable job пишет файлы в **отдельную staging-директорию**. Отменённый URL теряет только собственные частичные файлы; успешные результаты публикуются с `OwnedPaths`.
- Удаление готового медиа использует **точный путь из результата/чекпоинта**, без wildcard, с проверкой принадлежности каталогу вывода. Любой симлинк/junction/reparse point в пути к root, его родителях или вложенных каталогах означает отказ операции.
- Публикация из staging запрещена при существующем целевом файле (иначе чужой файл можно ошибочно принять за скачанный и удалить при Remove). Предварительно проверяется весь batch и ссылки в staging. Никакой overwrite чужих файлов.
- Нативные security-тесты проверяют реальные NTFS junction, обход `../`, соседние каталоги, preexisting и сохраняют контрольные файлы снаружи неизменными.
- Оговорка безопасности: проверки выполняются непосредственно перед файловой операцией; при намеренной параллельной подмене путей остаётся класс TOCTOU. Если нужна полная защита от враждебной подмены directory handles, необходима отдельно реализованная handle-based Windows FS layer.
- Результат отмены — `Cancelled`, это не `Failed` и не `Completed`; в постоянную историю успехов он не пишется.
- Пока работник не подтвердил завершение и попытку очистки, строка сохраняет `PendingRemoval`. `CleanupError`, `CleanupPaths`, `StageDir` и исходный `RunDir` сохраняются в checkpoint; при ошибке очистки Remove должен оставаться доступен для повторной попытки. Нельзя удалять runDir, пока там есть неочищенные задания.
- Старый checkpoint может содержать `Engine` с `CancelDir`, `OutputRoot`, `RunDir` и `EventsPath`. Не считай старый `Path` доказательством владения; живой старый engine блокирует восстановление и новые сессии. После его завершения считываются корректные финальные Result-события с прежними границами очистки.
- Каждый результат/строка хранит исходный `OutputRoot`: изменение поля Output не меняет границы удаления старых результатов. Повторное добавление удалённого URL при том же engine сохраняется для следующего Start и не отправляется повторно в ingress.
- Event для уже удалённого URL не должен снова добавлять строку в GUI.
- Любой недостаток прав при удалении — явное предупреждение, строка остаётся для повторной попытки.
- Визуальное подтверждение требуется перед удалением начатых или завершённых файлов.

- Перед передачей нового URL проверяется общая история успехов; Cancel не меняет очередь.
- Новые ссылки передаются в `DownloadCoordinator.Add` через канал заданий и dedup по точному URL. UI второго экземпляра доставляет аргументы существующему окну по named pipe.
- Добавление после завершения движка сохраняется как `Queued` до следующего Start.
- Статус `Running` для новой ссылки выставляется при фактическом начале работы задания.
- `Skipped` — отдельное незавершённое состояние, без истории/Processed. `SkipAsync` отзывает попытку по поколению, отменяет и join-ит только её child/pipes, сохраняет proof-bound staging и минимальный immutable `ResumeState`; работник берёт следующее задание. Явный `Resume` после join создаёт новую попытку, использует закреплённые параметры/OutputRoot и штатную дозагрузку yt-dlp. Не обещай дозагрузку источников без Range или диапазонов external FFmpeg; предупреждай о возможном новом скачивании. Публикация, успех и Skip согласованы: после победившей публикации Skip не превращает Completed в пропущенное.
- Обычный Start исключает `Skipped`; явные команды работают с выбранными видимыми строками, включая мультивыделение. Clear сначала захватывает только `Completed`, включая скрытые строки. Если их нет, применяется прежняя очистка всей очереди: смешанная очередь сохраняет пропущенные, полностью пропущенная очищает их собственный retained stage. После диалога/await повторяй eligible candidates и guards; режим подтверждённой операции не меняй и не захватывай поздние строки. В режиме готовых повторно проверяй `Completed`, без перехода к незавершённым при смене статуса. Готовые файлы и историю Clear не удаляет. `ResumeState` и маркер сохраняются при выходе, проверяются до продолжения, не содержат cookies contents/прямых media URLs. Редактирование формата retained-попытки требует сброса.
- «Сбросить и скачать заново…» требует подтверждения и обычной проверки истории до удаления. Сначала отмени и join-ь выбранные попытки/читателей, затем отзови preview generations и очисти собственные данные/кеш в фоне. URL/Order/подписку/пользовательскую Selection и append-only историю сохраняй; старый CompletedSelection и прогресс очищай. Restart разрешён только прежней joined-попытке той же строки после успешной очистки, не снимает tombstone для обычного Remove/re-add. Закрытие ждёт операцию, local-poster admission/повторные callbacks не обходят barrier. Не запускай строку с ошибкой очистки или read-only checkpoint; отложенные metadata callbacks не должны восстанавливать сброшенный кеш.
- Новые URL сохраняются в session checkpoint, а история успешных скачиваний продолжает пополняться из engine.

### Кодек — предпочтение

Для H264/VP9/AV1 format selector сначала пытается codec-specific вариант, затем generic fallback в рамках выбранного ограничения quality.

Это контракт автоматического выбора. Не документируй и не реализуй его как строгий codec lock; отдельный ручной выбор реальных ID ниже не использует этот fallback.

### Формат и фрагмент отдельного URL

- `DownloadItem.Selection` — параметры следующей попытки, `CompletedSelection` — неизменяемый снимок опубликованного результата. Координатор фиксирует выбор при Start; правка Completed не обнуляет статус, пути, владение или историю и не запускает обычный Start повторно. Для новой попытки нужен явный Retry. Старые checkpoint без полей означают полный материал и автоматический формат.
- `DownloadSelection` привязан к точному URL. UI «Формат и фрагмент…» редактирует одну захваченную строку независимо от дальнейшего выбора основной очереди. Строки текущей сессии, Running/Starting, PendingRemoval/ошибка очистки и read-only checkpoint не редактируются; обработчики повторно проверяют запрет даже при прямом событии кнопки.
- Реальный каталог `MediaFormat` получается из существующего metadata request `PreviewService`, до 1024 последних пригодных уникальных ID `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`. Проходи весь ограниченный по байтам JSON; при усечении сохраняй `FormatsTruncated` и сообщай о скрытой ранней части в UI, не выдавая показанное число за полный набор. Каталог учитывается в общем бюджете кеша 64 МиБ. Не сохраняй прямые media URL. Размер только `filesize`/`filesize_approx`, неизвестное не превращается в ноль; сохраняй разрешение/FPS/кодеки/язык/HDR и признак оценки. Исключай DRM и непригодные форматы; не используй first-entry ID коллекции для всей задачи.
- `RequestFormats` дополняет прежний кеш версии получения 3 без каталога через того же единственного работника, без дополнительного процесса и сброса обычного TTL обложек. UI показывает реальные сведения; отсутствующий сохранённый ID не заменяется автоматически.
- Ручные ID передаются строго без quality/codec fallback. Video-only требует отдельного audio-only; muxed не принимает второе аудио. `AudioTrack` должен быть `Default`, MP3-only требует audio-only основной поток. Несовместимые с MP4/WebM кодеки отклоняются явно; Auto/MKV допускают эти потоки. Временные повторы сохраняют выбранные ID и диапазон.
- `DownloadSection` принимает секунды, `М:СС` или `ЧЧ:ММ:СС` с точкой и максимум тремя дробными цифрами; оба пустых поля означают полный материал. Проверяй конечные значения, `start >= 0`, `end > start`, `end <= duration` при известной длительности. Коллекция не принимает диапазон или ручной формат. Используй `--download-sections` и `--force-keyframes-at-cuts` через FFmpeg.
- Фрагмент проходит ту же проверку публикации и получает Completed/OwnedPaths, но не пополняет историю полного URL и не помечает материал подписки Processed. Portable queue по-прежнему переносит только URL/title, без `Selection`/`CompletedSelection`.
- Для одного или нескольких отдельных диапазонов `SubtitleTimelineService` пересекает WebVTT/SRT/ASS/SSA cues с диапазоном и вычитает начало до embedding/publication; sidecar нормализуется в VTT. Каждый output связывается со своим диапазоном bounded-маркером без source URL, общий исходный sidecar не публикуется. Пустой язык оставляет пустой VTT без встроенной дорожки; неподдерживаемый формат явно завершает попытку ошибкой. FFmpeg читает только owned local staging с фиксированным demuxer и `file`, MOV external refs выключены. Проверяй фактически извлечённые cues/языки/кодеки и медиадорожки до публикации; сохраняй pause/cancel/join, no-history-on-failure и точное владение. Удаление SponsorBlock вместе с partial subtitles запрещается до admission, full download не меняется. Реальный HLS и форматы/overlap/failure/cancel проверяет `SubtitleTimelineTests`.
- `DownloadSelection.Sections` — необязательный immutable `DownloadSectionSet`, максимум 32 непересекающихся диапазона; соседние разрешены, порядок сохраняется. `EffectiveSections` читает список либо прежний одиночный `Section`; `IsPartial` и `DownloadItem.IsPartialResult` не допускают записи полного URL в историю. Если сохранены оба поля, первый диапазон совпадает с `Section`. Пустой сериализованный список не означает полное видео и отклоняется.
- Несколько диапазонов одного URL остаются одной задачей. У yt-dlp числовые ranges не имеют `section_number`: передавай повторные `--download-sections` и различай имена по миллисекундным границам. Собирай все `after_move` маркеры; до общей публикации требуй полное число разных собственных непустых файлов и верный контейнер каждого. После первого готового файла ошибка неполного batch запрещает автоматический transfer retry/quality fallback. Проверяй настоящий multi-output FFmpeg и WPF в `MultipleFragmentTests`/`MultipleFragmentUiTests`, включая отмену, старый checkpoint и защиту Completed.
- `FragmentOutputMode` по умолчанию `Separate`, необязательный `Merged` требует минимум два диапазона. `AllowMergeReencode` — только явное согласие в локальном черновике UI и фиксированном плане. До Start объясняй, что фактическая совместимость неизвестна до получения файлов. Проверяй FFprobe реальные параметры/time base/extradata; stream copy не меняет кодеки, несовместимость без согласия завершается ошибкой. Fallback сохраняет все языки/дорожки, отказывается при разных раскладках, HDR/высокой глубине/альфа-канале; не обрезай неизвестный формат до yuv420p молча. Субтитры пока отклоняются до запуска.
- Склейка принимает только регулярные owned-входы, фиксированные demuxer и `file` protocol, безопасный ffconcat без управляющих символов и внешних MOV refs. ManagedChildProcess + ограниченные pipes + активные сроки участвуют в pause/cancel/join. Проверяй один результат по контейнеру/дорожкам/длительности, публикуй только отдельный подкаталог результата; всё остальное очищается владельцем внешнего staging. TEMP резервирует 2 копии либо 3 при разрешённой нормализации. Частичная склейка никогда не пополняет полную историю/Processed; Completed и прежние файлы сохраняются при edit/Retry. Обязательны actual-media `FragmentMergeTests` и настоящий WPF `FragmentMergeUiTests`; детали — [архитектура](../developer/architecture.md#склейка-выбранных-диапазонов).
- Проверяй `DownloadSelectionTests` настоящим упакованным yt-dlp и FFmpeg на локальном медиа, а `MediaSelectionUiTests` — реальным WPF-окном, холодным metadata worker, сохранением/восстановлением и защитой Completed. Не подменяй это поиском флагов в строках.
- `FragmentTimeline` редактирует только существующие поля выбранного диапазона: настоящие Drag/Key-события синхронизируют ручки, время и длительность, но не применяют `Selection` и не меняют Completed/OwnedPaths. Известный FPS берётся у точного выбранного видеоформата либо единственного общего FPS всех видеоформатов; для остальных случаев явно показывай шаг 0.1 с. Дробный FPS привязывай к индексу кадра без накопления округления, длительность округляй вниз до допустимой миллисекунды. При неизвестной длительности выключай шкалу, сохраняя пошаговое редактирование валидных полей. Read-only/коллекция/закрытие проверяются повторно в обработчиках. `FragmentTimelineTests` и реальные `FragmentTimelineUiTests` проверяют расчёты, жесты, клавиатуру, кадровый запрос, восстановление и сохранность прежнего результата.
- Метка, совпадающая с округлением точки известной FPS-сетки до миллисекунд, включая ручной ввод, означает эту номинальную точку; другие миллисекунды сохраняются. Общие `Boundary`/`SectionBounds` используются в export, сопоставлении progress и коротком playback/waveform request. Конкретный формат фиксирует `Format.Fps`, auto с единственным общим FPS — additive конечный `FrameRate` (до 1000); legacy auto без поля не получает выдуманный FPS. Не округляй export снова до трёх цифр и не обещай точные PTS для VFR/иного auto-потока. `FragmentFrameConsistencyTests` декодирует barcode IDs реальных источников/экспортов/PNG/коротких клипов при пяти FPS; настоящий `FragmentFrameConsistencyUiTests` проходит +кадр → Apply → checkpoint → coordinator → decoded export.

#### Кадры границ фрагмента

- `MediaSelectionDialog.Frames` показывает «Кадр начала» и «Кадр перед концом» для точного захваченного URL. Каждая карточка независимо откладывает запрос на 350 мс, отменяет предыдущий и очищает изображение; token и поколение отбрасывают поздние ответы после нового ввода/смены формата/закрытия/запрета редактирования.
- Пустой, неразбираемый или выходящий за известную длительность ввод очищает соответствующую карточку без source request. Коллекция и выбранный формат без видео объясняют отсутствие кадра. Сравнение `end > start` проверяется при «Применить», независимо от пригодности каждого времени для просмотра кадра.
- Для конечной границы выбирай кадр перед ней, в том числе при `end == duration`; отображай фактическое время как «Кадр около…». Ошибка кадра не блокирует применение пригодного выбора. «Обновить кадры» повторяет предпросмотр, не запускает очередь и не меняет историю/владение файлами.
- `PreviewController.GetFrameAsync` делегирует одному работнику `MediaFrameService`; разрешение источника использует того же единственного metadata-работника `PreviewService`. Signed media URL, заголовки и временные cookies остаются только в памяти и не попадают в `PreviewData`, checkpoint, portable queue или журнал/argv FFmpeg. Кеш источников живёт две минуты, проверяет контекст файла cookies, ограничен четырьмя URL и 128 источниками на URL. Отмена кадра отменяет его ожидание, не останавливая общий metadata-запрос.
- FFmpeg получает случайный loopback URL через `BoundedMediaProxy`, а не исходный подписанный адрес. Разрешены прямые HTTP(S) MP4/MOV/M4V/WebM/MKV, завершённый HLS и статический DASH; коллекции, аудио, DRM, live и неподдержанные схемы дают честное отсутствие кадра. Ручной video-ID не подменяется другим источником; автоматический режим может выбрать меньший поток для предпросмотра.
- HLS/DASH разбирает `ManifestFrameMedia`, а не FFmpeg. Поддерживай master/media HLS, TS/fMP4/init/byte ranges, AES-128 для TS, а также DASH SegmentTemplate/Timeline/List/Base и MP4/WebM. Выбирай ограниченное окно сегментов, собирай только двоичное медиа и передавай его локальному реле с фиксированным demuxer; не разрешай декодеру читать исходный manifest или произвольный вложенный URL. XML DTD/не-HTTP URI/HTTPS downgrade/DRM/live отклоняются, manifest не более 1 МиБ, до 10 000 явных сегментов и 64 HTTP-обращений; манифест, ключи и сегменты делят 16 МиБ и общий deadline. Извлечённые URLs, ключи и headers не сохраняются на диск. Зашифрованный HLS fMP4 пока объясняет отсутствие кадра.
- Сохраняй общий deadline 30 секунд с ожиданием работника/метаданных, 16 МиБ передачи медиа на кадр, PNG stdout 1 МиБ, stderr 128 КиБ и кадр не более 640 × 360 без увеличения. Источник ограничен 16 777 216 пикселями. Восстанавливай `Boundary` только по явно переданному `MediaFrameRequest.FrameRate`: собственный FPS preview-потока не даёт такого разрешения при mixed-FPS auto или legacy caller. `FrameSample` сам не вызывает `Boundary` и по FPS потока вокруг уже определённой границы выбирает первый номинальный PTS на границе/после начала либо последний строго перед концом, с ограничением длительности; при неизвестном FPS для конца отступи на 50 мс, с нижней границей 0. Процесс FFmpeg принадлежит отдельному `ManagedChildProcess`; отмена завершает и дожидается процесса, pipe readers и HTTP-обработчиков.
- HTTP-реле принимает один Range, ограничивает запрос/число обращений/клиентов и редиректы; игнорирование ненулевого Range не должно скачивать материал последовательно. Cookies ограничены доменом/путём/Secure, приватные заголовки не переходят на другой origin, HTTPS не понижается до HTTP. Не сохраняй полную cookie jar или секретные HTTP-ответы ради диагностики кадра.
- Проверяй реальные WPF-карточки и пиксели в `MediaSectionFrameUiTests`, а передачу диапазонов, области cookies/заголовков, лимиты и joined cancellation — реальным loopback HTTP в `MediaFrameProxyTests`. Управляемые PNG UI-теста не подтверждают фактический поиск FFmpeg: `MediaFrameServiceTests` проверяет его на настоящем видео с разными цветами, конечную границу, приватность/смену контекста источника, отказ манифеста и отмену/таймаут с последующим успешным кадром.
- `MediaManifestFrameTests` должен подтвердить HLS/DASH реальным yt-dlp и FFmpeg, init и byte ranges, MP4/WebM/TS, auth scope, конечную границу, отмену и невозможность обхода лимита через вложенный playlist/XXE.
- Короткое воспроизведение редактора использует `MediaClipService` и настоящий `MediaElement` через `WpfMediaClipPlayer`. До 15 секунд с начала/конца диапазона, подпись точных фактических границ; Apply не ждёт плеер. Смена времени/формата, read-only и закрытие отменяют подготовку, проверяют поколение и освобождают Source до Dispose owned clip. Очередь, история, выбор строки и опубликованные файлы не меняются.
- Видео/отдельное аудио получают одним снимком существующего metadata-работника (`PreviewService.ClipSources`); явные ID и первый выбранный язык/Original не подменяются. Вытесненный ID требует повторного извлечения, известный отказ — отрицательного кеша. Поздние waiters не завершаются снимком без удержанных для них форматов. Секретные URLs/cookies/headers остаются в памяти; FFmpeg/FFprobe получают только bounded loopback.
- Клип: H.264/AAC, до 640 × 360, 15 секунд, 16 МиБ на файл, до четырёх lease/64 МиБ кеша, 64 МиБ суммарного входа (по 32 при двух входах), 60 секунд включая очередь/метаданные. Сохраняй фиксированные demuxer для скомпилированных HLS/DASH, ограничения headers/cookies/redirects и joined cancellation. Неизвестные codec flags проверяет bounded FFprobe вместо обязательного несуществующего audio-map или потери реального звука.
- `MediaClipCache` использует CreateNew, GUID-пару MP4/owner (без URL/секретов), PID+start time и no-reparse проверки. Неудачно удалённый lease продолжает занимать место, очистка ограничена и повторяется при новом запросе; мёртвый владелец допускает удаление только распознанной пары. Чужие файлы сохраняются. `MediaClipServiceTests` проверяет настоящие AV и decoded PCM RMS; `MediaClipPlaybackUiTests` — MediaElement/контролы/события/lifetime, без заявления о физических динамиках CI.
- `MediaSelectionDialog.Waveform` запрашивает звук только явными кнопками начала/конца. `AudioWaveformView` рисует измеренные peak/RMS bins на исходной оси времени; click/Thumb/клавиатура меняют только соответствующее поле черновика, не Selection до Apply. Собственный drag сохраняет окно и mouse capture, остальные изменения времени/формата/языка/cookies/строки диапазонов, Stop, read-only и закрытие отзывают поколения. Сравнивай смысловой контекст, не SavedAtUtc: приватное обновление источников не должно отменять свой запрос; исчезновение выбранного ID из каталога должно.
- `MediaWaveformService` использует тот же `MediaClipService`, единственный metadata-работник, приватный контекст и общий лимит четырёх lease/64 МиБ. Окно до 15 секунд около границы ограничено известной длительностью; при неизвестной конец получает предшествующие секунды, начало не выходит за выбранный конец. Отдельный owned clip волны не разделяет Source с плеером; retention того же lease удерживает файл при Dispose владельца до joined decoder/pipes. Не создавай независимый кеш или полную загрузку видео.
- Waveform decoder читает только owned локальный MP4, фиксированные file/mov без внешних ссылок; PCM S16LE 48 кГц stereo до 2 880 004 байт, максимум 320 bins, stderr 128 КиБ, decode 10 секунд и общий deadline 60 секунд. Peak и RMS учитывают оба канала без mono-подавления противофазного звука; короткую дорожку не растягивай, показывай фактический конец на прежней оси. Отсутствующий звук/тишина/ошибка различаются, случайные или картинные волны запрещены. Не сохраняй PCM/private URL и не меняй queue/history. Реальный PCM/лимиты/retention проверяет `MediaWaveformServiceTests`, WPF render/gestures/поколения — `MediaWaveformUiTests` на Windows.
- Общий `MediaClipService` сохраняет origin окна для видео и аудио. Не сбрасывай поздний audio STARTPTS отдельно: вычитай seek окна и заполняй начальный timestamp gap тишиной; иначе речь сдвинется на шкале и в проигрывателе. Реальные muxed/separate аудио с задержкой и нулевой/ненулевой seek должны сохранять паузу в `MediaWaveformServiceTests`; хвост короткой дорожки не растягивается.


### Повторы только временных ошибок

Классификация находится в `src/VideoDownloader/Downloads/YtDlpOutputParser.cs`; решение о повторе выполняет `DownloadCoordinator`.

Не retry permanent/auth/unavailable ошибки бессмысленно. По умолчанию внешний backoff:

~~~text
5s, 10s, 20s
~~~

Максимальная задержка — 60 секунд.

## Подписки: текущий контракт

Расписание принадлежит `NativeWindow`, не окну подписок: закрытие списка не отменяет автоматический scan. Ручная и автоматическая проверки используют общий guard; новый источник без Initialized сначала проверяется вручную с явным выбором baseline. Автоматическая проверка использует тот же ограниченный scanner/ApplyScan Full/RecentWindow и mutex, повторно проверяет точные Id/URL/FeedUrl и параметры расписания под mutex перед записью. После сна пропуски объединяются в один проход, источники идут последовательно, между автоматическими проверками одного host минимум минута; ошибки увеличивают интервал до недели, пауза host — до часа. Дедлайны и backoff не экспортируются.

Автоматическое обнаружение сохраняет URL/названия и входящие, не вызывает архивную предзагрузку изображений, модальное предложение очереди, enqueue или Start. Уведомление трея выдаётся только на новые точные URL со State New; прежние непринятые New не уведомляются повторно, сообщения объединяются и ограничены одним в минуту. В просмотре работают обычные превью. `SuspendSubscriptionSchedulingAsync` блокирует новые действия, отменяет и дожидается автоматического работника; активная ручная проверка запрещает обслуживание. Восстановление профиля держит lease до повторной проверки состояния и записи, импортированное ScheduleEnabled всегда false. Обновление компонентов использует тот же lease, установка приложения требует отсутствия работы/lease, выход отменяет и дожидается работников.

- Ручная проверка сохраняется. `SubscriptionSchedulePlanner` и `SubscriptionController.Schedule` обеспечивают только явно включённый интервал при открытом приложении/в трее. По умолчанию выключено, интервал 30 минут (5–10080); первая проверка после запуска, включения, возобновления или обслуживания ждёт полный интервал. Не добавляй проверку при запуске, автоскачивание или Планировщик Windows без отдельной задачи; направления развития перечислены в [плане проекта](../project/ROADMAP.md).
- Исходная разметка окна — `src/VideoDownloader/UI/Views/SubscriptionsWindow.xaml`; в ZIP сохраняется путь `ui/SubscriptionsWindow.xaml`. Данные — `subscriptions.json` версии 1 в фактическом каталоге пользовательских данных. Логика — `SubscriptionStore` и `SubscriptionScanner`. Не смешивай файл подписок с `session.json` или постоянной историей.
- Порядок материалов подписки хранится существующим списком `SubscriptionSnapshot.Items`, без новой версии JSON. После успешного Full ставь текущие материалы в порядке `scan.Items`, отсутствующие исторические записи сохраняй в конце; RecentWindow ставит проверенное окно перед прежним хвостом. Сохраняй точные URL, состояния и порядок других подписок. Не сортируй «Входящие и результаты» по состоянию или DiscoveredAt и не включай пользовательскую сортировку колонок. Для старого накопленного снимка достаточно одной полной проверки, удаление данных не требуется. Проверяй перестановку, RecentWindow, исторический хвост, старый формат, отказ/отмену и сохранение состояний.
- Поле «URL подписки» выбранного источника должно оставаться read-only, но выделяемым для Ctrl+C; «Копировать URL» копирует исходный точный URL и доступно во время проверки. Смена выделения не должна оставлять адрес прежней подписки.
- Поддерживается любая HTTP(S)-коллекция, полностью перечисляемая текущим yt-dlp. Не вводи whitelist только YouTube. RSS/Atom — необязательное дополнение, с автоматическим определением YouTube-ленты по метаданным и ручным адресом ленты. Первая проверка всегда требует полного перечисления через yt-dlp; последующие Windows-проверки могут использовать проверенное окно по правилам ниже. Неизменившаяся RSS не заменяет проверку коллекции; ошибка ленты означает предупреждение, а не отказ от пригодного результата yt-dlp. RSS обогащает только точные URL из текущего результата обнаружения. Не добавляй feed-only элементы во входящие.
- В Windows обычная повторная ручная и автоматическая проверка использует окно до 20 новых публикаций только при Initialized и непустом снимке известных URL: для явных вкладок YouTube `/videos`, `/shorts`, `/streams` без query/fragment либо Pornhub с подтверждённой секцией самых новых публикаций. Корни YouTube-каналов, произвольные плейлисты и прочие источники проверяй полностью. Флажок «Полная проверка» принудительно отключает окно для текущего batch; начальный scan всегда полный.
- Результат окна имеет явный `SubscriptionScanScope.RecentWindow`, не служит доказательством полного архива и не устанавливает baseline. Принимай его только после проверки ответа и пересечения точных URL с накопленными материалами; без пересечения, при неизвестном порядке или непригодном ответе переходи к полному scan в том же deadline. Окно дополняет прежний снимок; старые материалы и состояния сохраняются. Для пересечения учитывай Baseline/New/Queued/Skipped/Processed/AlreadyProcessed, не только успешно скачанные URL. RSS дополняет только подтверждённые текущим результатом URL. LastSuccessUtc означает успешную проверку любого поддержанного scope. Probe ограничен 30 секундами YouTube / 45 секундами Pornhub внутри общего deadline, чтобы таймаут окна оставлял бюджет полному fallback; пользовательская отмена fallback не запускает.
- Размер окна 20 не является лимитом новинок. Отдельный fixture-сценарий 100 известных (в том числе Processed/Skipped) + 100 новых должен выполнить recent-запрос без якоря, затем полный обход, вернуть все 200 материалов и сохранить все 100 новых с прежними решениями старого набора. Дальнейшая явная постановка всех 100 в очередь не запускает дополнительное перечисление и скачивание.
- Обычный полный scan ограничен 10 000 элементами, 180 секундами и 32 МиБ stdout метаданных. Сборщик публикаций Pornhub имеет отдельный бюджет: 10 000 роликов, 500 страниц, 15 минут и те же 32 МиБ. RSS/Atom ограничена 2 МиБ и 12 секундами. Обрезанный список, превышенный предел, null/неидентифицируемый элемент, некорректный URL или ошибка перечисления запрещают считать scan полным. Не меняй baseline, items и LastSuccessUtc при таком сбое.
- Для полного перечисления используй отдельный отменяемый процесс yt-dlp с игнорированием внешней конфигурации и `--no-flat-playlist`: вложенные коллекции должны раскрываться до материалов. Нераскрытые `url`/`url_transparent` не являются материалами и запрещают успешный scan. Не используй PreviewService с выбором первого элемента плейлиста. Читай stdout/stderr параллельно, проверяй пределы и завершай только дерево процесса текущей проверки при отмене.
- Явное исключение: Pornhub `/channels|model|pornstar|users/<slug>` перечисляет упакованный `collection-plugins/videodownloader/yt_dlp_plugins/extractor/vd_pornhub.py` через `--no-plugin-dirs --plugin-dirs … --use-extractors videodownloader:pornhub:channel --flat-playlist`. Он обходит только публикации (`/videos` каналов, `/videos/upload` профилей), исключает историю/рекомендации, проверяет пагинацию и повторно первую страницу. Адаптер C# различает полный `vd_ph_scan` версии 1 и явный `vd_ph_recent` с `complete=false`, `scope=recent`, подтверждённым порядком и повтором первой страницы; проверяет согласованность страниц и уникальные watch URL. Последний принимается только как окно, произвольный flat JSON по-прежнему запрещён. Режим `recent_window=20` передаётся сборщику явно; без него сохраняется полный обход, в том числе для Android. Недоступное видео с известным URL становится самостоятельной задачей обычного движка. Канал не является успешным media-результатом. Не помещай плагин в автоматически загружаемый каталог `yt-dlp-plugins`; отдельный Python нужен только тестам разработчика, приложение загружает плагин внутри yt-dlp.exe.
- Локальная идентичность материала — `SubscriptionId` + точный URL (ordinal). Не группируй по media ID и не нормализуй произвольно параметры URL. Между подписками совпадение определяется тем же точным URL.
- Адаптеры обнаружения формируют адреса только новых материалов коллекции: Pornhub — `https://www.<base-site>/view_video.php?viewkey=<id>`; быстрое окно YouTube после строгой проверки YoutubeTab/source, 11-символьного ID и соответствующего ему watch/shorts/live URL — `https://www.youtube.com/watch?v=<id>`, как при полном YoutubeIE. Не переписывай прежние URL подписок, очереди или истории и не объединяй их по media ID: общая exact URL identity сохраняется.
- При проверке редиректов Pornhub `/videos/upload` и `/videos` одного kind/slug — допустимые адреса публикаций. Следующие страницы и повтор первой запрашивай по подтверждённому конечному endpoint, но `vd_ph_scan.listing_url` сохраняет исходный ожидаемый адрес для адаптеров. Не принимай главную страницу профиля как полный архив и не ослабляй проверки сайта, профиля, вкладки или номера страницы. Диагностика отклонённого перехода должна показывать URL назначения без credentials и произвольной query.
- Для вариантов разметки Pornhub допускаются также `claimedUploadedVideoSection`, `channelVideosList`, `showAllChanelVideos`, `ul#moreData.videos`, `div/section.videoUList` и карточки `videoblock`. Не принимай произвольный `moreData.feedItems`, все watch-ссылки документа или несколько независимых списков одной обёртки за полный архив. Карточки меню, боковых панелей и footer исключаются; история и рекомендации исключаются вместе со своей пагинацией. Основная пагинация может находиться в `nav`/`footer`: не теряй объявленные страницы из-за тега контейнера. Ошибка неизвестной страницы сообщает только адрес, структурные имена секций и счётчик карточек, без HTML, viewkey, произвольных query или cookies; распознанная страница проверки возраста объясняет использование Cookies.
- Если есть `section#videosTab`, ищи публикации только внутри неё: неизвестная разметка основной вкладки не разрешает fallback к распознанной сетке снаружи. Разбирай карточки, счётчики, пустое состояние и пагинацию по секциям; не смешивай их глобально. При наличии этой вкладки не принимай внешнюю ownerless-пагинацию/`rel=next`/`moreDataBtn` за её навигацию; основные `nav`/`footer` внутри вкладки по-прежнему обходятся. Вложенные обёртки не являются отдельными списками; одинаковые копии сверяй по полному набору ключей и счётчикам. Игнорируй пустые placeholders только без карточек, watch-ссылок, счётчика, empty-state marker, ошибок карточек и своей пагинации. Не выбирай между разными самостоятельными списками по порядку, размеру или специфичности селектора; ошибка сообщает ограниченный список структурных имён и размеров без viewkey. Идентичность выбранной секции проверяется на следующих страницах и повторе первой.
- Новое начальное действие выбирается в dropdown из трёх вариантов: Queue / Skip (по умолчанию) / ManualDone. `InitialAction` — nullable опциональное поле v1; отсутствие сохраняет прежнюю семантику `DownloadExisting` и Baseline/New pending без переинтерпретации старых источников. Выбор сохраняется до первой успешной полной проверки, неудача/отмена его не меняет. Skip создаёт `Skipped`, ManualDone — `Skipped` с опциональным `ManuallyCompleted=true`, UI «Готово» и пояснением ручной отметки без файла/истории успеха. Флаг допустим только на Skipped, не является доказательством успеха и не создаёт уведомления другой подписке. Повторный scan сохраняет решение; последующие новые URL всегда New. Показывай старые Baseline как «Исходный снимок» с возможностью ручного добавления. Явно принятые в очередь материалы теряют ручную отметку только после durable acknowledgement; настоящий успех также снимает её.
- Queue буквально включает все материалы исходной проверки, включая подтверждённые Processed/AlreadyProcessed. `InitialQueuePending` для этих двух состояний допустим только у источника с `InitialAction=Queue`; reconciliation сохраняет явное намерение до фактического приёма. Используй selected callback с обычным подтверждением повторов истории; Cancel сохраняет pending для следующей ручной проверки. `AcknowledgeQueued` очищает intent только принятых точных URL, сохраняет реальные Processed/AlreadyProcessed и их provenance, остальные переводит в Queued. Legacy `DownloadExisting` без InitialAction сохраняет старое исключение известных успехов. Ни одно начальное действие не вызывает Start/live ingress.
- Элементы подписки имеют состояния Baseline/New/Queued/Processed/AlreadyProcessed/Skipped. Реальный успешный результат движка или общая история успехов подтверждают обработку; обнаружение, добавление в очередь, baseline и Skip не являются успехом. Уведомление об уже обработанном URL из другой подписки показывай и подтверждай один раз, сохраняя DuplicateSubscriptionId/DuplicateNotified. Успех только из глобальной истории без известной другой подписки означает Processed без cross-subscription notice. SuccessAttributed сохраняет различие после перезапуска: true только для Processed с подтверждённым успехом ранее поставленного в очередь материала подписки; глобальный успех без такого источника оставляет false и не становится источником уведомления при будущих проверках.
- Добавление из подписок возвращает реально добавленные URL и отправляет их только в обычную очередь следующего Start. Не вызывай live Add/ingress во время текущей сессии. Не помечай не добавленные или отклонённые ссылки как Queued.
- Явное выделение допускает все шесть статусов материала. При разных статусах предлагай «Только новые / Всё выделенное / Отмена», включая смешанный набор без New (первый вариант выключен). Захватывай точные SubscriptionId+URL до await/диалога; NewOnly требует показанного ранее и всё ещё New, AllSelected не захватывает поздние строки. Перечитывай историю/снимок и проверяй окно после await. Исторические Processed/AlreadyProcessed и provenance сохраняются при подтверждении очереди; для ручного выбранного набора используй отдельный callback, автоматический offer New не меняй. Существующие Completed/Skipped основной очереди получают RequeueRequested без удаления/обнуления старых данных; уже активный URL не дублируется.
- После завершения всей ручной проверки предлагай один общий приём `New` успешно проверенных источников, включая ранее найденные и пока не принятые новинки. При «Проверить все» не показывай вопрос после каждой коллекции. Отказ и закрытие вопроса сохраняют `New`; отменённая проверка или закрытое окно не показывают предложение, источники с ошибкой исключаются. `Baseline`, `Skipped` (включая ManualDone), `Processed` и `AlreadyProcessed` в общий приём не входят; строки с `InitialQueuePending` обрабатывай отдельно сохранённым начальным выбором. После согласия перечитай снимок и историю, заново отфильтруй предложенные материалы по точным SubscriptionId+URL и используй обычное durable-подтверждение очереди. Модальный цикл не разрешает второй запуск проверки/приёма; `Queued` получают только действительно принятые ссылки. Само согласие не запускает Start. Проверяй один диалог на batch, Yes/No/Close, отказ и отмену, частично успешный batch, позднее изменение состояния и ошибку/частичный отказ очереди. Mixed selection различает вычисляемый `StateKey`, чтобы ручное «Готово» и «Пропущено» не сливались из-за общего raw Skipped.
- Подписка имеет редактируемый ShortName. Пустое имя заполняй только при полном успешном scan из SuggestedName (канал/автор), иначе Title; после назначения не меняй его автоматически. Версию 1 без единственного нового поля ShortName читай с пустым значением, сохраняя строгую проверку остальных полей. Нормализация сохраняет прежние правила: один компонент Windows-пути, замена запрещённых символов/control, схлопывание пробелов, обрезка крайних точек/пробелов, предел 80 UTF-16 без разрыва surrogate pair, префикс для device names.
- Новые задания подписки сохраняют SubscriptionId и снимок SubscriptionName в session.json. Имя закрепляется при enqueue, базовый каталог — при Start: D:\Video\123, с Archive — D:\Video\yyyy-MM-dd\123. Переименование влияет только на будущие добавления; уже существующий URL очереди не переназначай. Старые checkpoint без полей означают обычное задание. Фиксируй фактический OutputRoot каждого задания для публикации/отмены/очистки; не подменяй его общим root сессии после успеха.
- Храни записи атомарно под общим mutex `Local\VideoDownloader.Subscriptions`; Read возвращает отделённый snapshot. Строго проверяй формат версии 1. При повреждённом JSON не перезаписывай и не пересоздавай файл. Удаление подписки не удаляет media, очередь и историю.
- Проверяй три начальных действия, безопасный default, ручную готовность без ложного успеха и её tooltip/mixed selection/requeue, Queue-all с отменой истории и частичным acknowledgement исторических состояний, retry после неудачной первой проверки с изменённой формой, старый baseline/очередь и его видимость, окно 20 среди 100 известных, новинки с пересечением и без него, forced-full, сохранение состояний/прежнего снимка при отказе, повторное обнаружение, полноту и пределы scan, отказ/отмену, RSS fallback, exact URL, уведомление после реального успеха и однократное подтверждение, сохранность повреждённого JSON, очередь без live-add. Для совместимости используй фиксированные `tests/fixtures/legacy/`, без запуска второй реализации.

Прогресс проверки подписок показывается через XAML-карточку: текущий источник, этап, время, завершённые источники/всего, анимация активного обхода. Общая шкала считает реальные завершённые проверки, включая ошибки; отмена оставляет частичный результат. Не выдавай байты, время или неизвестное число материалов за процент готовности коллекции. Scanner сообщает необязательные этапы RecentWindow/FullFallback/Enumerating/Parsing/Feed/Ready, подтверждённое число материалов после разбора и фактические байты не чаще 4 раз/с. Ready означает готовность результата обхода, успех отображается только после применения пригодного результата с явным scope. Ошибка обработчика прогресса не должна менять итог/вывод сканера. Публикуй данные в Dispatcher; работник не обращается к WPF. Отложенные события не откатывают этап сохранения/очереди и игнорируются после смены источника, отмены, закрытия или нового запуска. Терминальный итог остаётся видимым; анимация и часы останавливаются.

## Сохранение и восстановление сессии

- `AppPersistence.AtomicWrite` повторяет только `File.Move` одного закрытого temp на Windows для кодов 5/32/33: задержки 15/30/60/120 мс. Не снимай ReadOnly/ACL и не удаляй старое назначение ради обхода отказа. Постоянная ошибка сохраняет старый файл и исходный тип/HResult. Проверяй настоящий временный/постоянный sharing lock и ReadOnly в `AtomicWriteTests`; polling-readers тестов используют `FileShare.ReadWrite | FileShare.Delete`. Ошибка сохранения должна оставлять в журнале тип/HResult/стек, сохраняя защиту read-only checkpoint.

- Очередь, конечные статусы и параметры сохраняются атомарно в `%LOCALAPPDATA%\\VideoDownloader\\session.json`, не в `%TEMP%`.
- Обычный ingress проверяет будущий полный checkpoint до изменения очереди, preview и live admission: пределы `AppPersistence.MaxCheckpointBytes` / `MaxQueueItems` относятся к фактическим UTF-8 JSON-байтам и числу строк. Один пакет URL/TXT/clipboard проходит один batch-preflight с текущими `ReadOptions`, окончательными Order/deferred и pinned OutputRoot live Add; отказ не меняет прежние строки, историю, checkpoint или read-only flag. После модального диалога повторяй exact URL dedup и проверку владельца сессии. Single Add также проходит guard; не сериализуй полную очередь отдельно для каждого URL пакета.
- Уже проверенные `AppPersistence.Restore` строки принимай отдельно от ingress preflight: legacy Result, default-поля и восстановленный OutputRoot могут расширить допустимый старый файл сверх writer-бюджета. Не теряй строки/ownership/cleanup. До предупреждения включай capacity recovery/read-only с защитой исходного checkpoint и блокировкой Add/Start/автообогащения. Экспорт и явные Remove/Clear с прежним owned-proof/подтверждениями доступны только для этого recovery mode; после сокращения выходи из него лишь по успешному Save. Не ослабляй read-only при повреждении, I/O или живом legacy engine. Проверяй реальный WPF со старой near-cap очередью и fixed legacy Result cleanup.
- Обычная кнопка Start не перезапускает успешно завершённые и пропущенные URL без явного запроса. Ручной Retry и сохранённый `RequeueRequested` после выбора материала подписки разрешают новую попытку/продолжение. Подготовка повтора сохраняет прежние Status/State, ownership, Selection, ResumeState и прогресс; флаг и DeferredToNextStart проверяются полным batch-preflight и входят в fingerprint checkpoint. Снимай флаг после отменяемых проверок перед фактическим Start либо принятого Resume/Restart; отмена диалога истории или дисковой проверки сохраняет запрос. Ответ No по-прежнему удаляет строку из очереди и снимает её отметку повтора, сохраняя готовые файлы. Старые checkpoint без флага читаются как false, portable queue его не переносит.
- При запуске восстановление требует явного подтверждения пользователя и никогда не начинает загрузку автоматически.
- Не перезапускай задания, пока ещё жив старый engine, сопоставляй PID с StartTime, чтобы защититься от PID reuse.
- При изменении checkpoint logic дополняй нативные regression-тесты и `LegacyCompatibilityTests`, проверяй реальные диалоги восстановления в Windows CI.

## Постоянная история успешных загрузок

- Все успешные URL записываются append-only в `%LOCALAPPDATA%\\VideoDownloader\\successful-downloads.jsonl`.
- `CompletedAtUtc` хранит время успеха; в диалог повтора передаётся последняя дата, а не дата импорта. Legacy-запись без времени остаётся с неизвестной датой.
- История независима от session checkpoint и удаления Queue: **никогда не очищай её** при завершении сеанса.
- Сравнение URL точное (ordinal), без сомнительной нормализации параметров.
- Перед **каждым** download start/explicit retry проверяй кандидатов в истории и применяй Yes/No/YesAll/NoAll. No удаляет соответствующий URL из Queue. Cancel/X не запускает процесс и не меняет очередь.
- Не записывай failed/cancelled URL как успешные; UI проверяет историю *до* запуска engine.
- Код завершения yt-dlp 0 недостаточен: успех требует существующего media path из `after_move:__VD_FILE__`. Внешние конфиги yt-dlp не должны менять параметры движка. Filename template проверяется до native launch: только относительные пути без компонентов `..`.
- Append истории под mutex поддерживает корректный последний JSON record без LF, но не изменяет повреждённый хвост.
- Используй межпроцессную синхронизацию истории и не проглатывай ошибки при чтении повреждённых данных.
- Проверяй append/даты/повреждения нативными regression-тестами, а все варианты решения о повторе — настоящими WPF-диалогами.

Библиотека **«История…»** читает те же append-only события с optional `Title`/`Source`/`OutputPaths`; чтение прежнего Version=1 без metadata обязательно. После подтверждённой публикации полного результата передавай `DownloadItem` в `AppendSuccess`, а не только URL: путь и название берутся из фактически опубликованного результата. Частичные результаты не пополняют полную историю. Пути в истории не подтверждают владение и не разрешают удаление.

Поиск библиотеки просматривает весь файл в фоне с отменой, показывая ограниченный набор последних совпадений и его полноту. Окно не меняет checkpoint/очередь/историю и не начинает скачивание. Проверка существования выполняется явно и вне UI; Missing, Unavailable и Unsafe различаются. Не считай `File.Exists == false` доказательством отсутствия. Глобально ограничивай незавершённые OS-проверки; отмена/таймаут ожидания не освобождает слот до возврата самой операции. Исполняемые файлы, ярлыки, URI и reparse points из metadata не открываются. Проверяй это в `HistoryLibraryTests`, реальном worker контракте и `HistoryLibraryUiTests`.

## Свободное место

- Проверки локальных томов выполняются вне Dispatcher через `IDiskSpaceProvider`; не создавай каталоги ради измерения. UNC/сетевые диски, отказ и таймаут не превращаются в ноль. Не освобождай ограниченный слот запроса до фактического возврата OS-вызова.
- До Start оценивай известные видео/аудиопотоки и суммарную долю диапазонов, сохраняя неизвестные размеры явно. Временные файлы находятся в `DownloadCoordinator.StagingDirectory`, а не обязательно на диске `OutputRoot`: учитывай два временных входных размера и один опубликованный на соответствующих томах. Оценка не гарантирует итоговый размер.
- Модальное Continue/Cancel выполняется до мутации попытки и запуска координатора. После async-проверки и согласия повторно проверяй очередь, параметры, пути и закрытие; изменённый план требует нового Start.
- Во время сессии поллинг не чаще пяти секунд; предупреждение при остатке менее 1 ГиБ не останавливает/перезапускает загрузки и не удаляет файлы. Одно предупреждение на том с гистерезисом восстановления 1,25 ГиБ. Сохраняй Stop и Pause доступными.
- `DiskSpaceTests` проверяет реальные локальные пути, неизвестность и ограничение блокирующих запросов; `DiskSpaceUiTests` — настоящее окно подтверждения, отмену без потери владения, позднее изменение плана и предупреждение активного fixture-процесса.

## Внешние зависимости

- yt-dlp.exe хранится рядом с приложением;
- FFmpeg/ffprobe могут лежать рядом с приложением или находиться в PATH;

Directory/read-only/reparse/ACL запреты не обходятся, чужие файлы не удаляются. `DependencyInstallTests` проверяет реальный loopback ZIP, Windows sharing lock и ACL отказ второго файла после замены первого.
- не утверждай, что FFmpeg bundled, если это не было отдельно изменено;
- engine и preview используют <code>--impersonate chrome</code>, что зависит от возможностей текущей сборки yt-dlp.

## Сборка и состав пакета

Единственный Windows-проект приложения — `src/VideoDownloader/VideoDownloader.csproj`: Windows x64, .NET 8, WPF, автономный EXE. Пользователь запускает EXE напрямую. Обязательны соседние yt-dlp, XAML, ресурсы и `collection-plugins/`; единственный EXE не заменяет весь portable ZIP. Android собирается отдельно из `android/`, как описано выше.

`scripts/build.ps1 -Task Publish` создаёт `dist/native`, `dist/VideoDownloader-native.zip` и SHA-256. Параметры `-Version`, `-OutputDirectory`, `-ArchivePath`, `-ChecksumPath` позволяют main-only release job выбрать версию и имена файлов без второго упаковщика.

Пакет обязательно включает `collection-plugins/videodownloader/yt_dlp_plugins/extractor/vd_pornhub.py`; копируй только исходные `.py`, без `__pycache__`/`.pyc`. Проверка пакета должна отклонять CMD, `.ps1/.psm1`, `pwsh.exe` и launcher вместо приложения. Внешний Python пользователю не нужен.

`Publish` формирует корневой `windows-package.json` схемы 1 с версией, путями, размерами и SHA-256 файлов поставки; `verify-package.ps1` проверяет полный набор и хеши. Сам манифест защищён SHA-256 ZIP из release `SHA256SUMS.txt`. Не включай пользовательские данные, FFmpeg/ffprobe или произвольные локальные файлы в владение пакетом.

### Обновление Windows-приложения

- Проверяй только стабильный более новый Latest фиксированного официального репозитория. Startup-проверка отображает статус без отдельного окна, ручная показывает ошибку. Проверка не даёт согласия на установку; установка запускается отдельной кнопкой «Обновить и перезапустить».
- Сохраняй сетевую отмену и общие пределы: 20 секунд проверки версии, 6 минут checksum/ZIP/подготовки, 16 КиБ checksum, 512 МиБ ZIP, 1 ГиБ распаковки. SHA-256 проверяется до распаковки, далее версия, полный манифест, размеры и хеши. Небезопасные пути, reparse points, ссылки и посторонний файл нового ZIP запрещены.
- Установка разрешена только после завершения работников/Start/dependencies/scanner, восстановления и очистки, без read-only checkpoint и живого legacy engine. После подготовки заново проверь состояние; сохрани checkpoint до handoff и при финальном закрытии. Ошибка закрытия/сохранения не должна запускать установщик.
- Временная копия автономного EXE ждёт конкретного родителя по PID+StartTime и держит тот же singleton mutex во время замены. Это внутренний handoff. До первой мутации `AppUpdateInstaller` копирует и проверяет фактические байты всех прежних manifest-owned файлов, включая изменённый yt-dlp, и сохраняет durable-указатель `.video-downloader-update.json` на собственную транзакцию. Каждая замена атомарна из temp в каталоге назначения; EXE заменяется после остальных файлов и остаётся на месте до замены, манифест — последним.
- Более новый независимо обновлённый yt-dlp сохраняется только после stable PE-версии и hash всей программы из `SHA2-256SUMS` точного официального release yt-dlp. Непроверенный PE не выполняется. Если распознанная дата новее bundled, отказ сети/hash/версии прерывает подготовку без тихой замены. Original stage/manifest проверяются целиком; отдельная pinned copy и effective next manifest отражают реальный сохранённый hash. Helper проверяет все источники и неизменность live runtime перед мутациями. Recovery требует backup и next manifest, но не сохранности forward-install copy; прежний schema-2 owner без новых полей читается для rollback. Проверки — `AppUpdateRuntimeTests` с двумя фиксированными официальными PE и настоящим `--version` на Windows.
- Профиль, очередь, история, cookies, загрузки, внешние FFmpeg/ffprobe и посторонние файлы сохраняются. Новая коллизия с чужим файлом — отказ. Ошибка Apply вызывает rollback. После аварийного завершения следующий startup под singleton запускает recovery helper до WPF/preview/чтения и сохранения профиля; восстанавливает прежний пакет из проверенного backup и перезапускает. При неполном rollback сохраняй указатель и собственные stage/backup в `%TEMP%\VideoDownloaderUpdates` для повторного recovery или ручной помощи; повреждённые recovery-данные не допускают обычный запуск.
- Пакет без корневого манифеста не обновляй на месте. Первый переход с `v2.0.38` и более ранних выпусков требует полного нового ZIP вручную. Не переноси это поведение на Android APK.
- Фоновая очистка после startup ждёт две секунды и осматривает до 32 собственных update-каталогов. Удаляй только Applied/RolledBack без pending-указателя и живого helper, проверяя точный GUID-путь процесса и StartTime; неопределённая идентичность, reparse и незавершённые Prepared/Applying/RollbackFailed требуют сохранения файлов.
- `AppUpdateClientTests`, `AppUpdateInstallerTests` и реальные `AppUpdateUiTests` обязательны. Проверяй SHA/версию/HTTP body cancel, чужие файлы, Windows sharing locks/junction, rollback/failed rollback, принудительное завершение дочернего установщика в разных точках и повторный recovery, запрет downgrade и повторную idle-проверку до handoff. UI-тест с управляемым сервисом не доказывает запуск настоящего установщика: после `Test`/`Publish` выполни `dotnet run --no-build --configuration Release --project tests/VideoDownloader.Tests -- --published-app-update-smoke dist/native`. `AppUpdateBootstrapTests` должен запускать actual single-file helper без соседних DLL, ждать родителя и открывать реальное WPF-окно с сохранённым изолированным профилем; CI делает это отдельным шагом после `Publish`.

## Переносимая резервная копия профиля

- Windows `.vdbackup` — отдельный формат, не расширение общего `.vdqueue`. Экспортируй только `PortableProfileSettings`, переносимые подписки и URL/title/source/date истории. Не включай очередь, Engine, cookies, локальные пути, кеш, обновления, output/owned manifests и разрешения. Приватные URL исключай целиком с явными счётчиками, сохраняемые URL сравнивай ordinal без нормализации.
- До preview целиком проверь ZIP, схему, строгий JSON/UTF-8, SHA-256, размер/сжатие/число записей, уникальность, отсутствие приватных данных. Архив не распаковывается. Повреждённые текущие данные блокируют импорт, замена подписок никогда не очищает историю.
- Только явный restore использует `ProfileBackupTransaction`: durable прежние/новые копии, указатель/журнал, профильный mutex перед mutex подписок/истории, atomic publication, проверенный rollback и recovery до первого чтения/записи профиля. Не откатывай живого владельца; проверяй PID вместе со временем старта. Не изменяй чужие файлы/медиа и не удаляй каталог рекурсивно.
- На время maintenance блокируй очередь, старт, обновления, ingress и SaveCheckpoint; закрытие отменяет и ждёт операцию. Проверяй lifecycle повторно после await/диалога. Неполный rollback оставляет профиль только для чтения. Настройки сохраняют локальные Output/Cookies/WatchClipboard, queue/ownership остаются текущими; импорт не начинает scan/download.
- Держи настоящий `SuspendSubscriptionSchedulingAsync` lease до завершения apply/rollback и повторных lifecycle проверок; не уничтожай контроллер расписания. Новые импортированные источники получают `ScheduleEnabled=false` и переносимый интервал, merge существующего точного URL сохраняет локальное согласие. Возобновление ждёт полный интервал. При обновлении native checkpoint замещай существующие имена настроек без учёта регистра, сохраняя неизвестные поля и не создавая дубли lowerCamelCase/PascalCase.
- Поздние IPC-группы сохраняй без разбора файлов в FIFO с пределами 64 группы / 4096 аргументов / 262 144 символа. После проверенного commit/rollback повторно проверь lifecycle, передай исходные группы обычному ingress последовательно и один раз без autoStart, затем сохрани checkpoint. Overflow/recovery-required требуют явного предупреждения без приватного содержимого аргументов. Закрытие ждёт также replay.
- При merge/replace резервируй текущие ID подписок и queue-only `SubscriptionId`. Replace сохраняет локальный ID только при точном совпадении URL; разные источники с одинаковым ID требуют переназначения imported items и duplicate provenance. Не переписывай для этого очередь и OwnedPaths. После частичного отказа IPC повторяется только непринятый суффикс, без повторного чтения уже обработанных файлов.
- Сверяй фактический сериализованный результат подписок с каноническим `SubscriptionStore.MaxFileBytes` до preview/apply, а не только с общим пределом профиля. При merge в ещё не инициализированный источник того же точного URL применяй импортированный baseline/операционные даты, сохраняя локальные настройки/consent и более новую попытку; материалы требуют `Initialized=true`.
- Backup сохраняет опциональные `InitialAction` / `ManuallyCompleted`; только для этих новых DTO полей resolver снимает IsRequired, остальные поля/unknown fields остаются строгими. Импорт не возобновляет initial queue pending и не создаёт очередь/историю из ручной готовности. Старая полная схема читается новой программой; старые бинарники со строгим unknown-field reader не обязаны читать профиль с данными новой функции. Проверяй реальный ZIP roundtrip ручной отметки и неинициализированного выбора, архив без новых полей и отказ несовместимых комбинаций до нормализации.
- Проверки: настоящие ZIP/файлы, secret/path canaries, merge/replace/коллизии, stale preview, отмена после publication, killed-child recovery до/после commit point, Windows sharing/read-only и WPF export→preview→cancel/restore. [Контракт и устройство](../developer/architecture.md#переносимая-резервная-копия-windows).

## Тесты перед PR/merge

На Windows с .NET 8 SDK и PowerShell 7 выполни из корня:

~~~powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Test
~~~

Команда собирает приложение и выполняет release-version/Russian/smoke, нативные unit/integration/security/legacy tests и реальные WPF-сценарии с изолированным профилем. Общий срок дочернего WPF-процесса в `scripts/ui-tests.ps1` — 180 секунд на все окна; сохраняй отдельные короткие operation/assertion deadlines. Нативные mouse-сценарии подтверждают WPF MouseDevice position после HWND WM_MOUSEMOVE до кнопок мыши: один SetCursorPos с ручным RaiseEvent может оставить старые координаты. Не подменяй холодное получение метаданных тестом с готовым кешем. Проверяй все пути добавления URL/TXT/InternetShortcut/подписка до Start без выбора строки, а также singleton/протокол/трей и все варианты диалога повтора.

Исполняемые проверки находятся в `tests/VideoDownloader.Tests/` и `tests/VideoDownloader.UiTests/`: `LegacyCompatibilityTests` читает фиксированные старые данные; `SubscriptionStoreTests` и `SubscriptionScannerTests` проверяют обнаружение, RSS и состояния; WPF host проверяет настоящие контролы. Не заменяй эти сценарии поиском маркеров в исходниках.

Для коллектора выполни `python tests/pornhub-collector-tests.py` с версией yt-dlp, закреплённой в Windows CI. Windows-тест адаптера дополнительно проверяет загрузку плагина настоящим упакованным `yt-dlp.exe` на офлайн-страницах. Живую проверку сайта описывай отдельно и не выдавай фикстуры за доступ к реальному каналу.

Если менялась упаковка:

~~~powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Publish
~~~

Для изменений Windows-кода, тестов, скриптов и сборки Windows workflow `native-windows.yml` должен быть зелёным перед merge. Для Android-кода обязателен `android.yml`; изменения общих `collection-plugins/` и `tests/fixtures/portable-queue/` проверяются обеими платформами. Smoke проверяет синтаксис скриптов разработки, XAML и обязательные файлы/контролы; функциональные проверки выполняют C#-тесты. PR только с Markdown может не запускать workflow из-за фильтра путей: перед его merge проверь ссылки, якоря, Mermaid и соответствие инструкций исходникам. После push в `main` полный Windows workflow запускается независимо от состава изменений.
