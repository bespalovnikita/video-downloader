# Контракты Android для агента

Прочитай после [CORE.md](CORE.md) и [SHARED.md](SHARED.md), если задача затрагивает `android/`, Android CI, APK, runtime или мобильные данные. Пути в кодовых фрагментах указаны от корня репозитория. Windows-правила WPF, EXE, job objects и `%LOCALAPPDATA%` сюда не переносятся.

## Стек, процессы и данные

- Gradle root — `android/`; модули `:core` (Kotlin/JVM, модели, правила подписок, парсеры и хранение) и `:app` (Android/Compose, yt-dlp, служба и публикация). Не переноси Android-код в C#-проект.
- JDK 17, Kotlin 2.1.20, AGP 8.9.2, Gradle wrapper 8.11.1; `minSdk 26`, `compileSdk/targetSdk 35`. ABI — `arm64-v8a` и `x86_64`. Зафиксированные версии меняй согласованно с workflow и инструкцией сборки.
- Точки запуска — `DownloaderApplication` / `MainActivity`. `AppGraph` владеет общими зависимостями, `DownloaderViewModel` связывает Compose с хранилищем и командами. Не привязывай активное скачивание к Activity, Compose effects или `viewModelScope`.
- `download/DownloadService` — foreground service типа `dataSync` с уведомлением и собственным scope. Запуск только по явному Start; Home, смена Activity и поворот не останавливают загрузки. Сохраняй `stopWithTask=false`, управление из уведомления, освобождение WakeLock и обработку системного таймаута API 35. После принудительной остановки процесса или перезагрузки самопроизвольного скачивания нет.
- `engine/AndroidYtDlp` запускает Android-рантайм `youtubedl-android` и FFmpeg, инициализируется вне UI thread. Не передавай недоступный в этой сборке `--impersonate chrome`. Отмена должна дождаться завершения native-вызова до очистки staging; Windows job-object гарантии сюда не переносятся.
- Extractor yt-dlp закреплён отдельно в `android/yt-dlp.properties`: версия и SHA-256 официального Unix zipimport. Генерируемый `res/raw/ytdlp` заменяет устаревший ресурс wrapper; не коммить скачанный бинарник. При старте `RuntimeArchive` мигрирует старую приватную копию атомарно, сохраняет более новую ручную установку и проверяет ресурс до замены. Проверяй миграцию и фактический `--version` на устройстве; SharedPreferences wrapper не доказывают версию установленного архива.
- Публикуй только проверенный ffprobe медиафайл из собственного staging. `MediaPublisher` использует MediaStore на API 29+, app external Movies на API 26–28 или выбранную пользователем SAF-папку. Не требуй `MANAGE_EXTERNAL_STORAGE`; сохраняй явные гранты SAF. История и processed — только после успешной публикации. Отмена, rollback, manifest известных URI и повторная очистка должны переживать восстановление.
- Android-снимок `files/state.json` объединяет настройки, очередь, подписки и историю. Это отдельный формат, не замена Windows JSON/JSONL. Повреждённый снимок не перезаписывай автоматически. При импорте копии очищай чужие URI/пути, stage/run IDs, cookies и SAF grants; данные импортированного файла не доказывают владение файлами.
- Точные HTTP(S) URL сравниваются с учётом регистра; ключ материала — SubscriptionId + URL. Подписки проверяются вручную: первая и принудительная проверка полные; проверенное окно допускается только по контракту ниже. RSS дополняет только названия подтверждённых URL. Проверка и постановка в очередь не запускают скачивание. Превью запрашиваются после добавления URL и успешного scan, независимо от активной строки; листание не создаёт сеть.
- Cookies импортируются как приватная копия Netscape-файла, не читаются из профилей браузера и не включаются в backup. Не включай cookies, keystore, `local.properties`, SDK, APK и Gradle build/cache в Git.
- Проверки из `android/`: `./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest`; на устройстве/эмуляторе API 35 x86_64 — `./gradlew :app:connectedDebugAndroidTest`. В Windows используй `.\gradlew.bat`. Инструментальный сценарий `foregroundDownloadCompletesAfterPressingHome` должен проверить настоящий медленный transfer, Home, читаемый опубликованный файл и историю; наличия foreground-маркера в исходниках недостаточно.
- Android CI — переиспользуемый `.github/workflows/android.yml`, вызываемый из `.github/workflows/native-windows.yml`; он также доступен вручную. Проверки включают release lint/assemble. Единый Release после проверок обеих платформ содержит release APK с постоянной подписью из main-only job. Debug APK остаётся CI-артефактом; не подменяй им release-сборку. Ключ и параметры подписи настраиваются один раз через GitHub Secrets по [инструкции выпуска](../developer/releases.md#android-артефакт-и-подпись). Учитывай GPL-3.0 Android-рантайма и [THIRD_PARTY_NOTICES.md](../../android/THIRD_PARTY_NOTICES.md), не меняй лицензию собственного кода без отдельного решения владельца.
- Инструкции: [сборка APK](../developer/android-build.md), [руководство Android](../user/android.md), [архитектура](../developer/architecture.md), [проверки](../developer/testing.md). Общие требования определены в [CORE.md](CORE.md), перенос очереди — в [SHARED.md](SHARED.md).

## Прогресс, сессия и журнал

- `__VD_PLAN__` описывает выбранные компоненты и позицию материала коллекции. Общий процент отделён от процента потока; до проверенной публикации он не превышает 99. Неизвестный план не выдавай за точную оценку. `N/A`, NaN и Infinity сохраняют последний пригодный процент. Новый native invocation показывает честный сброс, а title/phase-событие копирует предыдущий снимок и не имитирует 0.
- `DownloadRetryBoundary` применяется в реальном download path. После postprocessing, готового media marker либо успешного native execute ошибка обработки/проверки не разрешает автоматический полный transfer/fallback. Ограниченные повторы передачи и quality fallback остаются только до этой границы.
- `EngineTransferCounters` принадлежит заданию в текущей сессии и переживает pause/resume. Сервис учитывает его кумулятивное значение один раз, без повторного прибавления final result. При ограничении реестра потоков требуется ограниченное предупреждение об оценке; это не повод останавливать скачивание.
- `SessionTracker` и часы `elapsedRealtime` принадлежат foreground service. Сводка включает ожидающие и завершённые задания, паузу и очистку; Activity/Compose только отображают готовый снимок. Финальное время фиксируется после native join, работников, pending и команд. Session ID отличается от staging run ID, поздние события прежнего владельца не меняют новую сессию. Финальный снимок хранится в памяти процесса и не возобновляет загрузку после process death.
- Профили журнала сохраняются стабильными ID `Errors`, `Standard`, `Progress`, `Detailed`; неизвестное значение читается как `Standard`. Смена профиля действует на новые события. Ошибки и предупреждения сохраняются во всех профилях; прогресс и raw yt-dlp — в подходящем уровне подробности.
- `DiagnosticJournal` маскирует секреты до памяти/файлов/копирования/экспорта, сохраняя разрешённые публичные query ID (`v`, `list`, `viewkey`). Контекст задания различает session/job/attempt/component/video_seq и название либо URL; общий прогресс содержит ограниченный состав участников. Используй реальное локальное время без timezone/печатного `#counter` и настоящие многострочные продолжения.
- Границы журнала: память 5 000 записей / 2 МиБ, UI 2 000 / 512 КиБ; фоновая файловая очередь 512, основной `journal.log` и две ротации по 5 МиБ. Файловый sink не блокирует callback загрузки; отказ, переполнение и symlink не меняют её успех. Копирование/экспорт берут очищенный текущий snapshot, очистка памяти не удаляет файлы. Большой snapshot сохраняется через Android-пикер вместо небезопасно большого clipboard transaction.

## Обновления подписок и превью

- `FullScan.scope` различает `Full` и `RecentWindow`, сохраняя совместимость прежних вызовов. Первая проверка, принудительный полный обход и неподходящий источник используют `Full`. Окно до 20 допускается только для явных вкладок YouTube `videos`/`shorts`/`streams` и подтверждённого списка новых публикаций Pornhub с проверенными доказательствами источника и порядка. Произвольная коллекция не считается упорядоченной автоматически.
- Сопоставляй окно с точными URL всех состояний. Нет якоря, ответ непригоден или порядок неизвестен — полный fallback в том же общем бюджете: 180 секунд для обычного источника, 900 для специального коллектора; проба 30/45 секунд и RSS 12 секунд входят в бюджет. Лимиты Full: 10 000 материалов / 32 МиБ, Pornhub также 500 страниц. Пользовательская/native-отмена не запускает fallback. Неполный результат не заменяет успешный снимок.
- `Full` задаёт текущий порядок и сохраняет отсутствующие исторические записи в конце. `RecentWindow` ставится перед прежним хвостом без потери решений. `100 известных + 100 новых` без якоря должны приводить к Full и обнаружению всех 100 новинок в пределах лимитов; 20 не является пределом новинок.
- Результат проверки остаётся видимым с фиксированным монотонным временем; завершение останавливает анимацию. События старого `UiOperation.id` не изменяют новую операцию, а сохранённый результат не блокирует следующую проверку.
- Превью обслуживает один общий работник. Готовые данные и действительный ответ без кандидатов используют TTL 72 часа; пустая ошибка изображения или метаданных — минуту до следующего запроса, без таймера автоматического повтора. Сохраняй прежние пригодные изображение и название, показывай title/первую картинку по готовности. Готовый кеш не создаёт повторную HTTP-загрузку.
- После успешного `Full` догружай отсутствующие превью всех состояний только из подтверждённых `scan.items`; после `RecentWindow` — из накопленного снимка подписки. Проверка и предложение очереди их не ждут. Отмена/неполный обход не запускают такую догрузку; её ошибка не меняет состояния подписки.
- Ошибки превью отражай ограниченными `Warning/preview`: этап, URL видео и кандидата, индекс, HTTP-статус, объём и причина при наличии. Не записывай тело ответа; финальный журнал маскирует секреты до хранения. Неудачная диагностика не останавливает работника.

## Добавление в активную сессию

- Обычные ручные Add/Paste/Share запоминают Session ID при получении URL. Новые строки сначала имеют `deferredNextStart=true`; только подтверждённый приём службой снимает этот флаг. Существующие строки по точному URL не дублируются.
- Подтверждение истории сериализуется с обычным Start, но при активной сессии не держит `dataOperation`: Pause/Stop должны работать, пока пользователь думает. Отказ и отмена оставляют строки до следующего Start.
- `ManualQueueAdmission` повторно проверяет ID, точный URL, неизменившуюся историю и отсутствие состояния/владения прежней загрузкой. Приём использует прямую команду существующему DownloadService; он не вызывает создание новой службы или сессии. Закрытая/сменившаяся сессия, Stop и drain отклоняют запоздалое решение.
- Резервируй `commandsInFlight` до dispatch, освобождай даже при ранней отмене. Stop закрывает admission синхронно, до ожидания gate. Новые участники сохраняют паузу, часы и пул работников; настройки каждого нового задания фиксируются при принятии.
- Подписки и импорт TXT/InternetShortcut/VDQUEUE сохраняют отложенный Start. Формат очереди и правила отмены, публикации, очистки и истории не меняются.

## Что проверить при изменении

- Изменение сервиса проверяй настоящим фоновым скачиванием, а не только флагами манифеста: Home, завершение transfer, доступность опубликованного файла и сохранённая история.
- Изменение runtime проверяй по фактически установленному архиву и `--version` на устройстве; версии Gradle-зависимости или сохранённого preference недостаточно.
- Изменение публикации проверяй на отказах и отмене, включая сохранённые URI, rollback и повторную очистку после восстановления. Импортированный путь не даёт права удалить чужой файл.
- Изменения `collection-plugins/` и общего формата очереди требуют также проверок Windows; Android CI не заменяет [Windows CI](WINDOWS.md#тесты-перед-prmerge).
- Не описывай [план выравнивания платформ](../project/ANDROID_PARITY.md) как уже реализованный функционал.
