## Точность пользовательских сценариев

- Используй фактические подписи контролов из XAML/Compose. Перевод Windows-ошибок — отображение по `CurrentUICulture`, а не изменение машинных состояний или исходной диагностики; подробный контракт — [WINDOWS.md](WINDOWS.md#русификация-интерфейса-и-документации).
- Различай прямой URL плейлиста — одну задачу движка, состав которой определяет yt-dlp, — и импорт через подписку с отдельными URL материалов. Не обещай отдельную строку или историю каждого ролика при прямом URL коллекции.
- В примере одного YouTube-видео не оставляй `list`. URL с заменяемыми ID явно помечай как шаблоны.
- RSS/Atom дополняет отсутствующие названия только точных URL, подтверждённых полным обходом либо проверенным окном Windows. Она не является самостоятельным планировщиком и не добавляет feed-only элементы. Android выполняет полный обход. Основной URL коллекции и необязательный `FeedUrl` — разные поля. Cookies из UI передаются yt-dlp, но не RSS HTTP-запросу.
- Немедленная постановка URL в очередь превью не гарантирует мгновенную готовность изображения. Покажи независимость preview от Start, а ошибки обложек не описывай как отказ успешной проверки подписки.
- Приватные cookies, токены, локальные пути/гранты и разрешения не должны попадать в примеры переносимой очереди и backup.

## Схемы и проверка Markdown

Диаграммы веди в Mermaid внутри Markdown, с понятными подписями и ссылками на реальные компоненты. Показывай независимость preview от скачивания, границу ручного Start, отдельные записи session/history/subscriptions и сохранение прежнего снимка при неполной проверке. Эти файлы не являются одной общей атомарной транзакцией. Android `state.json` показывай отдельно от Windows-хранилищ.

После правок проверь локальные ссылки, якоря и синтаксис/отрисовку всех диаграмм, а команды и подписи сопоставь с исходниками. Относительные пути считай от файла документа, а пути в командах — от указанной рабочей директории. Дублирующие инструкции заменяй ссылками на каноническое руководство.

Для PR только с Markdown достаточно этих проверок; запуск C#/Android runtime-тестов не требуется. Если Markdown описывает вместе с PR изменённое поведение кода, выполняй проверки соответствующей платформы из [CORE.md](CORE.md#проверки-по-области-изменения). Не выдавай непроведённую проверку за успешную. Push в `main` всё равно запускает полный Windows workflow и автоматический стабильный выпуск.
