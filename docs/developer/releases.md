# Выпуск и артефакты

[Разработчику](README.md) · [Локальная сборка Windows](windows-build.md) · [Сборка APK](android-build.md) · [Проверки](testing.md)

GitHub Release содержит Windows portable ZIP и Android release APK с одной версией. Выпуск начинается после успешных проверок обеих платформ для одного коммита `main`. Подпись Android требует [однократной настройки постоянного ключа](#android-артефакт-и-подпись); без обязательных секретов выпуск завершается ошибкой.

## Правило

**Каждый коммит в ветке main — кандидат на стабильный релиз.** Workflow `.github/workflows/native-windows.yml` с названием **Windows and Android build** запускается на любой push в `main`, включая изменения документации.

1. Job `native` выполняет компиляцию C# / WPF, тесты GUI, сохранения данных, безопасности файлов и настоящие офлайн загрузки через yt-dlp.
2. Переиспользуемый `.github/workflows/android.yml` выполняет Android unit/lint, debug/release-сборки и instrumented tests на API 35, включая настоящую загрузку после Home.
3. Только после обеих успешных проверок job **Publish GitHub Release from main** получает разрешение на публикацию. Этап выполняется для push и ручного запуска в `main`; в PR и при ручном запуске другой ветки публикация пропускается.
4. Job вычисляет Git-тег по положению коммита в first-parent истории `main`, собирает EXE и release APK с этой версией, подписывает APK постоянным ключом и проверяет подпись через `apksigner verify`.
5. Job создаёт собственный draft с Release Notes, загружает `VideoDownloader-Windows-x64.zip`, `VideoDownloader-Android.apk`, общий `SHA256SUMS.txt`, `THIRD_PARTY_NOTICES.md` и `youtubedl-android-GPL-3.0.txt`. Публичный Release появляется только после проверки целевого SHA и полноты всех пяти файлов.

**Скачать:** https://github.com/bespalovnikita/video-downloader/releases/latest

## Версии

- Исторические версии до границы миграции сохраняются. Неизменяемая опорная точка — `v2.0.35` на коммите `e93a78f6b82c04a213ec2eaf9cd93855c84ef691`.
- После неё каждый следующий first-parent коммит `main` резервирует очередной patch-номер. Порядок завершения CI не влияет на версию: для последовательных коммитов A и B это `v2.0.36` и `v2.0.37`, даже если B опубликовался раньше A.
- Проваливший проверки коммит тоже резервирует номер, поэтому в опубликованном списке допустимы пропуски. Ошибка версии в промежуточном коммите не мешает исправленному потомку; версия самого выпускаемого коммита должна быть корректной.
- Базовая `Version` из `src/VideoDownloader/VideoDownloader.csproj`, превышающая текущую вычисленную версию, начинает новую линию: например, `2.1.0`, затем `2.1.1`. Уменьшение базовой версии не откатывает нумерацию: очередной коммит продолжает текущую линию.
- Версии EXE и Android `versionName` совпадают с тегом без `v`. Android `versionCode` равен `major * 1000000 + minor * 10000 + patch`: например, `2.0.36` даёт `2000036`.
- Для Android допустимы `minor` от 0 до 99, `patch` от 0 до 9999 и итоговый `versionCode` от 1 до 2100000000. При достижении границы patch нужно поднять базовую minor-версию; несовместимая версия останавливает выпуск.
- Локальная сборка без переопределения сохраняет значения проекта. Для Android параметры `-PvdVersionName` и `-PvdVersionCode` передаются вместе; в Release их задаёт скрипт `scripts/build-android-release.ps1`.
- План вычисляет `.github/scripts/ReleaseVersion.psm1`; `scripts/select-main-release.ps1` проверяет опорный тег и принадлежность целевого SHA first-parent истории `main`. Чужие теги не определяют следующий номер и не переносятся на другой коммит.
- Concurrency-группа `video-downloader-main-release` выполняет готовые release jobs последовательно. `queue: max` сохраняет до 100 ожидающих jobs; очередность определяется готовностью к выпуску, а версия — историей `main`.
- **Latest продвигается только вперёд**: более поздняя публикация старого A не вытесняет опубликованный B. Защита учитывает и стабильную SemVer-версию, и Git ancestry, включая опубликованные вручную версии с неожиданными номерами.

**Проваливший проверки, сборку или подпись коммит не публикуется.** Предыдущий стабильный релиз остаётся доступен. Проверки нумерации, истории Git и публикации входят в `scripts/release-version-tests.ps1`.

## Повторный запуск и прерванная публикация

`scripts/publish-main-release.ps1 -Mode Inspect` сначала выполняет проверку без записи. Опубликованный Release считается завершённым только при совпадении тега, точного целевого SHA, фактического SHA Git-тега и полного набора пяти файлов в состоянии `uploaded` с ненулевым размером. Такой Release пропускается и никогда не перезаписывается.

Новый draft помечается скрытым маркером `video-downloader-release:v1`, связывающим репозиторий, SHA и тег. `-Mode Publish` может продолжить только draft с единственным точным маркером и тем же целевым SHA. После обрыва загрузки повторный запуск заново загружает все пять файлов только в этот собственный draft, затем сверяет состояние, размеры и SHA-256, когда GitHub возвращает digest. Публикация разрешается после полной проверки.

Чужие drafts, несовпадающий SHA, неожиданные или повторяющиеся файлы и неполный уже опубликованный Release приводят к ошибке без исправления на месте. Прежние опубликованные релизы автоматически не дополняются. Существующий draft `v1.0.0` и теги до границы миграции не изменяются.

## Артефакты и доступ

| Файл Release | Назначение |
| --- | --- |
| `VideoDownloader-Windows-x64.zip` | Автономное Windows x64 приложение: EXE, yt-dlp, XAML, ресурсы, общий коллектор и корневой `windows-package.json` |
| `VideoDownloader-Android.apk` | Подписанный release APK для Android 8.0+, arm64-v8a и x86_64 |
| `SHA256SUMS.txt` | SHA-256 Windows ZIP и подписанного APK |
| `THIRD_PARTY_NOTICES.md` | Сведения о сторонних компонентах Android и их исходниках |
| `youtubedl-android-GPL-3.0.txt` | Текст GPL для Android-рантайма |

Windows-пакет не требует установленного PowerShell, Python или .NET Runtime. FFmpeg и ffprobe устанавливаются через интерфейс или размещаются рядом с приложением/в PATH. Проверка пакета требует `collection-plugins/videodownloader/yt_dlp_plugins/extractor/vd_pornhub.py` и отклоняет CMD, пользовательские PowerShell-скрипты и `pwsh.exe`.

Windows ZIP собирается командой `pwsh -NoProfile -File scripts/build.ps1 -Task Publish` с выбранной версией и именем архива. Скрипт `scripts/build-android-release.ps1 -Version VERSION` собирает и подписывает APK; итоговый checksum-файл создаётся после сборки ZIP и подписи APK. Ключ извлекается только во временный каталог runner и удаляется после использования.

Windows CI после `Publish` отдельно запускает **Verify portable updater handoff and restart**: настоящий опубликованный автономный EXE работает временным helper, дожидается завершения владельца, применяет пакет и вновь открывает реальное WPF-окно с изолированным профилем. Команда и границы проверки — в [руководстве по тестированию](testing.md#windows-полная-проверка).

`Publish` создаёт `windows-package.json` схемы 1 с той же версией, относительными путями, размерами и SHA-256 всех файлов Windows-поставки. Манифест лежит непосредственно в корне ZIP, рядом с EXE; каталог-обёртка не подходит встроенному установщику. `verify-package.ps1` проверяет состав и хеши. Внешние FFmpeg/ffprobe и пользовательские файлы не становятся частью манифеста. Манифест не содержит собственного хеша: его целостность защищена SHA-256 всего ZIP в `SHA256SUMS.txt`.

PR и ручной CI сохраняют Actions artifacts **VideoDownloader-native-windows**, **VideoDownloader-Android-debug** и отчёты **Android-test-reports**. Для их скачивания может потребоваться вход в GitHub; срок хранения ограничен. Debug APK не прикрепляется к Release, его подпись между запусками может отличаться.

По умолчанию workflow имеет `contents: read`. Только main-only job `release` получает `contents: write` и секреты подписи. Личный PAT для стандартной публикации не нужен. При отказе доступа проверь **Settings → Actions → General → Workflow permissions**, сохраняя PR-сборки без write-полномочий.

## Использование

1. Для установки используй **Releases → Latest** и файл нужной платформы.
2. Для обновлений отправляй изменения в PR, дождись проверок обеих платформ и мержи в `main`.
3. Windows проверяет стабильный Latest Release при запуске и по кнопке. В полном пакете с `windows-package.json` кнопка **«Обновить и перезапустить»** устанавливает более новую версию после завершения операций. Первый переход с `v2.0.38` и прежних пакетов без манифеста выполняется вручную: заверши приложение и распакуй новый ZIP целиком. Данные в `%LOCALAPPDATA%\VideoDownloader` сохраняются. Живой работник старой PowerShell-версии блокирует восстановление и новый Start, пока не завершён.
4. Android обновляется поверх прежней установки при совпадении подписи и допустимом `versionCode`. Переход с debug APK может потребовать предварительного [экспорта данных](../user/android.md#установка-apk-и-обновление). Предыдущий APK с меньшим `versionCode` обычно нельзя установить как обновление.
5. Для отката Windows скачай предыдущий стабильный ZIP. Опубликованные теги и файлы не перезаписываются.

Перед выпуском выполни применимые [проверки](testing.md), включая `pwsh -NoProfile -File scripts/build.ps1 -Task Test`, и дождись CI. Релизы не требуют отдельного ручного подтверждения: **всё, что готово к merge в main, считается готовым к выпуску**.

## Встроенное обновление Windows

[AppUpdateClient](../../src/VideoDownloader/Updates/AppUpdateClient.cs) обращается к `/releases/latest` фиксированного репозитория `bespalovnikita/video-downloader`, принимает только стабильную более новую версию и точные имена `VideoDownloader-Windows-x64.zip` / `SHA256SUMS.txt`. Переадресации разрешены только на HTTPS-хосты файлов GitHub. Проверка версии ограничена 20 секундами; получение checksum и ZIP с подготовкой имеет общий шестиминутный бюджет и отменяется при закрытии владельца. Пределы — 16 КиБ для checksum, 512 МиБ для ZIP и 1 ГиБ распакованных файлов.

SHA-256 ZIP проверяется до распаковки; затем проверяются корневой манифест, версия, полный набор файлов и каждый размер/хеш. Небезопасные пути, ссылки/reparse points и неизвестные файлы в пакете отклоняются. Эти проверки опираются на HTTPS и официальный GitHub Release; отдельная цифровая подпись Windows-пакета не добавлена.

Установка начинается только после завершения загрузок, проверок подписок, операций с зависимостями, восстановления и очистки, при доступном для записи checkpoint. Приложение сохраняет данные и завершает обычный жизненный цикл окна. Временная копия автономного EXE ждёт именно родительский процесс по PID и времени запуска и захватывает тот же singleton mutex. Перед первой заменой копируются и проверяются фактические байты всех прежних собственных файлов, включая отдельно обновлённый `yt-dlp.exe`. Запись `.video-downloader-update.json` в папке приложения указывает на собственную транзакцию. Замены выполняются атомарным переименованием файлов в каталоге назначения, EXE заменяется после остальных файлов, манифест — последним. Коллизия с посторонним локальным файлом запрещает установку.

Ошибки замены вызывают откат. После аварийного завершения следующий запуск под singleton обнаруживает незавершённую транзакцию до окна, preview и чтения/сохранения профиля. Recovery helper восстанавливает прежний комплект из проверенной копии и перезапускает приложение. Незавершённое восстановление сохраняет указатель и собственные stage/backup в `%TEMP%\VideoDownloaderUpdates` для повторной попытки или ручной помощи. Сохранность данных пользователя и ограничения показаны в [справочнике Windows](../user/windows-reference.md#обновление-приложения), реализация — в [архитектуре](architecture.md#обновление-windows-приложения). Этот механизм не обновляет Android APK.

## Ручной запуск CI

Открой **Actions → Windows and Android build → Run workflow**, выбери ветку и запусти проверку обеих платформ. При выборе **main** после полного успешного Windows и Android CI выполняется тот же release job, что и после push. Ручной запуск другой ветки сохраняет Actions artifacts и пропускает публикацию. Для отдельных Android-проверок доступен **Android Kotlin build → Run workflow**; он сохраняет артефакты проверки.

Для восстановления после `startup_failure`, когда jobs не созданы и GitHub не разрешает **Re-run jobs**, выбери **Run workflow → main**. Новый запуск использует текущий SHA `main` и снова выполняет все проверки. Если ветка уже продвинулась, выпускается её текущий коммит; номер провалившегося коммита остаётся зарезервированным, поэтому возможен пропуск версии.

Для одного SHA ручной запуск сохраняет детерминированные тег и версию: полный опубликованный Release пропускается, собственный незавершённый draft возобновляется по правилам выше. Защита Latest и неизменность прежних релизов действуют и при восстановлении. **Re-run jobs** старого запуска использует его исходные SHA, ref и исторический workflow; обновлённый механизм восстановления доступен через **Run workflow → main**.

**This job was skipped** у `Publish GitHub Release from main` ожидается в PR и при ручном запуске другой ветки. Для публикации проверь запуск нужного SHA в `main` и успешность Windows, Android и release job.

## Как проверить публикацию

1. Найди запуск [общего workflow для main](https://github.com/bespalovnikita/video-downloader/actions/workflows/native-windows.yml?query=branch%3Amain) с SHA нужного merge-коммита.
2. Проверь успешность Windows и Android jobs, затем **Publish GitHub Release from main**. При провале любой платформы публикация не начинается.
3. Открой [Releases](https://github.com/bespalovnikita/video-downloader/releases), проверь тег, SHA и все файлы из таблицы выше.
4. Проверь совпадение версии EXE и Android `versionName` с тегом. Сверь SHA-256 скачанных ZIP и APK с `SHA256SUMS.txt`; подпись APK можно проверить `apksigner verify --verbose --print-certs VideoDownloader-Android.apk`.

| Симптом | Проверка |
| --- | --- |
| Release job пропущен | Это PR/ручной запуск другой ветки либо Windows или Android job не завершился успешно; проверь запуск `main` |
| `startup_failure`, jobs отсутствуют и повтор недоступен | Запусти **Actions → Windows and Android build → Run workflow → main**; новый запуск проверит и выпустит текущий SHA `main` |
| Все тесты зелёные, публикация ждёт | Проверь release job и очередь concurrency `video-downloader-main-release` |
| Не хватает параметров подписи Android | Настрой четыре GitHub Secrets из следующего раздела; debug APK не используется как замена |
| Ошибка подписи APK | Проверь keystore, alias и оба пароля; сохрани прежний ключ для обновлений |
| Публикация получила отказ в доступе | Job `release` требует `contents: write`; не расширяй права PR-сборок |
| Повторный запуск пропускает Release | Подтверждены SHA и полный опубликованный набор пяти файлов; изменений нет |
| Повторный запуск продолжает draft | Проверь маркер владения и SHA; только собственный draft получает повторную загрузку всех пяти файлов |
| Release опубликован позже, но не стал Latest | Уже существует более новая стабильная версия или опубликованный Git-потомок; это защита от отката |
| Тег указывает на другой SHA | Workflow отказывается переносить чужой тег; исследуй конфликт, сохраняя опубликованные версии |
| Устарела локальная версия | Сборка без параметра версии использует значения проекта, а не номер последнего Release |

Основные файлы: [native-windows.yml](../../.github/workflows/native-windows.yml), [android.yml](../../.github/workflows/android.yml), [ReleaseVersion.psm1](../../.github/scripts/ReleaseVersion.psm1), [ReleasePublication.psm1](../../.github/scripts/ReleasePublication.psm1), [select-main-release.ps1](../../scripts/select-main-release.ps1), [publish-main-release.ps1](../../scripts/publish-main-release.ps1), [build-android-release.ps1](../../scripts/build-android-release.ps1) и [verify-package.ps1](../../scripts/verify-package.ps1).

## Android: артефакт и подпись

Перед первым автоматическим выпуском администратор репозитория один раз задаёт постоянный ключ. Если приложение уже распространялось с release-подписью, используй прежний keystore: новый ключ не позволит обновлять те установки с сохранением данных.

| GitHub Actions secret | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Base64 полного файла keystore |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `ANDROID_KEY_ALIAS` | Alias ключа внутри keystore |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |

Если ключа ещё нет, рекомендуемый способ — запустить [скрипт первоначальной настройки](../../scripts/setup-android-signing.ps1) на своём компьютере из корня рабочей копии. Нужны PowerShell 7.3+, JDK 17 с `keytool` и GitHub CLI `gh`, авторизованный под администратором репозитория с доступом к Actions secrets. Укажи абсолютный путь в приватном каталоге вне репозитория:

```powershell
pwsh -NoProfile -File scripts/setup-android-signing.ps1 -KeyStorePath 'C:\Private\VideoDownloaderSigning\release.p12'
```

Скрипт создаёт постоянный RSA-ключ 4096 бит в PKCS12 с безопасным случайным паролем, сохраняет рядом recovery JSON с параметрами восстановления и загружает четыре secrets через stdin, не выводя значения. Если загрузка в GitHub не удалась, повтори ту же команду: уже созданные материалы используются повторно, ключ не заменяется. Существующие файлы не перезаписываются. Настройка требует доступа к secrets из `gh` на этом компьютере; изменение workflow само по себе их не создаёт.

**Keystore и recovery JSON содержат секретные данные.** Храни оба файла вне Git, создай защищённую резервную копию обоих и не отправляй их в issue, PR или чат. Потеря ключа лишит возможности выпускать обновления с прежней подписью; recovery JSON содержит пароль и также должен оставаться приватным.

Для ручной настройки создай secrets в **Settings → Secrets and variables → Actions → Repository secrets**. Альтернатива со своим ключом в Bash, где путь нужно заменить своим:

```bash
VD_KEYSTORE=/absolute/private/path/video-downloader-release.jks
keytool -genkeypair -keystore "$VD_KEYSTORE" -storetype PKCS12 -alias video-downloader -keyalg RSA -keysize 4096 -validity 10000
```

`keytool` запросит пароль и сведения о владельце. Для PKCS12 пароль ключа совпадает с паролем хранилища; укажи его в обоих password secrets. Сохрани защищённую резервную копию keystore и паролей: потерянный ключ нельзя восстановить из APK.

Для записи через авторизованный GitHub CLI выполни следующие команды. Base64 передаётся через stdin без вывода в терминал, password secrets вводятся по запросу `gh`:

```bash
python -c 'import base64,sys; sys.stdout.write(base64.b64encode(open(sys.argv[1], "rb").read()).decode())' "$VD_KEYSTORE" | gh secret set ANDROID_KEYSTORE_BASE64 --repo bespalovnikita/video-downloader
gh secret set ANDROID_KEYSTORE_PASSWORD --repo bespalovnikita/video-downloader
gh secret set ANDROID_KEY_ALIAS --body video-downloader --repo bespalovnikita/video-downloader
gh secret set ANDROID_KEY_PASSWORD --repo bespalovnikita/video-downloader
```

Release job прекращает выпуск, если секрет отсутствует или подпись не проходит проверку. В PR секреты не передаются. Локальный `assembleRelease` по-прежнему создаёт unsigned APK; [гайд сборки](android-build.md#release-apk-и-подпись) описывает локальную подпись.
