# Разработка и участие

Изменение готово к merge, когда оно реализовано, проверено на своей платформе и описано в документации. Любой успешный push в `main` выпускает Windows Release, поэтому `main` должен оставаться пригодным для пользователя.

[Разработчику](README.md) · [Архитектура](architecture.md) · [Проверки](testing.md) · [Выпуск](releases.md) · [Инструкции для агентов](../agents/README.md)

## Рабочая последовательность

1. Получи актуальный `main` и создай отдельную ветку. Сохраняй свои незавершённые изменения до переключения веток; не удаляй их ради обновления.
2. Найди владельца состояния по [карте исходников](README.md#карта-исходников). Прочитай корневой [AGENTS.md](../../AGENTS.md) и профильные правила перед правками.
3. Исправь причину, добавь регрессионную проверку значимого изменённого поведения и обнови соответствующее руководство.
4. Выполни [проверки для затронутой платформы](testing.md#какие-проверки-нужны), проверь diff и создай PR с понятным описанием результата.
5. Дождись применимых CI, устрани ошибки и конфликты. После merge проверь публикацию, если она ожидалась.

Пример начала работы из корня репозитория:

```bash
git switch main
git pull --ff-only
git switch -c fix/short-description
```

Разделяй изменения на небольшие осмысленные commits. В описании PR укажи проблему, итоговое поведение, выполненные проверки и ограничения, которые нужны ревьюеру. Не выдавай Linux-компиляцию Windows-проекта за проверку WPF, а unit-тест Android — за доказательство фоновой загрузки.

## Границы реализации

Windows-код находится в `src/VideoDownloader/`, Android — в `android/`. Не включай тестовые сценарии в релизный EXE и не добавляй пользовательские CMD/PowerShell-launcher: Windows запускается непосредственно через `VideoDownloader.exe`.

Windows `DownloadCoordinator` владеет очередью работников, отменой и финальной публикацией. Android-загрузкой владеет foreground `DownloadService` со своим scope. Не привязывай её к Activity, Compose effects или `viewModelScope`. Сетевые, дисковые и длительные операции выполняй вне UI thread.

Сохраняй основные контракты:

- URL сравниваются точно, с учётом регистра. Не заменяй URL идентификатором ролика и не нормализуй подписанные адреса.
- Превью и метаданные запрашиваются после добавления URL и успешной проверки подписки, независимо от выбора строки и до Start. Ошибка превью не должна ломать обнаружение материалов.
- Подписки проверяются вручную. Обнаружение и добавление в очередь не начинают загрузку; RSS дополняет названия только уже подтверждённых URL.
- История успеха и processed обновляются после проверки и публикации конечного файла. Процент 100 сам по себе не доказывает успех.
- Удаление и отмена затрагивают только собственные файлы с подтверждённым владением. Путь из старого checkpoint или чужой резервной копии таким подтверждением не является.
- Сохраняй чтение прежних данных и защиту повреждённого снимка от автоматической перезаписи. Windows session/history/subscriptions — отдельные хранилища, а не единая транзакция.

Подробности и схемы Windows — в [архитектуре](architecture.md), обязательные инварианты — в [правилах для агентов](../agents/README.md). Различия мобильной версии перечислены в [руководстве Android](../user/android.md) и [матрице развития Android](../project/ANDROID_PARITY.md).

## Изолированный профиль Windows

Локальный EXE по умолчанию использует те же `%LOCALAPPDATA%\VideoDownloader`, что и установленный релиз. Для ручной проверки задай отдельный каталог данных в PowerShell из корня репозитория:

```powershell
$env:VD_DATA_DIRECTORY = Join-Path $env:TEMP ('vd-manual-' + [guid]::NewGuid().ToString('N'))
pwsh -NoProfile -File .\scripts\build.ps1 -Task Build
& .\src\VideoDownloader\bin\Release\net8.0-windows\win-x64\VideoDownloader.exe
```

Сначала закрой прежний экземпляр, включая окно в трее: второй запуск может передать аргументы уже открытому приложению. Для завершения эксперимента закрой приложение, затем убери переменную текущего терминала:

```powershell
Remove-Item Env:VD_DATA_DIRECTORY
```

Выбирай отдельную папку для скачанных файлов: `VD_DATA_DIRECTORY` изолирует профиль приложения, но не заменяет выбор Output. Сохрани нужные результаты перед удалением тестового профиля.

## Зависимости и упаковка

Windows использует соседний `yt-dlp.exe`, а FFmpeg/ffprobe ищет рядом с приложением или в `PATH`. В текущий Windows ZIP FFmpeg не включён; его можно установить через UI. Вызов `Publish` пересоздаёт выходной каталог сборки. PowerShell, Python и .NET Runtime пользовательскому автономному пакету не требуются.

Android включает runtime и FFmpeg через зависимости APK. Версия официального yt-dlp отдельно закреплена датой и SHA-256 в [android/yt-dlp.properties](../../android/yt-dlp.properties). Меняй эти два значения согласованно и проверяй фактически запускаемую версию на устройстве. Не переноси Windows `--impersonate chrome` в Android-вызов: эта возможность в текущем Android-рантайме недоступна.

Изменения общего коллектора и переносимой очереди требуют обеих платформ. Не добавляй загруженные бинарники runtime в исходники Android. Учитывай [лицензии Android-компонентов](../../android/THIRD_PARTY_NOTICES.md) при изменении зависимостей и распространении APK.

## Что не включать в Git

Не коммить `dist/`, APK, Gradle build/cache, SDK, `local.properties`, личные абсолютные пути, cookies, ключи подписи и пароли. Фикстуры должны содержать только специально подготовленные данные. В журнале сохраняй полезные публичные ID URL, но скрывай секреты до обрезки сообщения; не прикладывай приватные cookies или токены к PR.
