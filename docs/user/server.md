# Серверная очередь в браузере

Открой веб-интерфейс на ПК, добавь ссылки и запусти очередь. Сервис скачивает видео на сервер, даже если вкладка закрыта или ПК выключен. При следующем подключении в браузере будут та же очередь и готовые файлы. Установленные приложения Windows и Android ведут собственные очереди. Windows может [передавать серверу часть заданий своей очереди](#подключение-очереди-windows).

## Запуск на сервере

Для запуска нужны Linux с поддержкой nftables, Docker Engine 28 или новее и Docker Compose v2. Выполни команды из корня репозитория на VPS.

```bash
cd server
cp -n .env.example .env
chmod 600 .env
```

Открой `.env` в редакторе и задай длинный уникальный пароль в `VD_SERVER_PASSWORD`. Сгенерировать пароль из 48 шестнадцатеричных символов можно командой `openssl rand -hex 24`. Имя пользователя для входа задано в `VD_SERVER_USER`.

Очередь и видео сохраняются в томе `downloader-data`, в том числе после `docker compose down` и пересборки образа. Для резервной копии останови сервис и сохрани том целиком.

Docker Compose создаёт отдельную сеть для контейнера. Оставь этот режим сети при развёртывании. При старте контейнер настраивает в ней сетевой фильтр и сбрасывает привилегии перед запуском сервиса. Загрузки могут обращаться к публичным IPv4-адресам по TCP. Локальные адреса, служебные сети и новые IPv6-соединения блокируются, в том числе если ссылка перенаправляет на них. При ошибке настройки фильтра сервис завершает запуск.

## Прямой доступ по HTTPS

В `server/.env` задай `VD_PUBLIC_ADDRESS` с публичным IPv4-адресом VPS или DNS-именем, которое указывает на VPS. Например, для имени `downloads.example.com` добавь строку `VD_PUBLIC_ADDRESS=downloads.example.com`. Для получения сертификата и доступа к сервису открой входящие TCP-порты 80 и 443 на VPS и в сетевых правилах провайдера.

Из каталога `server` запусти сервис с HTTPS-прокси Caddy.

```bash
docker compose -f compose.yaml -f compose.https.yaml up -d --build
docker compose -f compose.yaml -f compose.https.yaml ps
```

Caddy получает и обновляет сертификат Let's Encrypt для настроенного адреса. После выдачи сертификата открой HTTPS-адрес с ПК, например `https://downloads.example.com/status`. В штатной HTTPS-конфигурации используется порт 443. Для входа используй `VD_SERVER_USER` и `VD_SERVER_PASSWORD` из `.env`. Для [подключения очереди Windows](#подключение-очереди-windows) укажи базовый адрес без `/status`.

## Доступ через SSH-туннель

Для подключения через SSH-туннель запусти обычную конфигурацию из каталога `server`.

```bash
docker compose up -d --build
docker compose ps
```

По умолчанию порт `8080` доступен на `127.0.0.1` VPS.

В терминале на ПК открой SSH-туннель. Подставь свой SSH-логин и адрес сервера вместо `user@server`.

```bash
ssh -N -L 127.0.0.1:8080:127.0.0.1:8080 user@server
```

Если VPS записан в конфигурации SSH как `video-vps`, укажи `video-vps` в конце команды. Пока туннель открыт, перейди в браузере на `http://127.0.0.1:8080/status` и войди с данными из `.env`. SSH шифрует пароль и файлы на пути между ПК и VPS.

Если занят порт `8080` на ПК, замени первое `8080` в команде SSH и в адресе браузера. Если порт занят на сервере, задай `VD_LOCAL_PORT` в `.env`, снова запусти `docker compose up -d` и поменяй последнее `8080` в команде SSH.

## Обновление из веб-интерфейса

Для обновлений из браузера один раз установи службу обновления на VPS с systemd, Python 3, Git, util-linux и Docker Compose v2. Установщик подключается к уже запущенному штатному контейнеру `downloader` проекта `video-downloader`. Дождись завершения скачиваний и передачи файлов. Из корня существующего репозитория на VPS выполни команды с точным тегом опубликованного выпуска, содержащего `install-updater.sh`, вместо `v3.0.N`. [Официальные выпуски](https://github.com/bespalovnikita/video-downloader/releases).

```bash
git fetch origin tag v3.0.N
git switch --detach v3.0.N
cd server
sudo ./install-updater.sh v3.0.N
```

Установщик сверяет тег и исходники `server` с опубликованным выпуском. Служба использует прежний `.env`, HTTPS-настройки и том `downloader-data` с очередью и файлами.

1. Войди в веб-интерфейс и раскрой **«Обновление сервера»**.
2. Нажми **«Проверить обновления»**. Сервер сверит установленную версию с последним стабильным выпуском официального репозитория Video Downloader.
3. Когда появится версия в строке **«Доступна»**, нажми **«Установить обновление»** и подтверди перезапуск.

Если сервер занят скачиванием или выдачей файла, дождись завершения работы, снова проверь обновления и запусти установку. При обновлении сервис перезапускается, а открытая вкладка ждёт восстановления связи. Проверь строку **«Установлена»** после подключения. При сбое запуска новой версии служба восстанавливает предыдущую.

При ручном развёртывании обнови исходники и повтори команду запуска выбранной конфигурации из прежнего каталога `server`. При пересоздании контейнера подключается существующий том `downloader-data`.

## Подключение очереди Windows

Укажи в Windows HTTPS-адрес VPS и данные веб-интерфейса из `.env`. Для локального доступа через туннель укажи `http://127.0.0.1:8080` или выбранный локальный порт. Подключение проверяется кнопкой **«Проверить подключение»**. [Настройки очереди Windows](windows-reference.md#shared-server-downloads).

Строка **«Свободно на VPS»** показывает место на томе, где хранятся временные и готовые файлы. Веб-интерфейс обновляет цифру вместе с очередью. В Windows место видно после нажатия **«Проверить подключение»** к обновлённому серверу.

Сервер учитывает свободное место в томе, временные файлы и готовые результаты, которые Windows ещё не забрала. При нехватке места запуск новых заданий ждёт его освобождения. Сервер хранит готовый файл задания Windows один час с момента завершения загрузки. Обычно копия удаляется раньше, когда клиент подтверждает, что получил, проверил и сохранил файл на ПК. При обрыве связи Windows может докачать файл до истечения часа. Если срок истёк, Windows покажет ошибку, и задание можно скачать заново. Файлы веб-очереди этим сроком не ограничены.

Настройки места и параллельности задаются в исходном `server/.env`. При ручном развёртывании после изменения повтори команду запуска выбранной конфигурации из каталога `server`. При обновлении из веб-интерфейса новые параметры применяются при следующей установке выпуска.

| Переменная | Назначение |
| --- | --- |
| `VD_SERVER_MAX_CONCURRENT` | От 1 до 4 одновременно выполняемых серверных заданий. По умолчанию 4. Активное задание из браузера занимает один из общих слотов. Готовые результаты Windows до подтверждения также учитываются в пределах этого числа заданий Windows. |
| `VD_SERVER_FREE_RESERVE_MIB` | Резерв свободного места в МиБ, по умолчанию 512, минимум 64. Для запуска сервер дополнительно учитывает запас в 64 МиБ на каждое активное и новое задание. Если свободное место опустится ниже резерва, активные серверные загрузки завершатся с ошибкой. |

## Загрузки

1. Вставь веб-ссылки на отдельные видео, по одной на строку, и нажми **«Добавить в очередь»**.
2. Нажми **«Запустить очередь»**. Сервер обработает текущие задания по одному. Ссылки, добавленные во время работы, ждут следующего запуска.
3. У готового задания нажми **«Скачать файл»**. Сервер поддерживает скачивание по частям через HTTP Range, чтобы совместимый браузер или менеджер загрузок мог продолжить передачу после обрыва.

Если контейнер остановится во время загрузки, текущее задание получит статус **«Прервано»**. Кнопка **«В очередь»** возвращает его для новой загрузки с источника. Чтобы продолжить работу, нажми **«Запустить очередь»**. Когда контейнер запущен, выход из браузера и закрытие SSH-туннеля оставляют загрузки с источника работающими.

Серверный yt-dlp использует сетевой профиль Chrome, как приложение Windows. Если приходит HTTP 403, очередь показывает, был ли отклонён запрос данных о видео или запрос медиафайла. Сайт может по-разному отвечать домашнему ПК и серверу с другим IP-адресом.
