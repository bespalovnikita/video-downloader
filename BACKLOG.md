# Дальнейшее развитие подписок

Этот список описывает будущие задачи. Текущая версия поддерживает ручное обнаружение материалов и работу со входящими: проверка канала или плейлиста через `yt-dlp`, необязательная RSS/Atom, исходный набор при первом просмотре и добавление выбранного в очередь перед Start. У подписки есть редактируемое краткое имя и подпапка с этим именем внутри общего каталога загрузок. Перечисленные ниже функции ещё не являются возможностями приложения.

## Этап 3: проверки, пока приложение открыто

- Настраиваемый интервал проверки каждой подписки и отдельный флаг разрешения проверки при запуске программы.
- Последовательное выполнение пропущенных проверок после сна без одновременного запуска нескольких сканирований одного источника.
- Следующая проверка, история попыток, backoff при временных ошибках и явное состояние «нужно обновить cookies».
- Ограничение числа одновременных проверок и частоты запросов к одному сайту.

Критерий готовности: фоновая проверка не блокирует UI и загрузки, не создаёт дубликаты, корректно переживает сон, отмену и перезапуск. Само обнаружение по-прежнему не означает разрешения скачивать.

## Отдельная задача: Планировщик Windows

Запуск проверки при закрытом GUI требует отдельного этапа и режима без интерфейса. Его нет в текущей версии.

- Создание, изменение и удаление задачи только по явному действию пользователя; первоначально — запуск от текущего пользователя при входе в Windows.
- Определение фактического каталога данных и безопасное чтение cookies в контексте того же пользователя.
- Согласование с открытым GUI через общую блокировку и отдельные входящие. Фоновая проверка не должна параллельно перезаписывать `session.json`.
- Восстановление регистрации после перемещения portable EXE; понятное предупреждение, если прежний путь недоступен.
- Запись результатов и ошибок для просмотра при следующем открытии; отдельные настройки пробуждения компьютера и сетевых условий.

Первый вариант задания должен только обнаруживать материалы. Автоматическое скачивание требует собственной политики и отдельного разрешения пользователя.

## Этап 4: правила выбора и индивидуальные настройки

- Фильтры по дате, длительности, названию, доступности и типу публикации. Неизвестное или отсутствующее значение метаданных не должно молча исключать материал.
- Сохранённый профиль, собственный базовый каталог назначения и шаблон имени для каждой подписки, с фиксацией настроек при добавлении задания. Подпапка по краткому имени внутри общего каталога уже поддерживается.
- Пакетное применение правил ко входящим и предварительный просмотр результата до добавления в очередь.
- Явное управление повторной обработкой ранее пропущенных или недоступных материалов.

## Этап 5: автоматическая загрузка

- Отдельный opt-in для каждой подписки; включение не должно неожиданно скачивать весь старый канал.
- Лимиты числа заданий, объёма и свободного места, временные окна и ограничения нагрузки.
- Определённая политика повторных попыток, ошибок доступа и премьеры/трансляции, ставшей доступной позднее.
- Согласование параметров подписки с общей очередью и восстановлением после сбоя.

Эти этапы развиваются на текущем стеке C#/.NET 8/WPF, yt-dlp и FFmpeg. В проекте одна пользовательская UI-версия; PowerShell используется только для разработки и CI. Режим для Планировщика Windows потребует отдельного решения и пока не реализован. Замена стека и отдельный постоянно работающий сервис не являются условием развития подписок.
